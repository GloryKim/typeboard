# Why a 32-bit float can represent a wider range than a 32-bit integer

## Abstract

A signed 32-bit integer can represent every integer from \(-2^{31}\) to \(2^{31}-1\). A 32-bit IEEE 754 floating-point number uses the same 32 bits, yet reaches magnitudes near \(2^{128}\). That looks paradoxical: floats must also encode fractions between integers, so their range should be smaller, not larger.

The resolution is spacing. Integers map bit patterns to consecutive decimal values one-to-one. Floats spend most of their bits on a significand in \([1, 2)\) and an exponent that scales that interval. As the magnitude grows, the gap between representable values grows too. Past about \(2^{24}\), those gaps exceed 1, so many integers are skipped—but the reachable extremes become enormous. Relative error stays small even when absolute spacing does not.

This note walks through integer encoding, fixed-point fractions, floating-point layout, and TypeScript checks that make the trade-off concrete.

---

## 1. The apparent paradox

| Encoding | Bits | Approximate magnitude bound |
|---|---|---|
| Signed 32-bit integer | 32 | \(\approx 2.15 \times 10^9\) |
| IEEE 754 `float32` | 32 | \(\approx 3.4 \times 10^{38}\) |

Same budget of bits. More values to cover (including fractions). Still a much larger range. The rest of this note explains how.

---

## 2. How integers use bits

With \(n\) bits you get \(2^n\) distinct patterns. Those patterns are usually assigned to consecutive integers.

### Unsigned

```ts
// 8 bits, unsigned: 0 .. 255
const u8Max = (1 << 8) - 1; // 255
```

### Signed two’s complement

The high bit is the sign. For 8 bits:

| Pattern | Value |
|---|---|
| `01111111` | \(+127\) |
| `10000000` | \(-128\) |
| `11111111` | \(-1\) |

```ts
function signedRange(bits: number): { min: number; max: number } {
  const max = 2 ** (bits - 1) - 1;
  const min = -(2 ** (bits - 1));
  return { min, max };
}

signedRange(8);  // { min: -128, max: 127 }
signedRange(16); // { min: -32768, max: 32767 }
signedRange(32); // { min: -2147483648, max: 2147483647 }
```

The unspoken assumption: **each step of one in the bit pattern means a step of one in the value**. Binary `0, 1, 10, 11, 100` maps to decimal `0, 1, 2, 3, 4` with nothing skipped. Floating point drops that assumption.

## 3. Fixed-point: fractions by moving the radix

A first attempt at real numbers keeps the same integer bit layout but places a fixed radix point inside the word.

Start from a 32-bit signed integer field. Move the radix one place to the left:

- Integer span halves (one bit leaves the integer field).
- You gain a fractional step of \(0.5\).

Move it again: span halves again; step becomes \(0.25\), then \(0.125\), and so on.

```ts
/** Fixed-point: `fracBits` bits after the radix in a 32-bit word. */
function fixedPointStep(fracBits: number): number {
  return 2 ** -fracBits;
}

function fixedPointIntegerSpan(fracBits: number): number {
  // Remaining bits for the signed integer part (rough sketch).
  const intBits = 32 - fracBits;
  return 2 ** (intBits - 1);
}

fixedPointStep(1); // 0.5
fixedPointStep(2); // 0.25
fixedPointStep(8); // 1/256 ≈ 0.00390625
```

### Why fixed-point hurts common decimals

Suppose 8 bits are reserved for the fraction. The step is \(1/256 \approx 0.00390625\). The value `0.1` sits between two grid points:

| Neighbor | Absolute error vs `0.1` |
|---|---|
| \(0.09765625\) | \(\approx 0.00234\) |
| \(0.1015625\) | \(\approx 0.00156\) |

The closer neighbor is still about **1.5%** off. For everyday decimals, fixed absolute spacing wastes precision where you need it and still caps the range harshly.

## 4. Floating point: significand × base^exponent

Floating point borrows scientific notation.

In decimal:

\[
1972.1121 = 1.9721121 \times 10^{3}
\]

In binary, the base is 2. A normal finite `float32` value is essentially:

\[
(-1)^{\text{sign}} \times (1.\text{fraction})_{2} \times 2^{\text{exponent} - \text{bias}}
\]

IEEE 754 binary32 layout:

| Field | Bits | Role |
|---|---|---|
| Sign | 1 | Positive / negative |
| Exponent | 8 | Scale (\(2^{e}\)); biased encoding |
| Fraction (mantissa / significand) | 23 | Digits of the significand in \([1, 2)\) |

The leading `1.` before the fraction is implicit for normal numbers, so 23 stored bits buy 24 bits of significand precision.

```ts
// TypeScript numbers are IEEE 754 binary64 (float64).
// Use Float32Array to observe 32-bit float behavior.

function asFloat32(x: number): number {
  const buf = new Float32Array(1);
  buf[0] = x;
  return buf[0];
}

asFloat32(0.1); // 0.10000000149011612  — not exact in binary
asFloat32(1 / 3); // rounded to float32, then shown as float64
```

### What the 23 fraction bits cover

With the implicit leading 1, the significand spans \([1, 2)\):

- All fraction bits `0` → \(1.0\)
- High fraction bit `1`, rest `0` → \(1.5\)
- All fraction bits `1` → just under \(2\) (\(2 - 2^{-23}\))

The exponent then slides that window:

| Exponent scale | Covering interval (conceptually) |
|---|---|
| \(2^{0}\) | \([1, 2)\) |
| \(2^{1}\) | \([2, 4)\) |
| \(2^{2}\) | \([4, 8)\) |
| … | … |

Inside each binade (power-of-two octave), there are \(2^{23}\) evenly spaced values. The **absolute** spacing doubles every time the exponent increases by one; the **relative** spacing stays on the order of \(2^{-23}\).

```ts
/** Unit in the last place around a power-of-two binade start. */
function float32UlpNear(powerOfTwo: number): number {
  // Spacing in [2^k, 2^{k+1}) is 2^{k-23} for normal float32.
  const k = Math.log2(powerOfTwo);
  return 2 ** (k - 23);
}

float32UlpNear(1);  // 2^-23 ≈ 1.19e-7
float32UlpNear(2);  // 2^-22
float32UlpNear(4);  // 2^-21
float32UlpNear(2 ** 23); // 0.5
float32UlpNear(2 ** 24); // 1
```

Near \(3.5\), half an ULP as a relative error is on the order of \(10^{-7}\%\) of the magnitude—far tighter than the fixed-point `0.1` example above.

## 5. Why float32 outranges int32

Keep the same \(2^{23}\) slots per binade and march the exponent upward:

| Interval | Count of float32 values | Spacing |
|---|---|---|
| \([2^{0}, 2^{1})\) | \(2^{23}\) | \(2^{-23}\) |
| \([2^{1}, 2^{2})\) | \(2^{23}\) | \(2^{-22}\) |
| \([2^{2}, 2^{3})\) | \(2^{23}\) | \(2^{-21}\) |
| … | … | … |
| \([2^{23}, 2^{24})\) | \(2^{23}\) | \(0.5\) |
| \([2^{24}, 2^{25})\) | \(2^{23}\) | \(1\) |
| \([2^{25}, 2^{26})\) | \(2^{23}\) | \(2\) |
| … | … | … |

Until exponent \(\approx 24\), spacing is still \(\le 1\), so many integers remain exact. After that, spacing becomes \(2, 4, 8, \ldots\). Integers are skipped, but each new exponent still unlocks a whole new octave of magnitude.

An 8-bit biased exponent reaches scales around \(2^{\pm 127}\). Fold in a significand almost as large as 2 and the finite max is on the order of \(2^{128}\):

```ts
const INT32_MAX = 2_147_483_647;
const FLOAT32_MAX = 3.4028234663852886e38; // ≈ (2 - 2^-23) × 2^127

INT32_MAX < FLOAT32_MAX; // true by many orders of magnitude

// Past 2^24, not every integer is representable as float32:
asFloat32(16_777_216); // 16777216  (2^24) exact
asFloat32(16_777_217); // 16777216  — rounds; neighbor gap is 2
asFloat32(16_777_218); // 16777218  exact again
```

So float32 is not “more integers with the same density.” It is **variable density**: dense near zero, sparse at the extremes, with a range set by nested powers of two (\(2^{e}\) applied to a significand already near \(2\)).

```ts
function demonstrateTradeoff(): void {
  const dense = asFloat32(1 + 2 ** -23);
  const sparse = asFloat32(2 ** 30 + 1);

  console.log(dense !== asFloat32(1)); // true: tiny step still visible near 1
  console.log(sparse === asFloat32(2 ** 30)); // true: +1 vanished into the ULP
}
```

---

## 6. Summary

1. **Integers** spend all bits on consecutive values. Range grows as \(2^{n}\), spacing is always 1.
2. **Fixed-point** buys fractional steps by shrinking the integer field. Common decimals like `0.1` can still land far from the grid.
3. **Floating-point** stores a short significand and an exponent. Absolute spacing grows with magnitude; relative error stays small.
4. **Range vs density** is the trade: once spacing exceeds 1, float32 reaches far beyond `int32` by skipping integers.
5. In TypeScript, remember that the language’s `number` type is **float64**. Use `Float32Array` (or explicit bit ops) when you need binary32 behavior.

Floating point is efficient encoding under a fixed bit budget: wide dynamic range, controlled relative precision, and intentional loss of absolute uniformity.
