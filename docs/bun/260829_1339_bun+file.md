# 이미지 HTTP 서버 (`main.ts`) 기술 보고서

런타임: Bun 1.4.0+

---

## 1. 이 서버가 하는 일

파이프라인에서 **카메라 스냅샷 1장을 HTTP로 밖에 내보내는** 아주 작은 정적 파일 서버다. 다른 대시보드와는 별 프로세스로 돌아가며, 역할은 하나뿐이다.

```
GET http://<서버IP>:12344/image  →  JPEG(또는 이미지) 바이너리 1장
```

군중(crowd) 이벤트가 Kafka `topic` 으로 나갈 때 JSON 안의 `image` 필드에 이 URL이 그대로 들어간다. 외부 수신 측(관제·연동 시스템)이 이벤트를 받으면 해당 URL을 열어 현장 이미지를 확인하는 구조다.

`crowd.go` 상수:

```go
kafkaImageURL = "http://1.1.1.1:12344/image"
```

배회(roam) 쪽 Kafka 메시지에도 같은 URL이 붙는다(`ingestTrack` 분기). 즉 **포트 12344 / 경로** `/image` **는 파이프라인 전체에서 “이벤트 첨부 이미지”의 고정 주소**로 쓰인다.

---

## 2. 파이프라인에서의 위치

`sh/README.md` 기준 군중 도메인 흐름:

```
07 군중 bag 반복재생
  → 08 ros2_crowd (MOT + platform_bridge :8765)
  → 09 crowd.go (:8081, dashboard + Kafka)
```

이미지 서버는 위 체인 **밖**에 있다. `10_image_server.sh` 로 따로 띄운다.

```
                    ┌─────────────────┐
  bag / ROS2 ──→ crowd.go :8081 ──→ dashboard :3000
       │              │
       │              └── Kafka (image URL 포함)
       │
       └── (카메라 원본과 무관) image/main.ts :12344 ──→ GET /image
```

대시보드 WebSocket(:8081)과 이미지 HTTP(:12344)는 포트·프로토콜·목적이 전부 다르다. 대시보드는 좌표·마커, 이미지 서버는 **외부 연동용 스냅샷 URL** 제공이다.

## 3. 소스 코드 (`main.ts`) 전체

```ts
const PORT = Number(process.env.PORT ?? 12344);
const HOST = process.env.HOST ?? "0.0.0.0";
const IMAGE = Bun.file(`${import.meta.dir}/1.jpg`);

if (!(await IMAGE.exists())) {
  throw new Error(`image not found: ${IMAGE.name}`);
}

const imageBody = await IMAGE.bytes();

Bun.serve({
  port: PORT,
  hostname: HOST,
  routes: {
    "/image": new Response(imageBody, {
      headers: {
        "Content-Type": IMAGE.type || "image/jpeg",
        "Cache-Control": "public, max-age=60",
      },
    }),
    "/": new Response("GET /image\n", {
      headers: { "Content-Type": "text/plain; charset=utf-8" },
    }),
  },
  fetch() {
    return new Response("Not Found", { status: 404 });
  },
});

console.log(`image server http://${HOST}:${PORT}/image`);
console.log(`example: http://1.1.1.1:${PORT}/image`);
```

총 32줄. 의존성 파일(`package.json`) 없이 `bun run main.ts` 한 방으로 실행된다.

## 4. 줄 단위 동작 설명



### 4.1 설정 (1–2행)


| 변수     | 기본값       | 의미                                          |
| ------ | --------- | ------------------------------------------- |
| `PORT` | `12344`   | 리슨 포트. `crowd.go`의 `kafkaImageURL` 과 맞춰 둔 값 |
| `HOST` | `0.0.0.0` | 모든 인터페이스에 바인드. LAN·공인 IP 양쪽에서 접근 가능         |


`Number(process.env.PORT ?? 12344)` — 환경변수가 비어 있거나 없으면 12344. 잘못된 문자열이면 `NaN` 이 되어 Bun이 바인드 실패할 수 있으니, 운영 시 `PORT=12344` 를 셸 스크립트에서 명시하는 편이 낫다(`10_image_server.sh` 가 그렇게 함).

### 4.2 이미지 파일 로드 (3–9행)

```ts
const IMAGE = Bun.file(`${import.meta.dir}/1.jpg`);
```

`import.meta.dir` 은 **이** `.ts` **파일이 있는 디렉터리** (`/image/`). 실행 cwd와 무관하게 항상 같은 파일을 가리킨다.

기동 시 순서:

1. `IMAGE.exists()` — 없으면 즉시 `throw`. 서버는 뜨지 않음 (fail-fast).
2. `IMAGE.bytes()` — 파일 전체를 `Uint8Array` 로 메모리에 올림.

**중요:** 요청마다 디스크를 읽지 않는다. 1장짜리 고정 스냅샷 서버라는 전제에 맞는 선택이다.

### 4.3 `Bun.serve` (11–28행)



#### `routes` 에 `Response` 객체를 직접 넣은 이유

Bun.serve의 `routes` 값이 **함수가 아니라** `Response` **인스턴스**이면, 런타임이 해당 경로를 정적 디스patch로 처리한다(요청마다 핸들러 호출·할당 없음). Bun.serve 예제 문서에서 “제로할당 정적 디스패치”로 분류되는 패턴이다.

이 서버는 `/image` 가 사실상 GET만 쓰고 바디도 변하지 않으므로, 핸들러 함수 대신 미리 만든 `Response` 를 넣는 게 맞다.

#### `/image`

- Body: 기동 시 읽어 둔 `imageBody` (바이트 배열)
- `Content-Type`: `IMAGE.type` — Bun이 **확장자** 기준으로 추론. 없으면 `image/jpeg`
- `Cache-Control: public, max-age=60` — 클라이언트·중간 캐시 60초. Kafka는 5초 주기(`KAFKA_PERIOD_SEC`)로 같은 URL을 반복 보내므로, 짧은 캐시로 불필요한 재전송을 줄인다.



#### `/`

안내용 plain text 한 줄: `GET /image\n`. 헬스체크·URL 확인용.

#### `fetch()` 폴백

`routes` 에 없는 경로는 전부 404 `"Not Found"`. `/image` 외 POST·OPTIONS 등도 여기로 떨어진다. CORS preflight가 필요한 브라우저 연동은 현재 구현에 없다(이미지 URL은 주로 `<img src>`·백엔드 fetch 용).

### 4.4 로그 (30–31행)

기동 직후 바인드 주소와 예시 URL 출력. `1.1.1.1` 은 placeholder — 실제 공인 IP(`1.1.1.1` 등)로 바꿔 쓰라는 뜻.

## 5. 실행 방법



### 5.1 직접 실행

```bash
bun run main.ts
```

환경변수 예:

```bash
HOST=0.0.0.0 PORT=12344 bun run main.ts
```



### 5.2 셸 스크립트 (`sh/10_image_server.sh`)

```bash
./sh/10_image_server.sh
```

내부 동작:

1. `_lib.sh` 로 `ROOT` 설정
2. `cd "${ROOT}/image"`
3. `HOST`/`PORT` export (기본 `0.0.0.0` / `12344`)
4. `exec bun run main.ts`

파이프라인 번호 `[10]` — 군중 Go `[09]` 다음, 독립 프로세스.

### 5.3 요구 사항

- Bun **1.4.0 이상** (`routes` + `Bun.file` 조합)
- `/image/1.jpg` 존재 (현재 코드 기준)

## 6. HTTP API


| 메서드 | 경로       | 상태  | Content-Type                | Body           |
| --- | -------- | --- | --------------------------- | -------------- |
| GET | `/image` | 200 | `image/jpeg`*               | 이미지 바이너리       |
| GET | `/`      | 200 | `text/plain; charset=utf-8` | `GET /image\n` |
| *   | 그 외      | 404 | (기본)                        | `Not Found`    |


 실제 파일·Bun 추론에 따름. 현재 `1.jpg`(PNG 내용)는 `image/jpeg` 로 나갈 수 있음.

### 확인 명령

로컬:

```bash
curl -I http://127.0.0.1:12344/image
curl -o /tmp/out.bin http://127.0.0.1:12344/image
file /tmp/out.bin
```

루트 안내:

```bash
curl http://127.0.0.1:12344/
# GET /image
```

## 7. 네트워크·방화벽

`readme.md` 기준 운영 환경:

- 서버 공인 IP 예: `1.1.1.1`
- UFW active 가정
- 외부 접속 URL: `http://1.1.1.1:12344/image`

포트 개방:

```bash
sudo ufw allow 12344/tcp comment 'image server'
sudo ufw status | grep 12344
```

바인드는 `0.0.0.0` 이므로 방화벽만 열리면 외부에서 접근 가능하다. TLS·인증은 없다 — 내부망·VPN 뒤에 두거나, 공인 노출 시 URL 유출 = 이미지 노출로 간주해야 한다.

## 8. 설계 선택과 트레이드오프



### 8.1 Bun을 쓴 이유

- Node + express/nginx 대비 **단일 파일·의존성 제로**
- `Bun.serve` + `routes` 정적 `Response` 로 초저지연 디스패치
- 파이프라인 쪽에서 이미 Bun 1.4+ 환경을 갖춘 상태 (`readme.md`, 설치 기록)



### 8.2 기동 시 전량 메모리 로드


| 방식         | 이 코드                      | 대안 (`new Response(Bun.file(path))`) |
| ---------- | ------------------------- | ----------------------------------- |
| 메모리        | 파일 크기만큼 상주 (~545KB 현재)    | 요청 시 스트리밍, 상주 적음                    |
| CPU        | 요청당 디스크 I/O 없음            | 요청마다 파일 read                        |
| hot reload | 파일 바꿔도 **재시작 전까지 반영 안 됨** | 파일 교체 시 즉시 반영 가능                    |


1장·고정 스냅샷·Kafka URL 고정이라는 요구에는 기동 시 로드가 합리적이다. **실시간 카메라 프레임**을 내보내려면 이 구조는 맞지 않고, 주기적 파일 덮어쓰기 + 프로세스 재시작 또는 스트리밍 핸들러로 바꿔야 한다.

### 8.3 nginx/정적 호스팅과 비교

nginx `alias` 한 줄로도 가능하지만, 파이프라인은 Jetson/개발 PC에서 셸 스크립트 번호로 서비스를 켜는 패턴이다. Bun 한 프로세스가 **스크립트 생태계와 맞고**, Go/Rust/ROS와 포트만 분리하면 된다.

### 8.4 구현하지 않은 것

- HTTPS
- 인증·토큰
- CORS 헤더
- HEAD `/image` 전용 처리 (폴백 404 또는 routes 미매칭 가능성 — curl `-I` 동작은 Bun 버전에 따라 확인 필요)
- 여러 카메라·동적 경로 (`/image/:id`)
- 이미지 갱신 API
- 헬스체크 JSON (`/health` 등)

의도적으로 최소 기능만 둔 상태다.

## 10. 요약

`main.ts` 는 파이프라인 에서 **이벤트 연동용 단일 이미지 URL** (`:12344/image`) 을 제공하는 Bun 내장 HTTP 서버다. Kafka로 나가는 군중·배회 JSON의 `image` 필드가 이 주소를 가리킨다.

구현 핵심은 세 가지다.

1. 기동 시 `1.jpg` 를 메모리에 올리고 `routes["/image"]` 에 고정 `Response` 를 등록
2. `0.0.0.0:12344` 로 외부 접근 가능하게 바인드
3. 그 외 경로는 404
