## 0. 개요와 공통 개념

### Bun 1.4 한 줄 요약

Bun 1.4는 **런타임을 Zig → Rust로 재작성**한 첫 안정 릴리즈입니다. idle CPU **5×↓**, 메모리 **최대 35%↓**, Linux 시작 **~50% 빠름**, Node.js 테스트 스위트 **+1,517** 통과, 이슈 **2,900+** 수정. 동시에 `Bun.Image` / `Bun.WebView` / `Bun.markdown` / `Bun.cron` / `Bun.Terminal` 등 내장 표준 라이브러리가 크게 늘었습니다.

### 실행 방법

```bash
# 이 보고서의 예제 파일 번호 규칙: NN_name.ts → 포트 4100+NN
bun --hot 01_markdown.ts
bun --hot 13_image_api.ts
bun 18_http3.ts          # TLS+HTTP/3 — 실험적
bun --cpu-prof-md ./35_mini_app.ts
```

포트 배치: `01` → **4101**, `02` → **4102**, … (`파일번호 + 4100`). Bun.serve 예제(3000번대)와 겹치지 않게 잡았습니다.

### 1.3 → 1.4에서 “예제로 만져볼” 핵심

| 영역 | API / 플래그 | 한 줄 |
|---|---|---|
| 이미지 | `Bun.Image`, `Bun.file().image()` | sharp 대체. resize/rotate/webp/jpeg… |
| 브라우저 | `Bun.WebView` | Puppeteer 없이 네비·클릭·스크린샷 |
| 마크다운 | `Bun.markdown.html/react/render/ansi` | GFM. HTML은 **sanitize 안 함** |
| 스케줄 | `Bun.cron()` | OS cron / 인프로세스 둘 다 |
| PTY | `Bun.spawn({ terminal })` | node-pty 대체 |
| 정적 파일 | `routes: { "/static/*": { dir } }` | ETag·Range·index.html 자동 |
| fetch | `compress`, `protocol: "http2"\|"http3"` | 요청 압축·실험적 H2/H3 |
| 포맷 | `JSON5/JSONC/JSONL/TOML/YAML/XML/Archive` | 파서·직렬화 내장 |
| 라우팅 | `URLPattern` | path-to-regexp 대체 |
| 스트림 | `CompressionStream`, `Response.textStream()` | gzip/br/zstd 등 |
| 테스트 | `bun test --parallel/--isolate/--shard/--timings/--changed` | CI 친화 |
| 빌드 | `--react-compiler`, `--metafile-md`, `--compile --target=browser` | React Compiler 내장 |
| 관측 | `--cpu-prof-md`, `--heap-prof-md` | 터미널/LLM용 마크다운 프로파일 |
| 패키지 | `bun audit fix`, `dedupe`, `prune`, `pm diff` | 보안·정리·리뷰 |

> **참고 — `bun --hot` vs `bun`**: HMR이 필요하면 `--hot`. cron `using` 수명, graceful stop, 프로파일링은 순수 `bun` 이 관찰이 쉽습니다.

## `01_markdown.ts` — Bun.markdown

포트 **4101**. 마크다운 → HTML / ANSI. `bun ./README.md` 처럼 터미널 렌더도 가능하지만, 여기서는 API를 서버로 노출합니다.

```ts
// 01. Bun.markdown — html / ansi
// 실행: bun --hot 01_markdown.ts
// 확인:
//   curl http://localhost:4101/
//   curl -X POST http://localhost:4101/html -H 'content-type: text/plain' -d '# Hi **Bun**'

const DEMO = `# Bun.markdown

**굵게**, *기울임*, \`code\`

- GFM 목록
- [링크](https://bun.com)

| A | B |
|---|---|
| 1 | 2 |
`;

const server = Bun.serve({
  port: 4101,
  routes: {
    "/": () =>
      Response.json({
        tip: "POST /html 또는 /ansi 에 text/plain 바디",
        demoHtml: Bun.markdown.html(DEMO),
      }),
    "/html": {
      POST: async (req) => {
        const md = await req.text();
        const html = Bun.markdown.html(md || DEMO);
        return new Response(html, {
          headers: { "Content-Type": "text/html; charset=utf-8" },
        });
      },
    },
    "/ansi": {
      POST: async (req) => {
        const md = await req.text();
        // Bun.markdown.ansi — 터미널용 기본 ANSI 렌더
        return new Response(Bun.markdown.ansi(md || DEMO), {
          headers: { "Content-Type": "text/plain; charset=utf-8" },
        });
      },
    },
  },
  fetch() {
    return Response.json({ error: "Not Found" }, { status: 404 });
  },
});

console.log(`01 markdown → ${server.url}`);
```

**해설**
- `Bun.markdown.html(md)` → HTML 문자열.
- `Bun.markdown.ansi(md)` → 터미널 컬러 문자열.
- `Bun.markdown.render(md, handlers)` 로 태그별 콜백(커스텀 ANSI 등).
- `Bun.markdown.react(md)` 는 React 엘리먼트(React 프로젝트에서).

**검토**
- ⚠️ **HTML은 sanitize 되지 않음**. raw HTML, `javascript:` 링크, 이벤트 핸들러 속성이 그대로 통과합니다. 사용자 입력을 HTML로 서빙할 때는 반드시 별도 sanitize.
- GFM 테이블·취소선·태스크 리스트·autolink 지원. 파서는 adversarial 입력에 선형 시간.

## `02_json_family.ts` — JSON5 / JSONC / JSONL

포트 **4102**. npm의 `json5` / `jsonc-parser` / `ndjson` 대체.

```ts
// 02. Bun.JSON5 / JSONC / JSONL
// 실행: bun --hot 02_json_family.ts
// 확인: curl http://localhost:4102/

const json5Src = `{
  // JSON5: 주석·따옴표 없는 키·후행 콤마
  name: 'bun',
  tags: ['runtime', 'bundler',],
}`;

const jsoncSrc = `{
  // tsconfig 스타일
  "compilerOptions": {
    "strict": true,
  },
}`;

const jsonlSrc = `{"id":1,"msg":"hello"}
{"id":2,"msg":"world"}
`;

const server = Bun.serve({
  port: 4102,
  routes: {
    "/": () =>
      Response.json({
        json5: Bun.JSON5.parse(json5Src),
        jsonc: Bun.JSONC.parse(jsoncSrc),
        jsonl: Bun.JSONL.parse(jsonlSrc),
        tip: "POST /jsonl/chunk 로 스트리밍 파싱 예제는 19번",
      }),
    "/json5": {
      POST: async (req) => {
        try {
          return Response.json({ ok: true, value: Bun.JSON5.parse(await req.text()) });
        } catch (e) {
          return Response.json({ ok: false, error: String(e) }, { status: 400 });
        }
      },
    },
  },
  fetch() {
    return new Response("Not Found", { status: 404 });
  },
});

console.log(`02 json_family → ${server.url}`);
```

**해설** — `JSON5` 는 느슨한 객체 리터럴, `JSONC` 는 JSON+주석+trailing comma(tsconfig와 동일 파서), `JSONL` 은 줄 단위 JSON 배열로 파싱.

**검토** — 문제 없음. `Bun.JSON5.stringify` 도 있음. `.json5` 파일은 번들러가 로더로 직접 import 가능.

## `04_urlpattern.ts` — URLPattern

포트 **4104**. Web API `URLPattern` (WPT 408 통과). path-to-regexp 대체.

```ts
// 04. URLPattern
// 실행: bun --hot 04_urlpattern.ts
// 확인:
//   curl http://localhost:4104/users/42
//   curl http://localhost:4104/orgs/acme/repos/api

const patterns = [
  { name: "user", pattern: new URLPattern({ pathname: "/users/:id" }) },
  {
    name: "repo",
    pattern: new URLPattern({ pathname: "/orgs/:org/repos/:repo" }),
  },
];

const server = Bun.serve({
  port: 4104,
  fetch(req) {
    const url = new URL(req.url);
    for (const { name, pattern } of patterns) {
      const m = pattern.exec(url);
      if (m) {
        return Response.json({
          route: name,
          groups: m.pathname.groups,
          pathname: m.pathname.input,
        });
      }
    }
    return Response.json(
      { error: "no match", try: ["/users/42", "/orgs/acme/repos/api"] },
      { status: 404 },
    );
  },
});

console.log(`04 urlpattern → ${server.url}`);
```

**해설** — `pattern.exec(url)` 가 매칭되면 `pathname.groups` 에 파라미터. `Bun.serve` 의 `routes`/`:id` 와 역할이 겹치지만, **임의 fetch 폴백·미들웨어·외부 URL 매칭**에 유용합니다.

**검토** — Bun.serve `routes` 가 있으면 보통 그걸 쓰고, URLPattern 은 커스텀 라우터/게이트웨이/리버스 프록시 규칙에 적합.

## `05_compression.ts` — CompressionStream

포트 **4105**. Web 표준 `CompressionStream` / `DecompressionStream` (`gzip` · `deflate` · `deflate-raw` · `brotli` · `zstd`). Bun 1.3에는 없음.

```ts
// 05. CompressionStream / DecompressionStream
// 실행: bun --hot 05_compression.ts
// 확인:
//   curl -s http://localhost:4105/gzip | wc -c
//   curl -s http://localhost:4105/roundtrip

async function compressString(text: string, format: CompressionFormat) {
  const stream = new Blob([text]).stream().pipeThrough(new CompressionStream(format));
  return new Response(stream).bytes();
}

async function decompress(bytes: Uint8Array, format: CompressionFormat) {
  const stream = new Blob([bytes])
    .stream()
    .pipeThrough(new DecompressionStream(format));
  return new Response(stream).text();
}

const PAYLOAD = "Bun 1.4 CompressionStream! ".repeat(200);

const server = Bun.serve({
  port: 4105,
  routes: {
    "/gzip": async () => {
      const bytes = await compressString(PAYLOAD, "gzip");
      return new Response(bytes, {
        headers: {
          "Content-Type": "application/octet-stream",
          "Content-Encoding": "gzip",
          "X-Raw-Bytes": String(Bun.stringWidth(PAYLOAD)), // 참고용(문자폭≠바이트)
          "X-Compressed-Bytes": String(bytes.byteLength),
        },
      });
    },
    "/roundtrip": async () => {
      const formats = ["gzip", "deflate", "brotli", "zstd"] as const;
      const rows = [];
      for (const f of formats) {
        const compressed = await compressString(PAYLOAD, f as CompressionFormat);
        const back = await decompress(compressed, f as CompressionFormat);
        rows.push({
          format: f,
          ok: back === PAYLOAD,
          raw: PAYLOAD.length,
          compressed: compressed.byteLength,
          ratio: +(compressed.byteLength / PAYLOAD.length).toFixed(3),
        });
      }
      return Response.json({ rows });
    },
  },
  fetch() {
    return new Response("Not Found", { status: 404 });
  },
});

console.log(`05 compression → ${server.url}`);
```

**해설** — `pipeThrough(new CompressionStream(format))` 후 `Response.bytes()`/`.text()` 로 소비. `fetch` POST 바디를 gzip 파이프로 올리는 패턴도 동일.

**검토** — `X-Raw-Bytes` 에 `stringWidth` 를 쓴 건 데모용(문자 폭 ≠ UTF-8 바이트). 실측은 `Buffer.byteLength(PAYLOAD)` 또는 `new TextEncoder().encode(PAYLOAD).byteLength`.

## `06_ansi.ts` — stringWidth / sliceAnsi / wrapAnsi

포트 **4106**. 터미널 컬럼 인식 문자열 유틸(ANSI·grapheme 인식).

```ts
// 06. Bun.stringWidth / sliceAnsi / wrapAnsi
// 실행: bun --hot 06_ansi.ts

const colored = "\x1b[1;32m한글\x1b[0mABC"; // 굵은 초록 "한글" + ABC

const server = Bun.serve({
  port: 4106,
  routes: {
    "/": () =>
      Response.json({

        sliced: Bun.sliceAnsi(colored, 0, 4), // 앞 4컬럼
        wrapped: Bun.wrapAnsi(`${colored} · 긴 설명을 좁은 폭에 감습니다`, 12),
      }),
  },
  fetch() {
    return new Response("Not Found", { status: 404 });
  },
});

console.log(`06 ansi → ${server.url}`);
```

**해설** — CLI 테이블·프로그레스·로그 정렬에 필수. `slice-ansi` / `wrap-ansi` / `string-width` npm 대체.

**검토** — JSON 응답이라 ANSI 이스케이프가 이스케이프되어 보입니다. 터미널에서 눈으로 확인하려면 `console.log(Bun.wrapAnsi(...))` 또는 `Content-Type: text/plain`.

## `07_image.ts` — Bun.Image 기초

포트 **4107**. 1×1 PNG를 만들어 리사이즈·JPEG/WebP로 응답.

```ts
// 확인:
//   curl -o /tmp/out.jpg http://localhost:4107/jpeg
//   curl -o /tmp/out.webp http://localhost:4107/webp
//   open /tmp/out.jpg

// 1x1 PNG
const TINY_PNG = Buffer.from(
  "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg==",
```

**검토** — 체이닝 중간 `width`/`height` 가 `-1` 일 수 있음(지연 평가). 메타가 필요하면 `metadata()` 또는 encode 후 확인.

## `08_cron.ts` — Bun.cron 인프로세스

포트 **4108**. OS crontab 없이 이벤트 루프에서 도는 잡. `using` 으로 스코프 종료 시 정지.

```ts
// 08. Bun.cron — 인프로세스 스케줄
// 실행: bun 08_cron.ts   # --hot 없이 관찰 권장
// 확인: curl http://localhost:4108/ticks

const ticks: { at: string; n: number }[] = [];
let n = 0;

// 매 분 — 데모에선 parse로 다음 시각만 보여주고,
// 실제 콜백은 짧은 표현으로 돌리기 어려워 수동 tick API도 제공
const next = Bun.cron.parse("*/1 * * * *");

using job = Bun.cron("*/1 * * * *", async () => {
  n += 1;
  ticks.push({ at: new Date().toISOString(), n });
  if (ticks.length > 20) ticks.shift();
});
job.unref(); // 잡만 남아도 프로세스 종료 가능하려면 unref

const server = Bun.serve({
  port: 4108,
  routes: {
    "/": () =>
      Response.json({
        cron: job.cron,
        nextRunUTC: next,
        tip: "GET /ticks — 콜백이 돌면 쌓임. POST /stop 으로 job.stop()",
      }),
    "/ticks": () => Response.json({ n, ticks }),
    "/stop": {
      POST: () => {
        job.stop();
        return Response.json({ stopped: true });
      },
    },
  },
  fetch() {
    return new Response("Not Found", { status: 404 });
  },
});

console.log(`08 cron → ${server.url} (next=${next.toISOString()})`);

process.on("SIGINT", () => {
  job.stop();
  server.stop(true);
  process.exit(0);
});
```

**해설**
- `Bun.cron(expr, fn)` — 인프로세스. 잡은 **겹치지 않음**.
- `Bun.cron.parse(expr)` → 다음 매칭 `Date` (UTC).
- `job.unref()` / `job.stop()` / `using` dispose.
- 파일 경로를 넘기면 OS 크론(crontab/launchd/Task Scheduler)에 등록 → 고급·운영 주의.

**검토** — 데모는 `*/1`(매분)이라 즉시 확인이 느릴 수 있음. 로컬 실험은 `jest.useFakeTimers` + `Bun.cron`(테스트 문서) 또는 더 짧은 커스텀 루프와 병행. 기본 스케줄은 **로컬 타임존**, `{ tz }` 옵션으로 명시 가능(예제 20).

## `19_jsonl_stream.ts` — JSONL 스트리밍

```ts
// 19. Bun.JSONL.parseChunk
// 실행: bun --hot 19_jsonl_stream.ts
// 확인: curl http://localhost:4119/demo

function parseJsonlStream(chunks: string[]) {
  const values: unknown[] = [];
  let pending = "";
  for (const chunk of chunks) {
    const input = pending + chunk;
    const result = Bun.JSONL.parseChunk(input);
    values.push(...result.values);
    pending = input.slice(result.read);
    if (result.error) throw result.error;
  }
  return { values, pending };
}

const server = Bun.serve({
  port: 4119,
  routes: {
    "/demo": () => {
      // 의도적으로 객체를 두 청크로 분할
      const { values, pending } = parseJsonlStream([
        '{"id":1}\n{"id":',
        '2}\n{"id":3}\n',
      ]);
      return Response.json({ values, pendingEmpty: pending === "" });
    },
  },
  fetch() {
    return new Response("Not Found", { status: 404 });
  },
});
```

## `20_cron_tz.ts` — cron 타임존 · using

포트 **4120**. 1.4에서 인프로세스 cron/`parse` 는 **로컬 TZ**가 기본(이전 UTC). `{ tz }` 로 명시.

```ts
// 20. Bun.cron tz option
// 실행: bun 20_cron_tz.ts
// 확인: curl http://localhost:4120/

const expr = "0 9 * * 1-5"; // 평일 09:00
const from = new Date();

// parse(expr, fromMsOrDate, options?)
const nextLocal = Bun.cron.parse(expr, from);
const nextUTC = Bun.cron.parse(expr, from, { tz: "UTC" });
const nextSeoul = Bun.cron.parse(expr, from, { tz: "Asia/Seoul" });

// 인프로세스 잡도 마지막 인자로 { tz }
using jobUtc = Bun.cron(expr, () => {}, { tz: "UTC" });
jobUtc.unref();

const server = Bun.serve({
  port: 4120,
  routes: {
    "/": () =>
      Response.json({
        expr,
        from,
        nextLocal,
        nextUTC,
        nextAsiaSeoul: nextSeoul,
        jobCron: jobUtc.cron,
        note: "1.4: 기본 로컬 TZ. 예전 UTC 동작이 필요하면 { tz: 'UTC' }",
      }),
  },
  fetch() {
    return new Response("Not Found", { status: 404 });
  },
});

console.log(`20 cron_tz → ${server.url}`);

  jobUtc.stop();
  server.stop(true);
  process.exit(0);
});
```

## `23_urlpattern_router.ts` — URLPattern 미니 라우터

포트 **4123**. Method + URLPattern 테이블.

```ts
// 23. URLPattern mini router
// 실행: bun --hot 23_urlpattern_router.ts
// 확인:
//   curl http://localhost:4123/api/users/7
//   curl -X POST http://localhost:4123/api/users -H 'content-type: application/json' -d '{"name":"a"}'

type Handler = (req: Request, groups: Record<string, string | undefined>) => Response | Promise<Response>;

const routes: { method: string; pattern: URLPattern; handler: Handler }[] = [
  {
    method: "GET",
    pattern: new URLPattern({ pathname: "/api/users/:id" }),
    handler: (_req, g) => Response.json({ userId: g.id }),
  },
  {
    method: "POST",
    pattern: new URLPattern({ pathname: "/api/users" }),
    handler: async (req) => {
      const body = await req.json();
      return Response.json({ created: body }, { status: 201 });
    },
  },
];

const server = Bun.serve({
  port: 4123,
  async fetch(req) {
    const url = new URL(req.url);
    for (const r of routes) {
      if (r.method !== req.method) continue;
      const m = r.pattern.exec(url);
      if (m) return r.handler(req, m.pathname.groups);
    }
    return Response.json({ error: "Not Found" }, { status: 404 });
  },
});

console.log(`23 urlpattern_router → ${server.url}`);
```

**해설** — Bun.serve `routes` 없이도 Web 표준만으로 라우팅 가능. 미들웨어 체인을 직접 짤 때 기반.

```ts
  <li><a href="/public/hello.txt">static</a></li>
  <li><a href="/thumb">thumb jpeg</a></li>
  <li><a href="/health">health</a></li>
</ul>
</body></html>`;
      return new Response(html, {
        headers: { "Content-Type": "text/html; charset=utf-8" },
      });
    },
    "/public/*": { dir: PUB },
    "/thumb": () => new Response(new Bun.Image(TINY_PNG).resize(96, 96).jpeg({ quality: 80 })),
    "/health": () =>
      Response.json({
        ok: true,
        bun: Bun.version,
        widthDemo: Bun.stringWidth("한글ABC"),
      }),
    "/log": {
      POST: async (req) => {
        const line = await req.text();
        const parsed = Bun.JSONL.parse(line.endsWith("\n") ? line : line + "\n");
        for (const row of parsed) {
          logSink.write(JSON.stringify(row) + "\n");
        }
        await logSink.flush();
        return Response.json({ written: parsed.length });
      },
    },
  },
  fetch() {
    return new Response("Not Found", { status: 404 });
  },
});

console.log(`35 mini_app → ${server.url}`);

process.on("SIGINT", async () => {
  await logSink.end();
  server.stop(true);
  process.exit(0);
});
```

**해설** — 1.4에서 자주 쓰는 조합: `markdown` + `{ dir }` + `Image` + `JSONL` + `stringWidth`.

**검토** — 프로세스 수명 `FileSink` + `flush`. MD HTML sanitize 없음.

### 반복되는 공통 개선 포인트

1. **`Bun.markdown.html` 은 sanitize 없음** — 사용자 MD/HTML 절대 그대로 서빙 금지.
2. **`Bun.Terminal` / 셸 노출 = RCE** — 화이트리스트·내부망·미노출.
3. **HTTP/3 · fetch H2/H3 는 experimental** — 프로덕션 기본값으로 켜지 말 것.
4. **정적 `new Response(Bun.file)`** — 개발 중 파일 변경 반영엔 함수형 핸들러.
5. **병렬 테스트/스크립트** — 고정 포트·공유 outdir·공유 DB는 격리.
6. **이미지 업로드** — 크기 제한(`maxRequestBodySize`) + 디코드 비용 예산.
