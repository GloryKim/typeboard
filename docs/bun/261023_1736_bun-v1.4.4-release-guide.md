## 1. 개요 및 릴리즈 핵심 요약

Bun v1.4.4는 패치 번호지만 내용 대부분은 패키지 매니저와 SQL, WebSocket, 포맷터다. 가장 큰 사용자 대면 기능은 Prettier 호환 포맷터 **`bun fmt`**다. JavaScript·TypeScript 프린터는 Oxc 포맷터(그 자신은 Biome 포맷터의 포트)를 포팅한 것이고, 나머지 언어는 Prettier 동작을 기준으로 맞춘다.

그다음으로 큰 축은 **`bun install`이다.** 열려 있던 패키지 매니저 PR 597개 중 464개가 전부, 40개가 부분 반영됐고, 제목은 **133개 install 이슈를 닫았다**고 적는다. Yarn Berry `yarn.lock` 이전, 피어 의존성 선택, 지수 백오프 재시도, `bun pm fetch` / `cache pack`이 여기 속한다.

런타임 쪽은 `Bun.SQL`·`bun:sqlite`·`node:sqlite`를 한 변경으로 다시 짰고(열린 PR 149개를 대체, 이슈 51개 수정), `ws`를 npm `ws` 8.22.0에 맞춰 다시 포팅했다. JavaScriptCore는 업스트림 WebKit 커밋 **1,013개**를 받았다. 보안 절은 TLS, WebSocket, DB 클라이언트, 패키지 매니저와 함께 **Brotli**를 영향 표면에 넣는다. CVE 번호는 이 블로그 본문에 없고, 같은 주의 Brotli 디코더 경계 밖 쓰기(CVE-2026-111497)는 [별도 보고서](261022_1720_Node.js%20and%20Bun%20Brotli%20Decoder%20Out-of-Bounds%20Write.md)와 Bun 이슈 `#46352`에서 1.4.4 수정으로 연결된다.

## 2. 핵심 업데이트 심층 분석 & 원인 규명

### 2.1 bun fmt

#### 1) 무엇이 바뀌었나

`bun fmt`는 작업 디렉터리의 소스를 고친다. 포맷 대상은 JavaScript, TypeScript, JSX, Flow, CSS, SCSS, Less, HTML, Vue, Svelte, Angular, Lightning Web Components, MJML, JSON, JSONC, JSON5, YAML, TOML, Markdown, MDX, GraphQL, Handlebars다. HTML 안의 내장 코드, Markdown 코드 펜스, JavaScript의 `css`...`` 템플릿도 포맷한다.

`bun format`은 여전히 `package.json`의 `format` 스크립트를 실행한다. 내장 포맷터의 명령은 `bun fmt`뿐이다. `cargo fmt`, `go fmt`, `deno fmt`, `zig fmt`와 같은 이름이다.

```text
$ bun fmt
src/index.ts
src/styles.css
Formatted 2 files, 2 unchanged [5.59ms]
```

이 문서의 실측(파일 하나, `const x=1`):

```text
src/messy.ts
1 file needs formatting. Run bun fmt to fix it.
# bun fmt 이후
const x = 1;
1 file is formatted.
```

#### 2) 왜 빠른가

공식 비교는 포맷터 프로세스 차이다. Prettier 저장소(2,616파일, 그 저장소 설정)에서 `bun fmt --check`는 **59.7 ms / 피크 48 MB**, Prettier 3.9.10은 **17.1 s / 459 MB**다. 블로그는 286배로 적는다. vitest, date-fns, monkeytype, h3에서는 Prettier 3.9.9 대비 234–425배다.

oxfmt 0.74.0과 같은 트리를 보고 exit 0이며 파일을 바꾸지 않은 비교:

| 프로젝트 | 파일 | `bun fmt` | oxfmt 0.74.0 | 배율 | 메모리 |
| :--- | ---: | ---: | ---: | ---: | :--- |
| RSSHub | 7,121 | 97.3 ms | 298.5 ms | 3.0x | 42 vs 95 MB |
| redocly-cli | 3,397 | 62.4 ms | 217.5 ms | 3.4x | 61 vs 107 MB |
| vite | 2,537 | 65.2 ms | 406.7 ms | 6.2x | 64 vs 137 MB |
| fumadocs | 2,452 | 44.6 ms | 1,395 ms | 31x | 48 vs 179 MB |

측정 조건(공식): vite만 16코어 M4 Max, macOS 26.7, 평균. 나머지는 Intel Xeon Platinum 8488C 물리 8코어를 `taskset`으로 고정, Amazon Linux 2023, NVMe 위 xfs, warm cache, 중앙값. 한 코어와 vite의 JS/TS만 본 추가 표는 블로그에 있다. vite JS/TS 1,608파일은 52.2 ms 대 188.3 ms(3.6배), RSSHub 한 코어는 621.6 ms 대 1,212 ms(1.9배), redocly-cli 한 코어 375.1 ms 대 645.5 ms(1.7배), fumadocs 한 코어 255.2 ms 대 5,608 ms(21배).

재현에 쓰인 커밋: vite `4ca25e1d3a24`, redocly-cli `82da67d6ea5b`, RSSHub `8776927c78de`, fumadocs `bc86bbb0d406`, prettier `df39b5b60a28`. oxfmt 프로젝트는 `node_modules` 없이, prettier만 `bun install --ignore-scripts` 후 `bun fmt --no-script . --check`와 `prettier.cjs . --check`를 비교한다.

#### 3) 검사와 git 연동

| 명령 | 동작 |
| :--- | :--- |
| `bun fmt --check` | 고치지 않고 필요한 파일만 나열. 하나라도 있으면 exit 1 |
| `bun fmt --staged` | 커밋 직전 파일만 포맷하고 다시 stage. `lint-staged` 대체용. pre-commit에서 `bun fmt --staged` |
| `bun fmt --changed` | 기본 브랜치와 다른 파일. `bun fmt --changed=origin/dev`처럼 ref 지정 |
| `bun fmt --doctor` | Bun이 읽은 설정과, 지워도 되는 패키지를 표시 |
| `bun fmt --debug-check` | 포맷 결과를 다시 파싱해 의미가 바뀌면 실패. Prettier의 `--debug-check`와 같은 역할 |
| `bun fmt --init` | `bunfig.toml`에 `[fmt]` 섹션을 만든다 |
| `bun fmt --no-script` | `package.json`에 `fmt` 스크립트가 있어도 내장 포맷터를 실행 |

#### 4) 설정을 읽는 순서와 기본값

읽는 파일: `.prettierrc*`, `prettier.config.*`, `package.json`의 `"prettier"`, `overrides`, `.editorconfig`, `.prettierignore`, `.oxfmtrc.json`, `.oxfmtrc.jsonc`, `oxfmt.config.ts` / `.mts`. CLI 플래그는 Prettier·oxfmt와 같다. `// prettier-ignore`가 동작한다.

`bunfig.toml`의 이름은 Prettier 옵션과 같다. 플래그로도 된다(`--print-width 100`, `--no-semi`).

```toml
[fmt]
printWidth = 100
semi = false
sortImports = true
sortTailwindcss = true
sortPackageJson = true
jsdoc = true

[[fmt.overrides]]
files = ["*.test.ts"]
options = { printWidth = 120 }
```

`sortImports`, `sortTailwindcss`, `sortPackageJson`, `jsdoc`는 **기본 꺼짐**이다. Prettier 설정이 없어도 이 네 개는 `bunfig.toml`만으로 켠다. `sortImports`는 import를 묶고, `{ }` 안의 이름을 정렬하고, 같은 모듈의 중복 import를 합친다.

모노레포에서는 작업 디렉터리에서 위로 올라가 **`[fmt]`가 있는 가장 가까운 `bunfig.toml`**을 쓴다. Prettier 설정이 없으면 TOML도 포맷한다. `*.min.js`, `*.min.css`, 락파일은 경로를 직접 넘기기 전에는 건너뛴다.

import 정렬 플러그인(`@trivago/prettier-plugin-sort-imports`, `@ianvs/prettier-plugin-sort-imports`, `prettier-plugin-organize-imports`)은 `plugins`에 남겨 두어도 된다. Astro처럼 플러그인이 필요한 언어는 프로젝트에 설치된 Prettier로 폴백한다.

#### 5) 내장 플러그인과 Prettier와의 차이

Tailwind, `package.json`, Svelte는 패키지를 설치하지 않아도 같은 일을 한다. `plugins`에 남겨 두면 그 옵션을 읽는다.

Tailwind 클래스는 프로젝트의 `tailwindcss` 3 또는 4로 정렬한다. 설치돼 있지 않으면 클래스를 그대로 둔다. 공식 비교(플러그인 0.8.1, Tailwind 4.3.3과 3.4.19, Prettier 3.9.9):

| 입력 | 전체 | 바이트 동일 | 비율 |
| :--- | ---: | ---: | ---: |
| JS·TS | 13,952 | 13,654 | 97.9% |
| HTML, Vue, Angular, LWC, Handlebars, CSS, SCSS, Less, Markdown, MDX | 2,176 | 2,148 | 98.7% |
| Tailwind 3 프로젝트 | 15 | 15 | 100% |

차이의 약 절반은 의도적이다. `className={`header${open ? " active" : ""}`}`에서 플러그인은 `" active"`의 앞 공백을 지워 `headeractive`가 된다. `bun fmt`는 공백을 남긴다.

`package.json`은 플러그인과 같은 키 순서이고 값은 그대로다. 실제 파일 13,670개 중 13,644개(99.8%)가 Prettier 3.9.9+플러그인과 바이트 단위로 같다. 20개는 Bun이 값을 보존해서 다르고, 6개는 플러그인이 예외를 던진다.

`.svelte`는 기본으로 포맷하며 `prettier-plugin-svelte` 4.1.1과 맞는다. Prettier 설정이 있으면 그 설정이 플러그인을 나열할 때만 포맷한다. 끄려면 `[fmt]`의 `svelte = false` 또는 `--no-svelte`.

지원하지 않는 플러그인(예: `prettier-plugin-jsdoc`)이 있으면 **그 플러그인 이름을 찍고, 그 플러그인이 적용되는 파일은 건너뛰며, exit 2**다.

의미가 바뀌는 Prettier 출력은 `bun fmt`가 유지한다.

| 입력 | Prettier 3.9.9 | `bun fmt` |
| :--- | :--- | :--- |
| CSS `font-family: Font\ Awesome` | `Font\Awesome`. `\A`가 16진 이스케이프가 됨 | 유지 |
| CSS 선택자 `x \|b` | `x\|b` 네임스페이스 선택자로 바뀜 | 자손 선택자 유지 |
| Handlebars의 특정 공백 | 삭제 | 유지. 블로그 HTML에서 해당 토큰이 비어 전달됨 |
| Handlebars에서 `// comment`가 있는 줄 | 줄이 붙어 주석이 다음 줄을 삼킴 | 유지. 토큰은 위와 같이 비어 있음 |

#### 6) 적합성 숫자 (공식)

CI는 매 커밋에 Prettier 3.9.9 포맷 테스트를 돌린다. 통과 조건은 바이트 단위 동일이다. 차이 83개 중 64개는 YAML 블록 스칼라의 trailing blank line을 Prettier가 지워 문자열 값이 바뀌는 한 가지 경우다.

### 2.2 bun check 속도

1.4.3에서 들어온 내장 체커의 **알고리즘과 캐시**가 바뀌었다. 오류 개수는 프로젝트마다 1.4.3과 같다고 블로그가 적는다. 콜드 런, Linux x64, 스레드 8, 3회 중 최선:

| 프로젝트 | v1.4.4 | v1.4.3 | 배율 |

- `switch` 케이스가 수천 개이거나, 클로저가 읽는 변수에 대입이 수천 번인 경우 검사에 수 초가 걸리던 경로가 사라졌다.

`bun check -b`는 프로젝트들이 **파싱된 선언 파일, 모듈 resolve 캐시, emit 목록**을 공유한다. 1.4.3은 프로젝트마다 사본을 들고 있어서 프로젝트 수보다 시간이 더 가파르게 늘었다. `skipLibCheck: true`인 생성 모노레포, 16코어 M4 Max, 6회 중 최선:

| 참조가 최대 40개인 프로젝트 800개, 각 20파일 | 1.26 s | 7.36 s | 5.8x |

마지막 행의 피크 메모리는 1,987 MB에서 872 MB다.

`bun check --no-script`는 `package.json`에 `check` 스크립트가 있어도 타입 체커를 돌린다. `bun check --no-script -b`처럼 체커 플래그를 받는다.

타입 오류의 개별 수정(거짓 양성·누락)은 [2.11](#211-트랜스파일러-bun-check-번들러-테스트-셸-수정-전체)에 전부 있다. 실무에서 바로 닿는 것은 TypeScript 7.1을 따라 **TS2321을 더 이상 보고하지 않는 것**(중첩 비교 100번 뒤에는 연관된 타입으로 가정)과, Slate `CustomTypes` 모듈 보강의 거짓 TS2456·TS2502다.

### 2.3 bun install

#### 1) Yarn Berry 락파일

`bun install`이 Yarn 2+ `yarn.lock`을 `bun.lock`으로 바꾸면서 **핀된 버전을 유지**한다. 1.4.3은 Yarn v1만 이전해서, Berry 프로젝트를 Bun으로 옮기면 의존성을 전부 다시 resolve했다.

유지되는 것: 워크스페이스, `npm:` 별칭, `resolutions`, git, tarball, `file:`. `patch:` 의존성은 `package.json`의 `patchedDependencies`가 된다. `catalog:` 범위는 `.yarnrc.yml`에서 읽어 `package.json`으로 복사한다.

이전은 전부 아니면 실패다. `yarn.lock`이 핀한 것을 하나라도 보존하지 못하면 이유를 출력하고 `package.json`에서 resolve한다. 예: `exec:` 의존성, `.yarnrc.yml`에만 있고 `bunfig.toml`이나 `.npmrc`에는 없는 레지스트리.

#### 2) 재시도

1.4.3은 실패 요청을 다섯 번 재시도했지만 다섯 번이 5 ms 안에 끝나, 짧은 레지스트리 장애도 설치 실패가 됐다. 1.4.4는 첫 재시도 전 50 ms를 기다리고 매번 두 배다. **50, 100, 200, 400, 800 ms, ±20% 지터.**

| 레지스트리 | v1.4.4 | v1.4.3 |
| :--- | :--- | :--- |
| 503 한 번 뒤 성공 | 성공, 78 ms | 성공, 22 ms |
| 100 ms 동안 503 | 성공, 222 ms | 실패, 8 ms |
| 1초 동안 503 또는 429 | 성공, 1.6 s | 실패, 7 ms |
| 3초 동안 503 | 실패, 1.5 s | 실패, 18 ms |
| 수신 프로세스 없음 | 실패, 1.6 s | 실패, 15 ms |

1.5초보다 긴 장애는 `BUN_CONFIG_HTTP_RETRY_BACKOFF=250`처럼 초기 지연을 늘린다. 이 값이면 250 ms, 500 ms, 1 s, 2 s, 4 s다. `=0`이면 1.4.3처럼 즉시 재시도한다. `Retry-After`는 최대 60초까지 따른다. 429와 408도 재시도한다. `bun info`, `bun pm view`, `bun pm whoami`, `bun audit`도 같은 재시도를 한다.

#### 3) 피어를 고르는 순서

아무것도 피어를 제공하지 않으면, 1.4.3은 관계없는 패키지가 깔아 둔 버전을 넘겼다. `@remix-run/express@2.17.1`의 피어는 `express@^4.20.0`인데 MCP SDK가 `express@5`를 의존하면, 1.4.3은 Remix에 Express 5를 주고 `incorrect peer dependency` 경고를 냈다. 1.4.4는 Express 4를 준다. `elysia`와 `@jest/schemas`를 같이 두면 elysia가 `@sinclair/typebox@0.27`을 받아 로드에 실패하던 같은 종류의 문제도 여기 속한다.

고르는 규칙:

1. 프로젝트, 워크스페이스, 그 패키지의 조상 중 하나가 그 피어를 의존하면 **범위 밖이어도 그 버전**을 쓴다. 앱이 `react@17`이면 라이브러리도 `react@17`을 본다.
2. 그렇지 않으면 그 피어를 선언한 패키지들이 **범위를 모두 만족하는 버전 하나**를 공유한다. 이미 설치된 버전을 우선하고, 그다음 레지스트리에서 가장 새 버전이다.
3. 한 버전이 모두를 만족하지 못하면, `react`나 `graphql`처럼 사본이 둘이면 깨지는 패키지는 그래도 사본을 나누지 않는다. 각자 범위 안의 설치본이 있으면 그것을 쓰고, 없으면 다른 패키지와 같은 버전을 공유한다.

resolve가 필요한 설치에서 `--verbose`는 범위 밖으로 끝난 피어를 모두 출력한다. **이미 `bun.lock`에 있는 버전은 바뀌지 않는다.** 피어를 다시 resolve하려면 그 피어가 필요한 패키지를 지우고 다시 추가한다.

`bun update --latest`는 한 번이면 된다. 1.4.3에서는 `react-dom@17`을 19로 올려 피어 범위가 바뀌어도, 피어로만 설치된 `react`는 두 번째 실행 때까지 17에 남았다.

#### 4) libc, 캐시, 모노레포 속도 (공식)

hoisted 링커가 macOS·Linux에서 최대 8스레드로 링크한다. 캐시가 따뜻하고 `node_modules`가 비었거나 불완전한 CI에서 효과가 크다. Linux에서 캐시에 있는 패키지 1,000개(각 30파일):

| `node_modules` | 코어 | 이후 | 이전 |
| :--- | ---: | ---: | ---: |
| 빔 | 8 | 120 ms | 381 ms |
| 빔 | 4 | 174 ms | 383 ms |
| 빔 | 2 | 162 ms | 222 ms |
| 절반만 설치 | 8 | 54 ms | 140 ms |
| 절반만 설치 | 4 | 65 ms | 174 ms |
| 절반만 설치 | 2 | 107 ms | 161 ms |

`sharp`, `@swc/core`, `lightningcss`, `rollup` 같은 패키지는 Linux 빌드마다 `"libc": ["glibc"]` 또는 `"musl"`을 단다. 1.4.3은 이 필드를 무시해서 **glibc와 musl 빌드를 둘 다 받았다.** 이제는 시스템과 맞는 것만 설치한다. `bun install --libc musl`은 glibc 머신에서 Alpine용으로 받을 때, `--libc '*'`는 예전처럼 둘 다. 필드는 `bun.lock`에 저장된다. 예전 락파일에는 없으므로 패키지를 업데이트하거나 락파일을 다시 만들 때 붙는다.

다른 공식 수치: Yarn v1 락파일 20,000엔트리 `bun pm migrate`가 24 s → 0.27 s. 워크스페이스 2,100개 모노레포 설치 피크 메모리 91 MB → 35 MB. 패치 적용이 더 이상 2차 시간이 아니다. 10만 줄 파일에서 4만 줄이 바뀐 `bun patch --commit`이 1.45 s → 0.09 s.

퍼즈(공식): 의존성 종류·링커·락파일 형식을 조합한 생성 프로젝트 600개에서 구버전과 비교. 변이된 `bun.lockb` 90,000개에 명령 7개를 실행해 크래시·행 없음. `npm-pick-manifest`와 생성 케이스 20만 개를 비교해 차이가 두 가지뿐. `latest`가 없는 버전을 가리키는 경우, 그리고 `^1.0.0-a.0`.

#### 5) 새 명령과 플래그

`bun pm fetch`는 의존성을 캐시에만 받고 `node_modules`를 만들지 않으며 스크립트와 락파일을 건드리지 않는다. Dockerfile에서는 `package.json`과 `bun.lock`만 복사한 레이어에서 fetch하고, 소스 복사 뒤에 `bun install --offline --frozen-lockfile`을 둔다. 모노레포의 첫 단계는 루트 `package.json`과 락파일이면 된다.

```text
bun pm cache pack .ci/bun-cache.pack
bun pm cache unpack .ci/bun-cache.pack
bun pm cache prune              # 30일보다 오래된 항목
bun pm cache prune --max-age 7
bun pm cache prune --dry-run
```

`unpack`은 없는 것만 넣고, 손상된 팩은 통째로 거부한다.

`bun publish --recursive`는 의존 방향 순서로 워크스페이스를 출판한다. 첫 출판 전에 전부 pack한다. private와 레지스트리에 이미 있는 버전은 건너뛰므로 실패 후 재실행이 안전하다. `--filter "@acme/*"`로 이름을 제한한다.

`packageExtensions`는 선언하지 않은 import 때문에 isolated 설치가 실패하는 패키지에, 포크 없이 의존성을 더한다. pnpm·Yarn과 같은 형식이고, `pnpm-lock.yaml`·`yarn.lock`을 이전할 때 복사한다.

```json
{
  "packageExtensions": {
    "legacy-plugin@2": { "dependencies": { "lodash": "^4.17.21" } },
    "react-redux@7": { "peerDependencies": { "react": "*" } }
  }
}
```

`link:./dir`는 `package.json` 기준 상대 경로를 `node_modules`에 심볼릭 링크한다. `bun link`를 먼저 돌릴 필요가 없다. `link:shared`처럼 경로가 없으면 예전처럼 `bun link`로 등록한 패키지다.

폐기 패키지: `bun add rimraf@3`는 `warn: deprecated rimraf@3.0.2: ...`를 낸다. 직접 의존성은 한 줄, `--verbose`는 전이 의존성도 나열한다. 범위를 resolve할 때 폐기되지 않은 버전을 선호하고, `bun add pkg`는 폐기된 `latest`를 건너뛴다. 락파일에 이미 있는 버전은 `bun update` 전까지 유지된다.

```toml
[install]
minimumReleaseAge = "3d"   # "90m", "12 hours", "2 weeks". 숫자만 있으면 초
minimumReleaseAgeExcludes = ["@types/bun", "typescript@5.9.3"]
```

`name@version`은 그 릴리스만 제외한다. 플래그는 `--minimum-release-age 3d`, `--minimum-release-age-excludes typescript@5.9.3`.

`--env-file`은 모든 패키지 매니저 명령과 `bunx`에 동작한다. 1.4.3의 `bun install --env-file ci.env`는 `ci.env`라는 **패키지를 설치하려 했다.** `bunx --cwd`, `bunx --minimum-release-age`, `bunx --trust`(그 패키지와 의존성의 라이프사이클 스크립트)가 추가됐다. `--no-env-file`과 `bunfig.toml`의 `env = false`도 된다.

`bun add -d` / `--optional` / `--peer`는 이미 다른 그룹에 있는 패키지를 **옮긴다.** 예전에는 원래 자리에 뒀다. `bun add --save-prod`로 되돌린다.

`actions/setup-node`가 임시 `.npmrc`를 쓰고 `NPM_CONFIG_USERCONFIG`로 가리키면 Bun이 그 변수를 읽는다. 파일을 복사하지 않아도 private 레지스트리가 된다.

다른 패키지 매니저 플래그를 Bun에 대응되는 것으로 번역한다. 1.4.3은 무시해서 `bun add --save-dev zod`가 `dependencies`에 들어갔고 `bun install --immutable`이 락파일을 고쳤다.

| 넘어온 플래그 | Bun |
| :--- | :--- |
| `--immutable` | `--frozen-lockfile` |
| `--package-lock-only` | `--lockfile-only` |
| `--save-dev`, `--save-exact`, `--save-optional`, `--save-peer` | `--dev`, `--exact`, `--optional`, `--peer` |
| `--save-catalog` | `--catalog` |
| `--no-optional`, `--ignore-optional` | `--omit=optional` |
| `--only=production` | `--omit=dev` |
| `--location=global` | `--global` |
| `--shamefully-hoist`, `--node-linker=hoisted`, `--install-strategy=hoisted` | `--linker=hoisted` |
| `--node-linker=isolated`, `--install-strategy=linked` | `--linker=isolated` |

대응이 없는 플래그(`--no-package-lock`, `--network-timeout 100000`)는 값까지 무시한다. 1.4.3은 플래그만 무시해서 `100000`을 패키지 이름으로 설치하려 했다. npm·Yarn·pnpm 어디에도 없는 플래그는 오류다. `bun install --frozen-lockfil`은 `bun install has no --frozen-lockfil flag.`를 내고, 예전에는 오타가 조용히 일반 설치가 됐다.

#### 6) install 추가 동작 (공식, 한 줄씩)

- `bun update --depth 0`은 `package.json`에 적힌 의존성만 올리고, 전이 의존성은 락파일을 유지한다.
- `bun prune --check`는 지울 것을 출력만 하고, 지울 것이 있으면 exit 1.
- `publishConfig.registry`와 `publishConfig["@scope:registry"]`가 `bun publish`의 레지스트리다.
- npm 11처럼 `2.0.0-beta.1` 같은 프리릴리스는 `--tag`나 `publishConfig.tag` 없이 출판을 거부한다. `latest`로 올리지 않는다.
- `workspace:*`가 `bun install`, `bun pm pack`, `bun publish`에서 루트 패키지를 가리킬 수 있다.
- `npm-shrinkwrap.json`도 `package-lock.json`처럼 이전한다.
- `bun.lock`에 `"hasInstallScript": true`를 기록해, 커밋된 락파일로 설치할 때 막힌 스크립트를 보고한다. 더 오래된 Bun은 이 키를 무시하고 다음에 락파일을 저장할 때 뺀다.
- `--frozen-lockfile` / `bun ci` 실패 시 `is-odd was added`, `is-number changed from ^6.0.0 to ^7.0.0`처럼 **어떤 의존성이 바뀌었는지** 말한다.
- `--dry-run`이 `bun link`, `bun unlink`, `bun pm version`, `bun pm cache rm`, `bun pm trust`, `bun pm pkg`, `bun pm migrate`에서 실제로 쓰기를 하지 않는다. 예전에는 플래그만 받고 파일을 고쳤다.
- `bun pm pkg set` / `delete`가 배열(`keywords[]=cli`, `contributors[0].name=Jane`)과 대괄호 키(`exports[./package.json]`)를 받는다.
- `bun pm view` / `bun info`가 프로젝트 밖에서도 되고, 필드를 여러 개 받으며 `maintainers[0].name` 같은 npm 경로를 받는다.
- `bun pm ls`가 패키지 이름, `--production`, `--omit`, `--depth=0`을 받는다.
- `bun pm version`의 `preversion` / `version` / `postversion`에 `$npm_old_version`, `$npm_new_version`, `$npm_command`, `$npm_package_version`을 넣는다.
- 의존성 라이프사이클 스크립트에 그 패키지 자신의 `npm_package_name`, `npm_package_version`, `npm_package_json`, `npm_package_config_*`, `npm_lifecycle_event`, `npm_lifecycle_script`, `npm_config_local_prefix`를 준다.
- `"gypfile": false`면 암시적 `node-gyp rebuild`를 하지 않는다.
- `bun create`가 `--ignore-scripts`를 받고, `bunfig.toml`의 `ignoreScripts = true` 또는 `.npmrc`의 `ignore-scripts=true`이면 템플릿 preinstall·postinstall도 건너뛴다.
- `bunx -p pkg cmd`는 `pkg`를 설치한 뒤 그 bin을 `PATH` 앞에 두고 `cmd`를 실행한다. npx와 같다.
- 자동 설치가 `.npmrc`의 레지스트리·자격 증명, `bun.lock` / `bun.lockb`의 핀, `package.json`의 `devDependencies`·`peerDependencies`·`overrides`·`resolutions`·`catalogs`를 `bun install`과 같이 읽는다. `workspace:`·`file:`·`link:`는 디스크에서 로드한다.
- 보안 스캐너가 git, GitHub, tarball, `file:`, `link:`를 포함한 **resolve된 모든 의존성**을 받는다.
- 레지스트리 메타데이터의 `Cache-Control: no-cache`, `no-store`, `max-age` 5분 미만을 따른다.
- `--use-system-ca`가 install과 다른 패키지 매니저 명령에 동작한다. 예전에는 `NODE_USE_SYSTEM_CA=1`만 됐다.
- `BUN_INSTALL`, `XDG_CACHE_HOME`, `BUN_INSTALL_CACHE_DIR`, `BUN_INSTALL_GLOBAL_DIR`, `BUN_INSTALL_BIN`, `NPM_CONFIG_USERCONFIG`가 `~/`로 시작할 수 있다.
- `bun audit fix`가 취약한 버전에 핀한 `overrides`를 보고하고 고친다.
- `globalStore = true`에서 no-op `bun install`이 `node_modules/.bun` 링크를 매번 지우고 다시 만들지 않는다. 이번 업그레이드 때 스토어 엔트리를 한 번 다시 만들고, `bun pm cache rm`이 옛 엔트리를 지운다.

개별 버그 수정은 [2.12](#212-bun-install-수정-전체)에 있다.

### 2.4 Bun.SQL 과 bun:sqlite

`Bun.SQL`, `bun:sqlite`, `node:sqlite`를 한 변경으로 다시 짰다. 열린 PR 149개를 대체하고 이슈 51개를 고친다. 쿼리마다 할당과 명령 수가 줄었다.

PostgreSQL, Linux x64, 사용자 공간 명령 수 (공식):

| 연산 | 변화 |
| :--- | :--- |
| point `SELECT` | −48% |
| 100행 `SELECT` | −30% |
| `INSERT` | −21% |
| 1,000행 × 10열 bulk insert | −38% |

같은 bulk insert의 MySQL 명령 수는 −53%다. `await sql\`select 1\``당 GC 객체는 PostgreSQL 84 → 28, MySQL 76 → 27, SQLite 52 → 33이다.

#### 쿼리 취소와 COPY

`cancel()`은 타입과 문서에만 있었고 아무 일도 하지 않았다. 이제 서버에 취소를 요청하고, 프로미스는 서버 오류로 reject된다. 아직 보내지 않은 쿼리는 보내지 않고 `ERR_POSTGRES_QUERY_CANCELLED`, `ERR_MYSQL_QUERY_CANCELLED`, `ERR_SQLITE_QUERY_CANCELLED`로 reject된다. MySQL·MariaDB에서 **이미 서버에서 도는 쿼리는 끝까지 실행**된다.

```ts
const query = sql`SELECT pg_sleep(30)`.execute();
setTimeout(() => query.cancel(), 100);
await query; // rejects: canceling statement due to user request
```

`query.writable()`는 `COPY ... FROM STDIN`, `query.readable()`는 `COPY ... TO STDOUT`다. 웹 스트림이고 backpressure가 있어 테이블이 커도 메모리가 평평하다. 바이트는 문이 지정한 `text`, `csv`, `binary` 그대로다. 공식: 1,000 MiB `COPY`가 255 MiB/s, 피크 RSS 59 MiB. 스트림 없이 일반 쿼리로 `COPY`를 쓰면 `ERR_POSTGRES_COPY_NOT_SUPPORTED`다.

#### 이름 변환, 배열, 메타데이터, JSON

`transform: SQL.camel`은 양쪽이다. 읽을 때 `first_name` → `firstName`, 쓸 때 `firstName` → `first_name`. 모든 어댑터. `SQL.camel`, `SQL.pascal`, `SQL.kebab`는 양방향. `SQL.toCamel`은 결과만, `SQL.fromCamel`은 `sql()` 헬퍼에 넘긴 이름만. pascal·kebab도 같은 쌍이 있다. `{ column: { from, to } }`에 함수를 직접 줄 수 있다. 이름은 postgres.js와 같다.

JavaScript 배열과 `Int32Array`를 PostgreSQL 내장 배열 자리에 넘길 수 있다. `null`과 중첩 배열 포함. `ANY(${[1, 2, 3]})`와 `tags: ["bun", "sql"]` insert는 예전에는 실패했다. `uuid[]`, `int4range[]`, `tsvector[]` 등 내장 배열 타입 35개가 `"{...}"` 문자열이 아니라 배열로 온다. 사용자 정의 타입(enum 등)은 `sql.array(values, "mood")`.

PostgreSQL·MySQL·MariaDB 결과에 `columns`와 `statement`가 있다. `type`으로 `jsonb`와 `text[]`처럼 JS 값이 비슷해도 서버 타입을 구분한다. MySQL·MariaDB 컬럼은 `{ name, type, table, length, flags }`. SQLite에서는 둘 다 `null`. `statement.string`은 `$1`이 들어 있는 전송 텍스트, `statement.types`는 파라미터 타입이다.

`sql.json(value)`는 모든 어댑터에서 JSON으로 저장한다. 숫자, 불리언, 문자열, `null`에 쓴다. 맨 `null`은 여전히 SQL `NULL`이다.

#### 연결과 `--hot`

`bun --hot`에서 `new SQL()`을 같은 설정으로 다시 만들면 리로드 전의 연결을 재사용한다. 예전에는 저장할 때마다 `max`까지 새 PostgreSQL·MySQL 연결을 열고 옛 연결을 남겨 뒀다. `max: 2`로 다섯 번 리로드하면 서버 세션이 12개였고 이제는 2개다. `SET`과 임시 테이블은 유지된다. 재사용된 연결마다 `onconnect`가 다시 돈다.

```ts
const sql = new SQL("postgres://app@db.example.com/app?connect_timeout=5", {
  channelBinding: "require",
  tls: {
    ca: Bun.file("./ca.pem"),
    checkServerIdentity: (hostname, cert) =>
      cert.fingerprint256 === pin ? undefined : new Error("pin mismatch"),
  },
});
```

- `channelBinding`: `"disable"`(기본), `"prefer"`, `"require"`. PostgreSQL SCRAM을 서버 TLS 인증서에 묶는다(SCRAM-SHA-256-PLUS). `?channel_binding=`, `PGCHANNELBINDING`.
- `tls.checkServerIdentity(hostname, cert)`: PostgreSQL·MySQL·MariaDB에서 `node:tls`처럼 호스트명 검사를 바꾼다. 이 함수를 넘기면 `verify-ca`보다 낮은 SSL 모드가 `verify-full`로 올라간다.
- `foundRows: true`: MySQL·MariaDB에서 `affectedRows`가 변경 행이 아니라 매칭 행. `mysql2`와 같다. `?foundRows=true`.
- URL의 `?connect_timeout=`, `?idle_timeout=`, `?max_lifetime=`, `?max=`.
- PostgreSQL URL의 libpq 파라미터 `host`, `port`, `user`, `password`, `dbname`, `sslrootcert`, `sslcert`, `sslkey`, `sslpassword`. 예전에는 서버로 포워딩되어 연결이 거부됐다.
- `PGAPPNAME`, `PGOPTIONS`, `PGCONNECT_TIMEOUT`.

`Bun.SQL`은 더 이상 환경 변수 `PASSWORD`를 읽지 않는다. `PGPASSWORD`, `MYSQL_PASSWORD`, URL, `password` 옵션을 쓴다.

#### sqlite 사용자 함수와 훅

이 문서에서 `:memory:` 데이터베이스로 실행해 확인했다.

```ts
import { Database } from "bun:sqlite";

const db = new Database(":memory:");
db.function("add2", (a: number, b: number) => a + b);
db.query("SELECT add2(12, 4) AS sum").get(); // { sum: 16 }

db.aggregate("add_all", {
  start: 0,
  step: (total: number, value: number) => total + value,
});
```

`function`과 `aggregate`는 `varargs`, `deterministic`, `directOnly`, `safeIntegers`를 받는다. `inverse`가 있으면 집계를 윈도우 함수로 쓸 수 있다. 함수가 던진 오류는 그 쿼리의 `get()` / `all()` / `run()`으로 전파된다. 시그니처는 better-sqlite3에 맞춘다.

`db.onInsert`, `db.onUpdate`, `db.onDelete`에 함수를 두면 이 `Database`가 넣은·고친·지운 행마다 SQLite가 호출한다. `null`이면 훅을 뗀다. `stmt.reader`는 행을 돌려주면 true, `stmt.readonly`는 데이터베이스를 직접 고치지 않으면 true다. `db[Symbol.for("sqlite-type")]`은 `"bun:sqlite"`라서 `node:sqlite`의 `DatabaseSync`와 구분할 수 있다.

### 2.5 WebSocket 과 ws

`import "ws"`는 Bun 네이티브 클라이언트·서버 위의 내장 구현이다. 이번에 npm `ws` 8.22.0을 기준으로 다시 포팅했다. 프레이밍, 마스킹, UTF-8 검사, 압축은 여전히 네이티브다.

| npm `ws` on Node와 비교 | v1.4.4 | 이전 |
| :--- | ---: | ---: |
| `ws` 테스트 271개 | 234 | 94 |
| 클라이언트 스크립트 212개 중 출력이 바이트 단위로 같은 수 | 179 | 18 |
| 서버 스크립트 159개 중 같은 수 | 150 | 67 |

남은 실패는 `ws._receiver`, `generateMask`처럼 네이티브 구현에 없는 내부 API에 의존한다.

구현된 것: `createWebSocketStream()`(backpressure, 예전에는 "Not supported yet in Bun"), `agent` / `createConnection` / `lookup`(SOCKS 에이전트. 예전에는 커스텀 agent를 무시하고 직접 연결), `handshakeTimeout`, `closeTimeout`, `followRedirects`, `maxRedirects`, `origin`, `auth`, `protocolVersion`, `autoPong`, `skipUTF8Validation`. `maxPayload`는 클라이언트와 서버에서 강제된다. socket.io의 `maxHttpBufferSize`가 여기에 의존한다. `WebSocketServer({ perMessageDeflate })`가 압축을 협상한다. `WebSocketServer`는 아무 `Duplex`나 받는다. `http2.createSecureServer({ allowHTTP1: true })`(`vite --https`), `server.emit("connection", socket)`(socket.io sticky), fastify `injectWS`가 여기 속한다. 서버 소켓에 `pause()`, `resume()`, `isPaused`가 있고 `instanceof WebSocket`이며 `ws._socket`은 `node:http` 소켓이다.

이벤트:

- `'error'`의 인자는 `Error`다. 예전에는 `ErrorEvent`. `error.code`는 `"ECONNREFUSED"` 같은 값.
- 리스너 없는 `'error'`는 Node처럼 uncaught exception이다. 클라이언트와 서버 소켓마다 `'error'` 리스너를 둔다.
- `'close'`는 연결이 닫힐 때 상대의 code와 reason으로 발생한다. reason은 `Buffer`다(예전에는 문자열). 코드 없는 `close()`는 1005, 실패한 연결은 1006.
- 오류 문구가 npm 패키지와 같다. 예: `Unexpected server response: 403`.
- `CONNECTING` 중 `send()`는 throw.
- `ws` 서버에는 idle timeout, 자동 ping, backpressure 제한이 없다. 예전에는 `Bun.serve` 기본값을 물려받아 idle 120초, 104초에 ping, 제한 16 MiB였다.
- 기본 `maxPayload`는 16 MiB에서 **100 MiB**.

표준 `WebSocket`의 `close`는 연결이 실제로 닫힌 뒤에 발생한다. 브라우저·Node와 같다. 예전에는 `close()` 직후 자기가 넣은 코드와 `wasClean: true`로 발생했다. 코드 없이 `close()`하면 빈 Close 프레임을 보내고 양쪽이 1000이 아니라 **1005**를 보고한다. `Bun.serve`의 `close(ws, code)` 핸들러도 포함된다. 스크립트가 `ws.close()`로 끝나면 라운드트립이 하나 더 있다. 서버가 30초 안에 응답하지 않으면 `close`는 1006이다. `BUN_CONFIG_WS_CLOSE_TIMEOUT`으로 그 30초를 바꾼다. `ws.terminate()`는 즉시 닫는다.

나쁜 핸드셰이크, TLS·프록시 오류, 프로토콜 오류, 너무 큰 메시지, 잘못된 UTF-8은 `error` 다음 `close` 1006으로 보고한다. `event.error.code`가 새로 있다. 예전에는 `close`가 1002, 1007, 1009, 1011, 1015와 영어 reason으로 발생하고 `wasClean: true`인 경우도 있었으며 `error`가 없는 경우가 많았다. `event.message`에 예전 reason 설명이 더 자세히 들어간다. `event.error.code` 예: `ENOTFOUND`, `DEPTH_ZERO_SELF_SIGNED_CERT`, `ERR_TLS_CERT_ALTNAME_INVALID`, `WS_ERR_INVALID_UTF8`. `open` 이후 TCP가 끊긴 것은 실패로 치지 않고 `close` 1006만 발생한다.

`Bun.serve`의 `ws.pause()` / `ws.resume()`는 처리보다 빨리 보내는 클라이언트를 늦춘다. pause 중에는 읽기를 멈춰 TCP backpressure가 걸린다. `ws.isPaused`로 상태를 본다. pause 중에는 idle timeout이 멈춘다. `websocket.error`는 오류와 **그 소켓**을 받는다. 예전에는 오류만 받았고 타입에도 없었다. `message`를 포함한 모든 핸들러는 생략할 수 있다.

`https://` 프록시에서 `tls`는 프록시와 대상 서버 둘에 적용됐다. `proxy.tls`를 주면 프록시는 `proxy.tls`만, 서버는 `tls`만 쓴다.

```ts
const ws = new WebSocket("wss://example.com", {
  proxy: {
    url: "https://proxy.internal:8443",
    tls: { ca: Bun.file("./proxy-ca.pem") },
  },
});
```

`ws`·클라이언트·서버의 개별 버그는 [2.10](#210-bun-api-web-tls-websocket-런타임-수정-전체)에 있다. 업그레이드 때 바로 깨질 수 있는 변화는 **리스너 없는 `error`가 프로세스를 죽이는 것**, `close` reason이 `Buffer`인 것, 코드 없는 close가 1000이 아니라 1005인 것, `ws` 서버의 120초 idle·자동 ping이 사라진 것이다.

### 2.6 JavaScriptCore, Glob, Headers, 스트림, strict

#### JavaScriptCore

업스트림 WebKit 커밋 1,013개. Apple silicon, 여러 번 중 최선 (공식):

| 연산 | v1.4.4 | v1.4.3 | 배율 |
| :--- | ---: | ---: | ---: |
| `n.toLocaleString("en-US")` 10만 회 | 25 ms | 1,341 ms | 54x |
| 정수 100만 개 배열 리터럴 로드 | 11 ms | 45 ms | 4.2x |
| `for (const ch of str)` 문자 100만, 일부 non-Latin-1 | 1.2 ms | 3.2 ms | 2.7x |
| `n`이 4 미만인 `new Array(n)` 1,000만 회 | 31 ms | 61 ms | 2.0x |
| `try { throw "x" } catch {}` 100만 회 | 37 ms | 72 ms | 2.0x |
| `try { throw new Error("x") } catch {}` 100만 회 | 128 ms | 174 ms | 1.4x |
| `new WeakMap()`과 `set()` 한 번, 100만 회 | 7.7 ms | 9.9 ms | 1.3x |

로케일만 주고 옵션 없는 `toLocaleString()`은 `Intl.NumberFormat`을 캐시해서, 포매터를 만들어 `format()`을 부르는 것과 같은 속도다. 숫자와 BigInt 모두.

의미 변화:

- `switch` 안의 중첩 함수에서 `using`이 `SyntaxError`가 아니다.
- `+1n * 2n`은 `TypeError`다. 예전에는 `2n`을 반환했다. **이 문서에서 `TypeError`를 확인했다.**
- `+a * b()`는 `b()`보다 먼저 `a.valueOf()`를 호출한다.
- `for...in`이 함수의 인덱스 프로퍼티(`fn[0]`)를 방문한다.
- JIT된 `(x + y + 0.5) | 0`이 `x + y`가 32비트를 넘어도 맞는 값을 반환한다.
- JIT된 코드가 `new Uint8Array(-1)`을 배열을 쓰지 않아도 `RangeError`로 던진다.
- sloppy 모드에서 `label: function f() {}`가 라벨 없는 함수 선언처럼 호이스트된다.
- WebAssembly 베이스라인 컴파일러가 함수에서 가장 많이 쓰는 로컬을 레지스터에 둔다.

#### Glob

extglob과 중괄호 범위가 `Bun.Glob`과 Bun이 glob을 쓰는 모든 곳(`--filter`, `workspaces`, `package.json`의 `files`·`sideEffects`)에 적용된다. 1.4.3에서 `"packages/!(internal)"` 워크스페이스는 `Workspace not found`였다.

| 패턴 | 의미 |
| :--- | :--- |
| `?(a\|b)` | 패턴 중 0개 또는 1개 |
| `*(a\|b)` | 0개 이상 |
| `+(a\|b)` | 1개 이상 |
| `@(a\|b)` | 정확히 하나 |
| `!(a\|b)` | 그 경로 조각에서 패턴이 아닌 것 |
| `{1..3}`, `{01..10}`, `{a..e}`, `{1..9..2}` | 숫자·문자 범위. 세 번째 값은 step |

`?`, `*`, `+`, `@`, `!` 다음이 아닌 `(`는 리터럴이다. Next.js `app/(marketing)/**`는 그대로다. **이 문서에서 `!(*.test).ts`, `@(app|lib)`, `shard-{1..3}`, `(marketing)` 리터럴을 확인했다.**

의미가 바뀌는 패턴:

| 패턴 | v1.4.3 | v1.4.4 |
| :--- | :--- | :--- |
| `*(1).txt` | `copy(1).txt`에 매칭 | `1`이 0번 이상 나온 뒤 `.txt`. 예전 의미는 `*[(]1).txt` |
| `!(g)/a.ts` | `(g)/a.ts`만 제외한 전부 | `g`가 아닌 폴더의 `a.ts` |
| `{1..3}` | 글자 `1..3` | `1`, `2`, `3` |

경로 글자는 그대로다. 이름에 그 문자가 있는 파일도 `**/*.ts`에 매칭된다. Bun Shell의 따옴표와 `${}`는 여전히 리터럴이라 이 변화의 밖이다.

`Bun.Glob.match()` 속도(공식, M4 Max): `**/*.{ts,tsx}`를 `src/components/button/index.tsx`에 맞추면 158 ns → 32 ns(1.6–5배 구간의 한 점).

#### Headers와 메모리에 있는 바디

`for...of`, `entries()`, `keys()`, `values()`, `forEach()`, `Object.fromEntries(headers)`가 1.7–2.8배다. `@hono/node-server`처럼 응답 헤더를 `node:http`로 복사하는 어댑터가 요청마다 이 경로를 탄다. M4 Max, 7회 중 최선 (공식): 헤더 3개 `for...of` 277 → 98 ns(2.8배), 헤더 14개 1.41 µs → 627 ns(2.2배), 커스텀 `X-` 14개 2.08 → 1.24 µs(1.7배), `forEach` 14개 1.10 µs → 505 ns, `keys()` 688 → 261 ns, `values()` 680 → 295 ns, `Object.fromEntries` 1.46 µs → 579 ns.

이미 메모리에 있는 바디(`new Response("...").body`, `request.body`, `blob.stream()`) 읽기가 1.5–2.6배다. 100바이트 바디 읽기 할당이 270 KB → 7 KB. Linux x64에서 `reader.read()`로 `new Response(string).body` 전체를 읽는 시간: 100 B 3.66 → 1.41 µs, 4 KB 4.15 → 1.77 µs, 16 KB 5.54 → 2.93 µs, 64 KB 14.33 → 9.11 µs, 1 MB 272 → 176 µs. Hono를 `@hono/node-server`에 올리면 요청 24개 배치가 24.0 ms → 16.0 ms.

이 문서의 arm64 실측은 비교 대상이 없는 절대 시간이다. 헤더 14개 `for...of` 20,000회 22.93 ms, 100바이트 `Response` 바디 `read()` 2,000회 3.47 ms, `toLocaleString("en-US")` 20,000회 6.91 ms. 1.4.3과 나란히 재지 않았으므로 배율로 쓰지 않는다.

#### `=strict`

1.4.3의 `--disallow-code-generation-from-strings=strict`는 정해 둔 API 목록을 막았다. 1.4.4에서는 JavaScriptCore가 **Bun 내장도 아니고 프로그램 자신의 파일도 아닌 코드**를 어떤 API로 들어왔든 실행하지 않는다.

`bun build --compile` 실행 파일에서는 실행 파일 안의 코드만 프로그램이다. 디스크의 JS·TS는 방금 프로그램이 쓴 파일이라도 실행되지 않는다.

```ts
const path = "/tmp/plugin.js";
await Bun.write(path, "console.log('hi')");
await import(path);
// EvalError: Code generation from strings disallowed for this context
```

`--compile`이 아니면 디스크 파일이 프로그램에 포함되므로 위 import는 실행된다. `=strict`가 추가로 막는 것: `contents`를 반환하는 플러그인(로더 무관, 대신 `exports` 객체를 반환), 매크로, 컴파일된 실행 파일에서 `BUN_OPTIONS`의 `--preload`와 디스크의 `.txt`·`.md` import. `.json`, `.toml`, `.yaml`은 디스크에서 여전히 로드된다. JSON이 들어 있는 `data:` URL의 `import()`는 더 이상 막지 않는다.

#### 개발 서버 오류 오버레이

`Bun.serve`와 HTML import의 오류 오버레이가 다시 그려졌고, 같은 파일의 비슷한 오류는 카드 하나로 묶인다. 스타일시트의 글꼴 세 개가 없으면 예전에는 블록 세 개였다. 오버레이가 스크롤된다. 창 아래의 오류에 도달하지 못하던 문제가 사라졌다. 서버와 브라우저 양쪽에 번들되는 파일(페이지가 import한 스타일시트)의 빌드 오류가 두 번 보이던 것이 한 번이 됐다. 라이트 테마는 시스템 설정을 따른다. 런타임 오류도 같은 디자인이고 제목은 오류 이름이다.

`bun ./index.html`이 공백 형태의 `--port 3000`, `--host 0.0.0.0`을 무시하던 문제, `--host=::1`의 `RangeError`, 시작 오류가 두 번 출력되던 문제가 같이 고쳐졌다.

### 2.9 Node.js 호환 수정 전체

블로그가 "various stability issues"라고만 적은 묶음은 `node:http`, `node:http2`, `node:quic`, `node:dgram`, `node:dns`, `node:crypto`, `node:vm`, `node:stream`, `node:zlib`, `node:util`, `node:diagnostics_channel`, `node:worker_threads`, 네이티브 애드온이다. 아래에 개별 항목을 모두 적는다.

**`node:http`**

- `res.statusCode`가 `"404"` 같은 숫자 문자열이나 `200.5` 같은 분수일 때 `res.end()`가 `ERR_INVALID_ARG_TYPE`을 던지던 것을, Node처럼 `404`와 `200`을 보내도록 고쳤다.
- `NaN`이나 `undefined`면 `200`을 보내던 것을 `ERR_HTTP_INVALID_STATUS_CODE`로 고쳤다.
- `res.end({})`가 잘못된 청크로 throw한 뒤 아무것도 안 보냈는데 `res.headersSent`가 true라 `res.setHeader()`가 `ERR_HTTP_HEADERS_SENT`를 던지던 것을 고쳤다.

**`node:http2`**

- `pushStream()`이 `ERR_HTTP2_OUT_OF_STREAMS`를 콜백으로 넘기지 않고 throw하던 것을 고쳤다.
- `http2.createSecureServer()`와 `server.emit("connection", socket)`에서 `session.socket`이 `TLSSocket`이 아니고 `'connection'` 리스너가 안 불리던 것을 고쳤다.

**`node:fs`**

- Linux·macOS의 모든 `fs.realpath()` 변형이 `\`를 구분자로 봐서, `a\b`라는 파일이 `ENOENT`가 되거나 존재하는 `a/b`로 resolve되던 것을 고쳤다.
- `realpath.native()`, `realpathSync.native()`, `fs.promises.realpath()`가 심볼릭 링크를 따라가기 전에 `..`를 접어서, `link/../y`가 링크 대상이 아니라 링크 옆으로 resolve되고 `missing/..`가 throw하지 않던 것을 고쳤다.
- `realpath()` / `realpathSync()`가 `file/`처럼 일반 파일에 슬래시가 붙으면 `ENOTDIR`를 던지던 것을, Node처럼 그 파일 경로를 반환하도록 고쳤다.
- Windows에서 `fs.promises.realpath("C:\\")`가 `C:`를 반환하던 것을 `C:\`로 고쳤다.

**`node:vm`**

- `vm.createContext(vm.constants.DONT_CONTEXTIFY)`가 컨텍스트 글로벌 대신 래퍼를 반환해, 최상위 `var`·`function`이 사라지고 Vitest+jsdom 30.1이 시작하지 못하던 것을 고쳤다.
- 그 컨텍스트에서 글로벌 프로토타입 체인의 이름, `Proxy`를 통한 이름에 `ReferenceError`가 나던 것을 고쳤다. jsdom 30의 `runScripts`가 이 동작에 의존한다.

**`node:stream` / `node:crypto` / `node:util` / `process`**

- `Readable.fromWeb(stream).destroy()`가 웹 스트림 `cancel()` reject 때 `'error'`를 내던 것을, Node처럼 내지 않도록 고쳤다.
- X25519 `CryptoKey`를 `structuredClone()`·`postMessage()`로 복제하지 못하던 것을 고쳤다.
- `Hash`·`Hmac`의 `digest()` 이후 `write()`가 `ERR_CRYPTO_HASH_FINALIZED`를 던지던 것을, Node처럼 청크를 버리도록 고쳤다.
- `util.types.isDate`처럼 생성자가 아닌 네이티브 함수에 `new`를 하면 호출 결과를 반환하던 것을 `TypeError`로 고쳤다. 출력도 `[class isDate]`였다.
- `util.types.isProxy(globalThis)`가 true이던 것을 고쳤다.
- `process.on()`에 같은 함수를 두 번 등록하면 한 번만 들어가던 것을, Node처럼 두 번 등록되고 두 번 불리게 고쳤다.
- `import * as process from "node:process"` 뒤 `process.on()`이 `process`에 리스너를 안 넣던 것을 고쳤다.

**`node:diagnostics_channel` / 워커 / 애드온 / 기타**

- `publish()` 도중 구독자가 자기 자신을 해제하면 다음 구독자를 건너뛰던 것을 고쳤다.
- `publish()` 도중 추가된 구독자가 그 `publish()`에서 불리던 것을 고쳤다.
- `channel._subscribers`가 frozen·sealed 배열일 때 `unsubscribe()`가 `TypeError`를 던지던 것을 고쳤다.
- `env: SHARE_ENV` 워커에서 `process.env`가 프로토타입 체인에 있는 배열의 구멍을 `join()`·`slice()`·`concat()`가 빈 값으로 취급하던 것을 고쳤다. `arr[1]`은 이미 `process.env[1]`을 읽고 있었다.
- 메인 스레드가 이미 로드한 `NODE_MODULE` 애드온을 워커에서 로드하면 `ERR_DLOPEN_FAILED`를 던진다. Node와 같다.
- 워커가 네이티브 애드온의 비동기 작업이 끝나기 전에 멈추면 파이널라이저가 그 작업보다 먼저 돌던 것을, Node처럼 작업 뒤로 미뤘다.
- `node:net`·`node:tls` 소켓이 쓰기가 대기 중일 때 연결이 닫히면 `write()` 콜백이 안 불리던 것을 `ECANCELED`로 부르게 고쳤다.
- `os.userInfo()`에 숫자나 문자열을 넘기면 `TypeError: Type error`이던 것을 Node처럼 고쳤다.
- `os.setPriority(priority, undefined)`가 throw하던 것을 Node처럼 고쳤다.
- `node:dgram`의 `socket.connect()`가 포트 `"41234"`에 `ERR_INVALID_ARG_TYPE`이던 것을, Node가 받는 대로 고쳤다.
- `zlib.crc32(data, undefined)`가 `ERR_INVALID_ARG_TYPE`이던 것을 `zlib.crc32(data)`처럼 0에서 시작하게 고쳤다.
- `http.maxHeaderSize = "5000000000"`이 `705032704`로 랩되던 것을, 1 이상의 안전 정수만 받게 고쳤다. `"16384"` 문자열은 `ERR_INVALID_ARG_TYPE`이다.
- `node:module`의 `new SourceMap()`이 빈 `mappings`(re-export만 있는 청크의 소스맵)에 `ERR_INVALID_ARG_TYPE`이던 것을 고쳤다.
- `node:inspector`의 `Profiler.takePreciseCoverage`가 V8과 다른 함수·블록 범위를 줘서 `v8-to-istanbul`가 잘못된 줄을 표시하던 것을 고쳤다. 건너뛴 `?? fallback()`이 실행된 것으로 세어졌다.

### 2.10 Bun API, Web, TLS, WebSocket, 런타임 수정 전체

"various stability" 묶음: `Bun.serve`, `Bun.spawn`, `FileSink`, `Bun.S3Client`, `Bun.RedisClient`, `Bun.YAML`, `Bun.JSON5`, `Bun.markdown`, `Bun.Cookie`, `Bun.WebView`, `HTMLRewriter`, `bun:ffi`, `Bun.gzipSync()`, `Bun.deflateSync()`, `Bun.unsafe.arrayBufferToString()`. Web 쪽 묶음: 실험적 HTTP/2 `fetch()`, `ReadableStream.from()`, `crypto.subtle`, `structuredClone`, `URL`, `URLSearchParams`, `URLPattern`, `Headers`, `FormData`. TLS 클라이언트·서버, WebSocket 클라이언트와 `ws`도 같은 문장이 있다.

**Bun API**

- 워커 안 `Bun.serve` 핸들러가 던진 오류가 메인 스레드처럼 출력된다.
- `Bun.hash()`와 그 알고리즘이 `Bun.file()`, S3 파일, `outdir`에 쓴 `Bun.build()` 출력에 빈 입력의 해시를 반환하던 것을 `TypeError`로 고쳤다.
- `Bun.CryptoHasher`, `Bun.SHA1.hash()`, `Bun.sha()`, `crypto.hash()`가 S3 파일에 빈 다이제스트를 반환하던 것을, `Bun.file()`과 같이 `TypeError`로 고쳤다.
- `Bun.hash()`, `Bun.hash(undefined)`, `Bun.hash(null)`이 `""`, `"undefined"`, `"null"`의 해시이던 것을 `TypeError`로 고쳤다. `crc32`와 다른 알고리즘도 같다. **`Bun.hash(null)`의 `TypeError`를 이 문서에서 확인했다.**
- `Bun.MD5`, `Bun.SHA256` 등의 서브클래스에서 정적 `byteLength`를 읽으면 `TypeError`, `Bun.CryptoHasher` 서브클래스의 `algorithms`도 같던 것을 고쳤다.
- `Bun.Glob.match()`가 중괄호 안의 `**`를 `*`처럼 봐서 `{src/**,lib/**}`가 `src/a/b.ts`에 안 맞던 것을 고쳤다.
- 중괄호 그룹이 10개를 넘거나 중첩이 10을 넘으면 `match()`가 false이던 것을 고쳤다.
- `scan()` / `scanSync()`가 `true`가 아닌 truthy 옵션을 false로 보던 것을 고쳤다. `{ dot: 1 }`이 닷파일을 건너뛰고 `{ onlyFiles: 1 }`이 디렉터리를 나열했다.
- `Bun.JSON5.parse("1\0 2")`가 `1`, `"{a\\u002d: 1}"`가 `{ a: 1 }`로 파싱되던 잘못된 입력을 `SyntaxError`로 고쳤다. **NUL 케이스를 이 문서에서 확인했다.**
- `Bun.markdown.ansi()`와 `bun file.md`가 ``code`` 뒤의 `.`, `(` 뒤의 링크처럼 여러 조각으로 된 단어 중간에서 줄을 끊을 수 있던 것을 고쳤다.
- `bun:ffi`의 `cc()` 심볼 `.ptr`이 C 함수 주소가 아니던 것을 고쳤다.
- `Bun.YAML.parse()`가 S3 파일에 `null`, `Bun.TOML.parse()`가 `{}`를 반환하던 것을, `Bun.file()`처럼 `TypeError`로 고쳤다.
- `Bun.gzipSync()` / `Bun.deflateSync()`가 `memLevel`과 `strategy`를 무시하고 기본값만 쓰던 것을 고쳤다. `memLevel` 1–9 밖, `strategy` 0–4 밖은 throw.
- `Bun.CSRF.generate(undefined, options)`가 "Secret is required"라서 기본 시크릿을 유지한 채 옵션을 넘길 수 없던 것을 고쳤다.
- `Bun.$.escape()`가 이스케이프가 필요 없는 `null`, `true`, `new String("foo")`를 비문자 그대로 반환하던 것을, 항상 문자열을 반환하게 고쳤다.
- `Bun.CSRF.generate()`의 `expiresIn: NaN`, `verify()`의 `maxAge: NaN`, `Bun.dns.prefetch()`의 `NaN` 포트가 기본값으로 떨어지던 것을 `RangeError`로 바꿨다.
- `Bun.indexOfLine()`의 첫 인자가 버퍼가 아니면(개행이 있는 문자열 등) `-1`이던 것을 `TypeError`로 고쳤다.
- `Bun.JSONL.parseChunk()`가 이미 반환한 값 뒤에  stray `,` `]` `}`가 있으면 `read` 오프셋을 그 값보다 앞에 보고하던 1.4.3 회귀를 고쳤다.
- `Bun.JSONL.parse()` / `parseChunk()`가 빈 줄 뒤에 stray `,` `]` `}`가 있으면 값을 두 번 이상 반환하던 1.4.3 회귀를 고쳤다.
- `Bun.FileSystemRouter`의 `assetPrefix`가 항상 `undefined`이던 것을, 옵션 값 또는 없으면 `null`로 고쳤다.
- `match()`의 `query`와 `params`가 숫자 키를 두 번 넣어 `Object.values(router.match("/?0=a").query)`가 `["a", "a"]`이던 것을 고쳤다.
- `Bun.ModuleGraph`의 `graph.dispose()`가 `Bun.Terminal`이 열려 있거나 `node:http` 서버가 listen 중이면 그래프 모듈을 누수하고, 터미널 fd도 누수하던 것을 고쳤다.

**Web / fetch / Blob**

- `keepalive: false`인 `fetch()`, 또는 `keepAlive: false`인 `Bun.FetchSession`이, 요청에 `Connection: keep-alive`가 있으면(헤더를 그대로 전달할 때 생김) HTTP/1.1 연결을 풀에 열어 두던 것을 고쳤다.
- `new Response(blob, { headers }).blob()`이 타입이 없는 원본 `Blob`에 `type`을 써 넣던 것을 고쳤다.
- 바디 `Blob`의 타입 없는 `slice()`가 부모 타입을 유지하던 것을 `""`로 고쳤다.
- `WebSocket`, `BroadcastChannel`, `Worker`를 `Reflect.construct()`할 때 `newTarget`의 `prototype` getter가 throw해도 연결·구독·스레드 시작이 일어나던 것을 고쳤다.

**TLS**

- `requestCert: true`가 있어야 클라이언트 인증서를 요청한다. `ca`만으로는 요청하지 않는다.
- `tls.createServer()`의 `SNICallback`이 ALPN을 협상하지 않고 `ALPNProtocols`·`ALPNCallback`을 무시해 HTTP/2 클라이언트가 HTTP/1.1로 떨어지던 것을 고쳤다.
- `ws`가 최상위 TLS 옵션 `rejectUnauthorized`, `ca`, `cert`, `key`를 무시해 자체 서명 `wss://`가 `TLS handshake failed`이던 것을 고쳤다. `pfx`도 된다.
- `node-fetch`가 `https.Agent`의 `ca`, `cert`, `key`, `rejectUnauthorized`를 무시하던 것을 고쳤다.
- Ed25519 인증서 서버에 `fetch()`, `tls.connect()` 등이 실패하던 것을 고쳤다.
- CA로 표시되지 않은 자체 서명 인증서(`dotnet dev-certs`가 만드는 종류)를 `NODE_EXTRA_CA_CERTS`나 `ca`로 줘도 신뢰하지 않던 것을 고쳤다.
- `key`·`cert` 쌍이 여러 개면 마지막 쌍만 제공하던 것을, RSA와 ECDSA를 같이 두면 클라이언트가 지원하는 쌍을 받게 고쳤다.
- `tls.DEFAULT_CIPHERS` 대입이 `fetch`, `WebSocket`, `Bun.connect`, `RedisClient`, `Bun.SQL`, `S3Client`에 영향을 주지 않던 것을 고쳤다.
- `sslmode=prefer`인 `Bun.SQL`이 TLS 없는 Postgres에서 타임아웃나던 것을, 문서대로 비암호화로 폴백하게 고쳤다.
- `Bun.SQL`이 `node:tls` 철자 `tls.servername`을 무시하던 것을 고쳤다.
- `autoSelectFamily`인 `tls.connect()`가 시도한 주소마다 `'end'` 리스너를 넣어 아홉 번째 이후 `MaxListenersExceededWarning`이 나던 것을 고쳤다.
- `key`, `cert`, `ca`, `crl`, `ALPNProtocols`가 `buffer.subarray(n)` 같은 뷰를 받으면 뷰가 아니라 원본 `ArrayBuffer` 전체를 읽던 것을 고쳤다.

**WebSocket 클라이언트**

- 메모리 안 `Bun.build()` 출력에 `send()`·`ping()`·`pong()`이 텍스트 `[object BuildArtifact]`를 보내던 것을, `ServerWebSocket`처럼 바이트를 보내게 고쳤다.
- `ws.send()` 직후 `ws.close()`가, 서버가 아직 보내는 중이면 `ws://`에서 메시지를 잃고 `close`는 깨끗한 1000을 보고하던 것을 고쳤다.
- 프록시 경유 `wss://`에서 Close·Pong이 대기 메시지보다 먼저 나가 메시지가 유실되고 close는 깨끗하다고 보고되던 것을 고쳤다.
- TLS 1.2 서버가 renegotiate하는 동안 프레임을 보내면 프록시 경유 `wss://`가 1006으로 닫히던 것을 고쳤다. 직접 연결은 영향이 없었다.
- backpressure 아래에서 송신 큐 끝이 플러시되지 않고 `bufferedAmount`가 0보다 크게 남는 드문 경우를 고쳤다.
- `new WebSocket()`의 `AsyncLocalStorage` 컨텍스트에서 이벤트 리스너가 돌지 않던 것을 고쳤다.
- `{ protocols: "chat" }`가 "Value is not a sequence"를 던지고 `protocol: "chat"`가 무시되던 것을 고쳤다.
- `ws://:token@host`가 자격 증명을 안 보내던 것을 고쳤다.
- `proxy.headers`의 항목 하나가 잘못되면 `Proxy-Authorization`을 포함해 헤더 전체가 조용히 버려지던 것을, throw하도록 고쳤다.
- 프록시 407이 "Proxy connection failed"로 보고되고, reason phrase 없는 `HTTP/1.1 200`이나 200이 아닌 2xx CONNECT를 거부하던 것을 고쳤다.
- 101 전에 `100 Continue`나 `103 Early Hints`가 오면 핸드셰이크가 실패하던 것을 고쳤다.
- `Bun.file()`이나 S3 파일을 `send()`·`ping()`·`pong()`에 주면 빈 프레임이던 것을 throw로 고쳤다.
- 비ASCII 헤더 값을 UTF-8로 보내던 것을, `fetch`와 Node처럼 Latin-1로 고쳤다.
- 타입: `error`·`onerror`는 `ErrorEvent`, `ping`·`pong` 이벤트와 `binaryType: "blob"`이 선언되고, `headers`는 `Headers`를 받는다.

**`Bun.serve` WebSocket 서버**

- `perMessageDeflate: true` 서버가 압축 메시지를 보내면 Safari가 1002로 닫던 것을 고쳤다.
- `compress`의 `"dedicated"`와 `"4KB"`–`"256KB"`가 `"3KB"`로 취급되던 것을, 값마다 윈도우 크기를 쓰게 고쳤다. `"dedicated"`는 연결당 149 KB → 282 KB.
- `{ compress: false, decompress: true }`가 나가는 메시지를 압축하고, `decompress: "16KB"`가 압축기 쪽을 설정하던 것을 고쳤다.
- `server.stop(true)`가 WebSocket을 1006으로 닫던 것을 1001 "Server closed"로 고쳤다.
- 프로토콜 오류, 잘못된 UTF-8, `maxPayloadLength` 초과 뒤 클라이언트가 1006을 보던 것을, 1002·1007·1009와 reason이 있는 Close 프레임으로 고쳤다.
- `idleTimeout: 0`이 약 256초 뒤에 유휴 연결을 닫던 것을, 닫지 않도록 고쳤다.
- `idleTimeout: 65536`, `maxPayloadLength: 2 ** 32 + 16`, `backpressureLimit: 2 ** 32 + 1`이 0, 16, 1로 랩되던 것을 고쳤다.
- `maxPayloadLength`가 Ping, Pong, Close에도 적용되던 것을 고쳤다.
- `backpressureLimit`를 넘은 소켓의 `ws.close()`가 이미 `send()`가 받은 메시지와 Close 프레임을 버리던 것을 고쳤다.
- `ws.cork()`, `drain`, 비동기 업그레이드 뒤 `open` 안의 `ws.close()`가 16초 늦게 닫히던 것을 고쳤다.
- `terminate()`, throw하는 `open`, `stop(true)`, 프로세스 종료가 같은 틱에 `send()`·`publish()`가 받은 데이터를 버리던 것을 고쳤다.
- 긴 `ws.close(code, reason)` reason이 문자 중간에서 잘려 클라이언트가 1007을 보던 것을 고쳤다.
- `server.upgrade(req, { headers })`가 `headers`에 `Sec-WebSocket-Accept`, `Upgrade`, `Connection`이 있으면 두 번 보내고, `headers: {}`에서 throw하며, 서브프로토콜을 거절하지 못하던 것을 고쳤다. 빈 `Sec-WebSocket-Protocol`이 거절이다.
- `server.upgrade()` 이후 throw가 조용히 버려지던 것을 `error()`로 넘기거나 stderr에 찍게 고쳤다.
- `server.reload()`가 WebSocket이 있는 서버의 라우트마다 메모리를 누수하고, 이미 열린 소켓에 새 `websocket` 옵션이 적용되지 않던 것을 고쳤다.

**`ws` 패키지 구현과 `node:http`**

- `ws` 서버가 큰 메시지를 연속으로 보내면 일부가 두 번, 일부가 순서 없이 전달되던 것을 고쳤다.
- `ws.once("message")`와 `ws.on("message")`를 같이 두면 메시지가 두 번 전달되던 것을 고쳤다.
- 서버 소켓에서 `addEventListener("message")`가 텍스트를 `Buffer`로 받고 `onclose`가 숫자를 받던 것을 고쳤다.
- `ArrayBuffer`·`Blob`에 대한 `send()`의 `binary` 옵션이 무시되고 `{ fin: false }`가 조각이 아니라 전체 메시지를 보내던 것을 고쳤다.
- `close()` 이후 버려진 메시지에 `send()` 콜백이 성공을 보고하던 것을, 데이터가 쓰인 뒤 또는 소켓이 먼저 닫히면 오류로 한 번만 부르게 고쳤다.
- 연결이 끝난 뒤 `'close'` 전에 버려진 프레임의 `send()`·`ping()`·`pong()` 콜백이 성공을 보고하던 것을 `ERR_STREAM_DESTROYED`로 고쳤다.
- `await`나 비동기 `verifyClient` 뒤 지연된 `handleUpgrade()` 전에 도착한 메시지가 유실되던 것을 고쳤다.
- `'unexpected-response'`에서 청크 바디가 디코딩되지 않고, 응답 헤드 뒤에 온 바디가 유실되던 것을 고쳤다.
- `hpagent`의 `proxyRequestOptions.headers`를 무시해 `Proxy-Authorization`이 필요한 프록시가 407을 주던 것을 고쳤다.
- `'headers'` 리스너가 push한 헤더가 101 응답에 없고(engine.io 쿠키), `handleProtocols: () => false`가 그래도 프로토콜을 고르던 것(graphql-ws)을 고쳤다.
- `node:http`의 `'upgrade'`·`'connect'` 소켓에서 `socket.bytesWritten`이 0이던 것을 고쳤다. engine.io가 1초 뒤 그런 소켓을 닫아서 Vite·SvelteKit 개발 서버의 socket.io가 1초마다 페이지를 새로고침했다.
- Slack Bolt Socket Mode가 `undici`에 `ping()` export와 `undici:websocket:ping`·`pong` diagnostics channel이 없어 영원히 재접속하던 것을 고쳤다.

**런타임, hot, watch, bun run**

- Linux arm64 시작, Linux GC, uncaught 오류 보고의 안정성.
- 구문 오류의 `^`가 그 줄 앞의 전각 문자(CJK) 때문에 너무 왼쪽을 가리키던 것을 고쳤다.
- JIT 함수에서 원소 16개 이하 정수의 `.sort()`가 `(a, b) => (a + 0.5) - (b + 0.5)` 같은 비교자로 틀린 결과를 내던 1.4.0 이후 회귀를 고쳤다.
- cgroup v1 계층이 같이 있는 Linux(단지 `name=systemd`여도)에서 cgroup v2 제한을 `navigator.hardwareConcurrency`, `os.availableParallelism()`, `process.constrainedMemory()`, 스레드 수, GC 힙 크기가 무시하던 것을 고쳤다.
- 블록 맨 위의 `let copy = value` 직후 throw가, 상수가 약 110개를 넘는 함수에서 더 앞선 문의 줄·열로 보고되던 것을 고쳤다.
- `CallSite#getColumnNumber()`가 1이 아니라 0부터 세던 것을 고쳤다. `@cspotcode/source-map-support`가 설치된 상태에서 열 1인 프레임의 `error.stack`을 읽으면 "`column` must be greater than or equal to 0"이 났다.
- `error.stack`이 열 1인 프레임의 열을 빼서 `file.js:3:1` 대신 `file.js:3`으로 찍던 것을 고쳤다.
- `const x = require("./x")` 프레임이 `require()`가 아니라 `x`를 가리키던 것을 고쳤다.
- 정의되지 않은 JSX 컴포넌트가 여는 태그가 아니라 닫는 태그에서 보고되던 것을 고쳤다.
- 마지막 줄에 개행이 없는 파일의 uncaught 오류 소스 미리보기가 그 줄을 빼던 것을 고쳤다.
- `bun --hot`·`bun --watch` 안정성. macOS·Linux에서 uncaught 예외 뒤 `--hot` 타이머가 저장으로 고친 뒤에도 안 울리던 것을 고쳤다. 리로드는 종료 코드도 0으로 되돌린다.
- `bun run`, `bunx`, 모듈 resolve 안정성. 컨테이너 PID 1일 때 Ctrl+C나 `docker stop`의 종료 코드가 128 + 시그널 번호다.

### 2.11 트랜스파일러, bun check, 번들러, 테스트, 셸 수정 전체

**트랜스파일러**

- `Bun.Transpiler`와 TypeScript 데코레이터 안정성.
- `@dec static {}`를 받던 것을, 클래스 static 블록의 데코레이터는 TypeScript·esbuild처럼 구문 오류로 고쳤다.
- 표준 데코레이터에서 클래스 데코레이터가 새 클래스를 반환해도, 본문 안의 클래스 이름(데코레이터 인자, 정적 필드, 메서드)이 원래 클래스를 가리키던 것을 고쳤다.
- 2^53을 넘는 16진·8진·2진 리터럴이 틀린 double로 반올림되던 것을 고쳤다. `0xb3c8bf81fdf2247`이 Node와 다른 수였다. `Bun.JSONC.parse()`도 같았다.
- `exports.eliminate`가 제거된 export만 쓰던 import를 남기던 것을 고쳤다. `trimUnusedImports: false`면 import를 유지했는데, TypeScript 출력에 맨 `import "pkg"`가 남았다.

**`bun check` 정확도**

- 안정성 한 건.
- Slate `CustomTypes` 모듈 보강(`Editor: BaseEditor & ReactEditor`)의 거짓 TS2456·TS2502. `Editor`가 `any`가 되어 진짜 오류가 숨었다.
- 스레드 수에 따라 오류가 달라지던 것. `@sinclair/typebox`에서 스레드 2개 이상일 때 거짓 TS2321.
- TypeScript 7.1을 따라 TS2321을 보고하지 않는다. 중첩 비교 100번 뒤에는 연관된 타입으로 가정한다.
- `Promise | PromiseLike`의 `.then()` 결과를 `"catch" in result`로 좁힐 때 `tsc`가 안 내는 TS18046·TS7006. tRPC에 영향.
- 무한히 깊은 타입의 선택 파라미터를 뺀 호출의 거짓 TS2589. TanStack Router `useLoaderData()`와 재귀 JSON.
- 클래스나 제네릭 함수 안에서 spread로 만든 객체가 제네릭 호출 체인을 통과할 때의 거짓 TS2589. ts-pattern.
- immer `Draft`를 받는 메서드가 있는 클래스를 타입 가드가 좁힌 뒤의 거짓 TS2615.
- 서로를 참조하고 `infer`를 쓰는 제네릭의 거짓 TS2344, TS2345, TS2339, TS7031.
- 한 멤버가 `never` 제약의 미해결 조건부 타입을 가진 intersection 유니온에 대입할 때의 거짓 TS2322.
- 제네릭 별칭(`Id`)으로 적힌 제네릭 함수를 제네릭 래퍼에 넘기고 그 결과를 같은 별칭에 대입할 때의 거짓 TS2322.
- 클래스 메서드가, 그 클래스의 타입 파라미터·메서드와 같은 이름의 import 함수를 호출할 때의 거짓 TS2554.
- 반환 타입 주석이 자기 자신을 참조하는 함수의 `return`에 TS2577 위에 TS2322를 더 내던 것.
- 반환 타입 없는 제너레이터가 루프에서 변수를 yield하고 자기 호출로 다시 대입할 때 `tsc`가 안 내는 TS7023.
- 루프가 재대입하는 변수를 `extends`가 읽는 클래스에 `tsc`보다 넓은 타입을 주어, `tsc`가 안 내는 TS2322가 나던 것.
- `unknown` 문맥의 구조 분해 파라미터 기본값이 다른 바인딩을 읽을 때 `tsc`의 TS2339 자리에 TS7022를 내던 것. `take({ first, second = first })`.
- `tsconfig.json`이 순환 `extends`일 때 TS18000의 파일 이름 자리에 `{0}`을 찍던 것.
- 루프에서 재대입되는 변수의 타입을 추론하는 동안 `tsc`가 내는 오류를 놓치던 것. `last = last.next = item`의 TS2322, 그리고 TS2367, TS2774, TS2349, TS2344.
- 루프 본문에서 더 먼저 읽히는 루프 변수에 대입되는 값 안의 `y === 5`(`y: string`) TS2367을 놓치던 것.
- 루프가 클래스 프로퍼티를 통해 자기 변수에 의존하는 값, 또는 `for...of` 변수로 재대입할 때 TS7022를 놓치던 것.
- setter 파라미터 주석이 그 setter가 선언하는 프로퍼티를 읽는 TS2502를 놓치던 것.
- 자기 참조 제약이 있는 제네릭 함수를 제네릭 호출에 넘길 때 TS2589를 놓쳐, 위의 `// @ts-expect-error`가 미사용으로 표시되던 것.
- `readonly`를 제거하는 매핑 타입과 교집합일 때 `readonly` 프로퍼티의 TS2540·TS2704를 놓치던 것.
- 매핑 타입과 클래스의 교집합을 통해 `protected`·`private`를 읽을 때 TS2445·TS2341을 놓치던 것.
- `tsconfig.json` 객체의 키 수, 주로 `paths`에 2차 시간이 걸리던 것. 키 40,000개가 10.9 s → 0.1 s.
- `paths`나 `files` 항목 수천 개가 각각 오류일 때 2차 시간. TS5090 4,000개가 35.5 s → 0.04 s.
- 프로젝트 디렉터리에 형제 파일이 수만 개일 때(`$TMPDIR`, 큰 `~/code`) 느려지던 것.
- `bun check -b`가 공유 base `tsconfig.json`을 한 번만 파싱. `paths` 5,000개를 extend하는 프로젝트 1,000개가 71 s·3.08 GB → 1.6 s·0.62 GB.
- `bun check -b`가 작은 프로젝트를 병렬로 검사. 동시 4개에서 최대 16개. 큰 프로젝트로 이뤄진 모노레포는 메모리를 더 쓴다.

**번들러, compile, CSS, 개발 서버**

- `bun build`, `Bun.build` 플러그인, 매크로 안정성.
- `--minify`가 괄호로 묶인 이름 있는 함수·클래스 표현식 기본 export 두 개에 같은 이름을 주던 것. `export default (function inc() {})`.
- 스타일시트가 `url()`로 같은 이미지를 인라인하면 HTML의 그 이미지 참조가 소스 경로를 가리킨 채 파일을 안 쓰던 것.
- `--react-compiler` 소스맵에서 `catch`와 그 뒤 `{`가 `try` 위치를 가리키던 것.
- `export default function`, `export default class`, `export async function`, `abstract class`, `import()`, `require()`, `require.resolve()`의 소스맵 열이 틀리던 것.
- `bun build --compile`과 컴파일된 실행 파일의 안정성.
- CSS 파서 안정성.
- 같은 CSS 규칙에서 `transform`보다 앞에 선언된 `translate`, `rotate`, `scale`을 버리고, 뒤에 선언된 것은 `transform`으로 합치던 것.
- 개발 서버 안정성.
- `url('/fonts/a.woff2')` CSS resolve 오류의 밑줄이 5자 앞에서 끝나던 것을, `url(...)` 전체를 덮게 고쳤다. `composes: x from "./a.css"`에서는 경로만 덮는다.
- `bun ./index.html`의 `--port`·`--host` 공백 형식, `--host=::1`의 `RangeError`, 시작 오류 이중 출력.

**`bun test`**

- `bun test`, `bun test --changed` 안정성.
- `--update-snapshots`가 `--bail`처럼 일찍 끝나면 스냅샷 파일을 비우던 것을, 새 내용이 쓰일 때까지 옛 내용을 유지하게 고쳤다.
- `--coverage`가 건너뛴 코드를 커버된 것으로 세던 것. 혼자 한 줄인 `||` `&&` `??` `?:`의 오른쪽, `?.` `||=` `&&=` `??=`와 쓰이지 않은 기본값으로 건너뛴 코드, 타지 않은 `break`.
- `await`·`yield` 뒤의 줄을, 함수가 그 너머로 재개되지 않았는데 커버된 것으로 세던 것. 업그레이드 후 `% Lines`가 내려갈 수 있으니 `coverageThreshold`를 확인한다.
- 한 번도 안 돈 함수의 `Uncovered Line #s`가 두 줄 일찍 시작하고 마지막 줄을 빼던 것.
- 실행된 줄을 미커버로 보고하던 것. `while (true)` 안 블록의 `break`, `class Derived extends Base() {}` 위의 `import`.
- 실행된 함수에서 혼자 있는 `default:` 줄, 값이 다음 줄인 `case`를 무시하던 것.
- `else`와 `{`가 다른 줄일 때 `{` 줄을 나열하고, 소스맵이 `else`에 그 다음 문 위치를 주던 것.
- `--define` 이름이 비어 있지 않은 객체·배열일 때 파일 맨 위의 주석까지 코드로 나열하던 것.
- `% Funcs`가 암시적 생성자, 클래스 필드 이니셜라이저, `static` 블록, 제너레이터·async 함수 본문을 함수로 세어, 전부 테스트한 클래스가 50%로 보이던 것.
- `lcov.info`의 `DA:` 히트 수가 줄 실행 횟수가 아니던 것. 한 번 돈 줄이 14로 보일 수 있었다.

**Bun Shell**

- 안정성 한 건.
- `` $`cmd` ``가 환경 변수 값을 NUL에서 자르던 것. `.env()`와 `.cwd()`는 NUL이 있는 문자열에 `ERR_INVALID_ARG_VALUE`를 던진다.
- `mv -n`이 기존 대상을 덮어쓰던 것.
- `cp -n`이 대상이 있으면 exit 1이던 것.

### 2.12 bun install 수정 전체

"various stability" 묶음: `bun install`, `bun update`, `bun outdated`, `bun run`.

**설치**

- hoisted에서 `package.json`에서 뺀 의존성과, 그것만 의존하던 패키지가 `node_modules`에 남던 것.
- isolated에서 `package.json`에서 수동 삭제했거나, 워크스페이스 안에서 `bun remove`했거나, 다른 패키지가 아직 의존하는데도 `node_modules`와 `.bin` 링크가 남던 것.
- hoisted와 isolated를 오가면 두 레이아웃이 섞이고 `.old_modules-*` 사본이 남던 것.
- 설치가 중간에 죽으면 반쯤 쓴 패키지를 이후 설치가 설치된 것으로 보던 것.
- hoisted에서 프로젝트 밖의 `file:../plugin`이 자기 의존성을 로드하지 못하고, Windows에서는 `EPERM`이던 것.
- hoisted에서 `file:` 폴더와 로컬 tarball이 매 `bun install`마다 다시 설치되던 것.
- 락파일 없이 `--production`이, 없는 폴더를 가리키는 `workspace:`·`link:`·`file:` devDependency(모노레포 중 패키지 하나만 담긴 Docker 이미지)에서 실패하던 것.
- 최신인데 읽기 전용으로 마운트된 `node_modules`에서 `Failed to link: EEXIST`이던 것.
- `--dry-run`이 라이프사이클 스크립트를 실행하고, `bunfig.toml`의 `dryRun = true`가 무시되던 것.
- `--dry-run`이 의존성 간선마다 한 줄을 찍고 피어를 건너뛰며 플랫폼을 무시하던 것을, `node_modules`에 추가될 패키지를 한 번씩 나열하게 고쳤다.
- `--analyze`와 `bun add --analyze`가 `lodash/debounce`처럼 서브패스로만 import된 패키지를 건너뛰던 것.
- isolated에서 optional 의존성 tarball을 받지 못하면 설치가 실패하던 것을, 건너뛰게 고쳤다.
- `bun install`, `bun link`, `bun update -i`가 `Failed to install N packages`를 찍고도 exit 0이던 것.
- 상대 `--cwd`를 `bun update`, `bun link`, `bun unlink`, `bun why`가 두 번 적용해 `ENOENT`이던 것.
- 캐시를 공유하는 설치 둘, 또는 tarball 추출 실패가 `$TMPDIR`에 추출 디렉터리를 남겨 오래 도는 CI 디스크를 채우던 것.
- NFS에서 캐시를 공유하는 설치가 서로의 엔트리를 지우고 `ENOENT`이던 것.
- `NODE_ENV=development` 또는 `test`일 때 `bun run`이 읽는 `.env` 대신 `.env.production`을 읽던 것.
- `bun --bun run`이 공유 머신의 첫 사용자에게만 동작하던 것.
- Alpine(musl)에서 `Bun.which()`가 실행 비트가 없는 파일을 반환하던 것.

**버전 resolve**

- `1.0.0 || ^2.0.0`이 `1.0.0`만으로 파싱되던 것. 정확한 버전으로 시작하는 범위가 그 버전만으로 읽혔다.
- `latest` dist-tag가 없거나 미출판 버전을 가리키면 `bun add`, `bun install`, `bun update --latest`가 실패하던 것을, 가장 높은 릴리스로 폴백하게 고쳤다.
- `pkg@1beta`처럼 숫자로 시작하는 dist-tag가 버전 범위로 파싱되던 것.
- 자동 설치된 피어가 의존 패키지 하나가 허용하는 최신만 받던 것을, 모두가 받는 최신으로 고쳤다.
- `bun` 피어가 npm의 `bun` 패키지(80–170 MB)를 받던 것.
- 메타데이터를 캐시한 뒤 출판된 버전을 최대 5분 동안 설치하지 못하던 것.
- 모노레포 락파일이 있을 때, 다른 워크스페이스가 `npm:` 별칭으로 쓰는 이름의 의존성을 추가하면 `GET /1.0.0no-deps - 404`처럼 이름이 깨지던 것.
- 워크스페이스 `package.json`을 고치면 락파일에 이미 resolve된 GitHub·tarball·git 의존성을 다시 받던 것.
- `package.json`에 `name`이 없는 `file:`·tarball·git 패키지의 `bun.lock` 엔트리가 깨지던 것을, 출처로 이름 붙이게 고쳤다.
- `pkg@>=5.0.0-alpha.0 <8` 같은 프리릴리스 override가 `^4` 의존성까지 바꾸던 것.
- `"foo@>=2.0.0": "1.2.0"` 같은 override가 금지하는 버전을 `bun add foo`와 `bun update --latest`가 설치하던 것.
- `Bun.semver.satisfies()`가 `""`, `"1.2.3.4"`, `"1.2.3 junk"`에 true, `1.0.0+build-1` 대 `^1.0.0`에 false이던 것.
- `^2+x`의 빌드 메타데이터를 두 번째 범위로 파싱해 다른 메이저를 허용하던 것. `satisfies()`와 install 모두.
- `Bun.semver.order("2+1", "2.0.0")`가 throw하던 것.
- `>=0.5 0`이 교집합이 아니라 두 대안으로 파싱되고, `<x`와 `>x`가 모든 버전에 맞던 것.

**hoisted·isolated 링커**

- hoisted가 피어 범위 밖의 피어 옆에 패키지를 둘 수 있던 것.
- hoisted에서 `--filter`, `--production`, `--omit`, `--os`, `--cpu`가 배치를 바꿔, 플래그를 바꾸면 워크스페이스가 틀린 버전을 로드할 수 있던 것. 배치는 `bun.lock`만으로 결정된다.
- `bundledDependencies`가 있는 패키지 아래에 중첩된 의존성이, 요청한 버전 대신 번들된 사본을 로드할 수 있던 것.
- `bun.lock`이 번들로 표시하지 않으면 `bun prune`이 `aws-cdk-lib` 같은 패키지의 번들 의존성을 지우던 것.
- `~/.bunfig.toml`에 `linker = "isolated"`이면 `bun add -g`가 글로벌 bin에 바이너리를 링크하지 않던 것.
- isolated에서 서로 피어인 패키지를 워크스페이스나 의존성이 다르게 끌어오면 두 번 설치하던 것.
- isolated와 `npm:` 별칭이 패키지 두 번째 사본을 설치할 때 `node_modules/.bun/node_modules` 링크가 설치마다 다른 버전을 가리킬 수 있던 것.
- isolated가 심볼릭 링크 `node_modules`를 실제 폴더로 바꾸던 것. 두 링커 모두 링크를 통해 설치하고, 정리가 링크 뒤를 지우지 않는다.
- macOS·Linux isolated에서 워크스페이스 폴더나 부모가 심볼릭 링크면 의존성 링크가 끊기던 것.
- isolated가 `file:` 폴더 안의 심볼릭 링크를 조용히 버리던 것. 두 링커 모두 폴더 안을 가리키는 링크는 유지하고, 다른 프로젝트 파일로 가는 링크는 일반 파일로 복사하며, 나머지는 경고와 함께 건너뛴다.
- `globalStore = true`에서 TypeScript가 공유 패키지 안에서 프로젝트의 `@types/*`를 찾지 못하던 것.
- `BUN_INSTALL_GLOBAL_STORE=false`(`no`, `off`, 빈 값 포함)가 글로벌 스토어를 **켜던** 것.
- 이름이 바뀌거나 제거된 워크스페이스의 심볼릭 링크가 `node_modules`에 남던 것.
- hoisted에서 같은 이름·버전의 레지스트리 패키지가 이미 있으면 새로 추가한 워크스페이스를 링크하지 않던 것.
- Alpine에서 glibc와 musl 바이너리를 같이 담은 패키지(`@anthropic-ai/claude-code` 등)의 명령이 glibc 바이너리에 링크될 수 있던 것.
- `bin` 객체의 값 하나가 문자열이 아니면 바이너리 전부가 링크되지 않던 것.
- 같은 바이너리를 여러 패키지가 선언하면 `.bin`에 들어가는 쪽이 임의이던 것을, 직접 의존성을 우선하게 고쳤다.
- `prepare`에서 빌드되는 워크스페이스 CLI처럼 설치 스크립트가 만드는 바이너리가 다음 `bun install` 때까지 `.bin`에 안 들어가던 것.
- 심볼릭 링크를 지원하지 않는 파일 시스템에서 설치가 실패하던 것을, 한 번 경고하고 `.bin` 링크를 건너뛰게 고쳤다.

**락파일과 `--frozen-lockfile`**

- 어느 레지스트리 응답이 먼저 도착하는지에 따라 새 `bun install`의 `bun.lock`이 달라지던 것을, 결정적 순서로 resolve하게 고쳤다.
- 워크스페이스에 라이프사이클 스크립트와 `latest` 의존성이 있는 변경 없는 모노레포에서, 그 의존성의 새 버전이 출판되면 `bun ci`가 실패하던 것.
- `bun ci`가 락파일에 이미 핀된 버전에 `minimumReleaseAge`를 적용하고, `catalog:`처럼 `package.json` 표기가 다르면 실패하던 것.
- 나쁜 머지 뒤 `package.json` 범위 밖에 잠긴 직접 의존성이 그래도 설치되고 `--frozen-lockfile`을 통과하던 것.
- override가 금지하는 잠긴 버전을 유지하던 것을 다시 resolve하게 고쳤다. `--frozen-lockfile`은 설명을 내고 실패한다.
- 한 패키지가 번들한 패키지를 다른 패키지가 optional 피어로 두면, Bun이 읽을 수 없는 `bun.lock`(`Failed to resolve prod dependency`)을 쓸 수 있던 것.
- `bun.lockb`가 파일 자체가 아니라 그 파일이 있는 디렉터리의 락파일을 출력해, git `textconv`(임시 사본을 넘김)가 깨지던 것.
- `bun pm migrate`가 `trustedDependencies`를 락파일에 안 넣어 `bun pm untrusted`가 신뢰된 패키지를 차단 목록에 올리던 것.
- GitHub 의존성을 핀한 `yarn.lock`·`pnpm-lock.yaml`이 첫 설치에 실패하고 두 번째에 핀을 잃던 것을, pnpm `type: git` resolution을 포함해 핀된 커밋을 설치하게 고쳤다.
- Yarn v1 이전에 `link:`·`./dir`, 레지스트리 패키지가 워크스페이스에 의존하는 모노레포에서 "failed to resolve"이던 것.
- Yarn v1 이전이 tarball·hosted-git 엔트리를 같은 이름·버전의 레지스트리 패키지와 합쳐, 포크가 출판본으로 바뀌던 것.
- npm 6 `package-lock.json`처럼 이전할 수 없는 락파일이 옆의 `yarn.lock`·`pnpm-lock.yaml` 이전을 막던 것을, 경고 후 다음 파일을 시도하게 고쳤다.
- `integrity` 없는 다른 호스트의 `package-lock.json` 엔트리 하나가 락파일 전체를 무시하게 하던 것을, 그 엔트리는 버전을 유지하고 설정된 레지스트리에서 integrity를 받으며 경고를 내게 고쳤다.

**워크스페이스와 카탈로그**

- `name` 없는 워크스페이스 `package.json`이 설치 전체를 실패시키던 것을, 건너뛰게 고쳤다.
- 출판되지 않은 형제 워크스페이스의 `latest`에 의존하면 404이던 것을, 워크스페이스 링크로 고쳤다.
- 루트가 같은 이름의 레지스트리 패키지에 의존하면 워크스페이스가 설치에서 빠지던 것을, 락파일 엔트리와 의존성을 유지하게 고쳤다.
- 워크스페이스 안의 `bun add`가, 그 이름이 형제 워크스페이스일 때도 레지스트리에서 설치하던 것을 `workspace:*` 링크로 고쳤다.
- `bun add alias@npm:`가 `"alias": "workspace:*"`를 써서 이후 설치가 전부 거부하던 것.
- `workspace:`·`catalog:` 의존성이 있는 워크스페이스에서 `bun link`가 `Workspace dependency "bar" not found` 또는 `is not in the catalog`이던 것.
- `!./pkg`, `!pkg/` 형태의 부정 워크스페이스 항목이 무시되고, `bun run --filter`와 `--workspaces`도 부정 항목을 적용하지 않던 것.
- 워크스페이스 glob이 심볼릭 링크 디렉터리를 건너뛰던 것.
- `bun update`가 `workspace:^`를 `workspace:*`처럼 비레지스트리 `package.json` 엔트리를 다시 쓰던 것.
- `bun run --filter deploy`가 `predeploy` 실패 뒤에도 `deploy`와 `postdeploy`를 실행하던 것을, `--filter` 없는 `bun run`처럼 건너뛰게 고쳤다.

**레지스트리, `.npmrc`, `bunfig.toml`**

- 경로가 있고 슬래시로 끝나지 않는 레지스트리 URL(`https://host/npm/repo`)이 마지막 경로 조각을 잃어 모든 요청이 404이던 것.
- `.npmrc` 자격 증명을 npm과 같이 매칭한다. `//host/` 엔트리는 `--registry`나 환경 변수로 정한 레지스트리를 포함해 그 아래 모든 경로에 적용된다.
- `cache.dir`, `globalDir`, `globalBinDir`, `cafile`의 `~`가 글자 그대로 `~`라는 디렉터리를 만들던 것.
- `bunfig.toml`·`.npmrc`의 상대 `cafile`, `cache`, `globalDir`, `globalBinDir`를 그 파일 기준으로 resolve한다. 상대 `cafile`은 프로젝트 루트에서만 동작했다.
- 상대 `--config`, `--cache-dir`, `--cafile`를 프로젝트 루트가 아니라 cwd 기준으로 resolve한다.
- `-g` 명령이 `--config`와 `~/.bunfig.toml`의 `globalDir`을 무시하던 것.
- `bun publish`와 `bun pm whoami`가 `http_proxy`를 무시하고, 그 둘과 `bun audit`이 `NODE_TLS_REJECT_UNAUTHORIZED=0`을 무시하던 것.
- 리다이렉트된 레지스트리 요청이 새 URL의 `NO_PROXY`를 무시하던 것을, `fetch()`처럼 리다이렉트마다 그 URL로 프록시를 고르게 고쳤다.
- 레지스트리 URL에 포함된 자격 증명을 퍼센트 인코딩된 채로 보내 `p%40ss`가 `p@ss`로 나가지 않던 것.
- `BUN_CONFIG_MAX_HTTP_REQUESTS`가 무시되던 것.

**tarball, 캐시, git**

- `--force`와 같은 경로·URL을 다시 추가해도 tarball 의존성의 옛 내용이 남고, `bun update`가 `bun.lock`의 옛 해시를 남기던 것.
- `file:`·URL tarball을 경로나 URL로만 캐시해서, 같은 경로의 다른 파일(다른 프로젝트·브랜치)이 서로의 패키지를 받던 것.
- 호스트가 같고 포트·경로·프로토콜만 다른 레지스트리 둘이 캐시 엔트리를 공유하던 것.
- 2 MB 이상의 비압축 `.tar`, `Content-Encoding: gzip`으로 제공된 그 크기의 `.tgz`가 설치에 실패하던 것.
- `Bun.Archive`의 `extract(dir, { glob })`와 `files()`가 잘리거나 손상된 아카이브에서 그때까지 읽은 엔트리로 resolve하던 것을, `extract(dir)`처럼 reject하게 고쳤다.
- git 의존성이 Git 2.24 이상을 요구한다.
- 캐시된 git 의존성이 캐시 이후의 태그와 브랜치를 안 봐서, 새 태그로 올리면 `no commit matching`이고 `bun update`가 옛 커밋에 남던 것.
- `git+ssh://git@host:2222/...`가 ssh 폴백 때 포트를 잃던 것.
- ssh URL의 https 시도가 "not found"를 반환하면 ssh로 폴백하지 않던 것.
- GitHub가 아닌 호스트의 `bun add name@git+ssh://host/repo.git`가 `unrecognised dependency format`이던 것.
- `deploy@host:org/repo.git`가 `git@deploy@host`로 클론되던 것.
- `gitlab:`, `bitbucket:`, `gist:`, `sourcehut:`가 깨끗한 머신의 `bun.lock`에서 설치에 실패하던 것을 `git+ssh://git@gitlab.com/user/repo#커밋`으로 적게 고쳤다. 기존 엔트리도 설치된다.
- 클론할 수 없는 optional git 의존성이 설치를 실패시키던 것을, 경고와 함께 건너뛰게 고쳤다.
- git 훅에서 실행한 `bun install`·`bun create`가 `GIT_DIR` 등을 git에 넘겨 훅의 저장소를 대상으로 삼던 것.
- `~/.gitconfig` 밖(`~/.config/git/config`, include)에 있는 `core.sshCommand`·`core.askPass`를 git 의존성에서 덮어쓰던 것.
- `submodule.recurse = true`가 서브모듈이 있는 git 의존성을 깨던 것.
- 낡은 락 파일이나 손상된 ref 때문에 git이 쓸 수 없는 캐시 클론이 모든 설치를 실패시키던 것을, 다시 클론하게 고쳤다.

**라이프사이클, trust, add/remove/update, pm, publish, patch, bunx, create, 자동 설치, Windows**

- isolated에서 설치 뒤에 `trustedDependencies`에 추가한 패키지의 스크립트가 안 돌던 것.
- `npm:` 별칭으로 설치된 패키지를 일관되게 신뢰하지 못하던 것을, `package.json`·`--trust`·`bun pm trust`·`bun.lock`에서 **실제 이름**으로 신뢰하게 고쳤다.
- `--concurrent-scripts`와 `concurrentScripts`가 isolated에서 효과가 없고, `bunfig.toml` 값이 플래그보다 우선하던 것.
- `bun pm untrusted`, `bun pm trust`, `bun pm ls --trusted`가 `package.json` 대신 낡은 락파일을 쓰던 것.
- `bun pm pack`, `bun publish`, `bun pm version`의 라이프사이클에 `node_modules/.bin`이 `PATH`에 없어 `"prepack": "tsc"`가 `command not found`이던 것.
- 1.4.0 회귀: 실패한 라이프사이클의 비UTF-8 출력(Latin-1, Shift-JIS 컴파일러 오류)에서 잘못된 바이트가 모두 U+FFFD로 바뀌던 것.
- `bun remove`로 그룹의 마지막 패키지를 지우면 `package.json`의 다른 키 순서가 바뀌던 것.
- 프로젝트 하위 디렉터리의 `bun add ../path`, `bun install -g .`가 경로를 틀린 디렉터리에서 resolve하던 것.
- `package.json`에 다른 출처로 이미 있는 폴더·tarball·git URL을 `bun add`하면 `bun.lock`에 두 번 적히던 것.
- 머신의 첫 `bun add -g`가 글로벌 디렉터리 위의 `~/package.json` 같은 파일을 고치던 것.
- 빈 디렉터리의 `bun add --dry-run`이 `package.json`을 만들던 것.
- `bun add -E react@18`이 `18`을 적던 것을, npm처럼 입력한 범위를 설치된 버전에 핀하게 고쳤다.
- `bun add`, `bun remove`, `bun update`, `bun patch`가 변화가 없어도 `package.json`을 다시 쓰던 것.
- `package.json`을 다시 쓰는 명령이 문자열의 제어 문자를 JSON에 유효하지 않은 `\x1B`, `\v`로 바꾸던 것.
- `package.json`을 고쳤는데 `bun update`가 `(no changes)`를 찍던 것.
- `"canary"`처럼 `latest`보다 앞선 dist-tag를 `bun update --latest`가 다운그레이드하고, `bun update -i`도 더 오래된 `latest`를 제안하던 것.
- `latest`보다 앞선 `catalog` 엔트리(핀, 범위, `canary` 같은 dist-tag)를 `bun update --latest`가 다운그레이드하던 것.
- `bun update --interactive`가 `>=1.0.0 <2`, `1.x`, `^1 || ^2`를 첫 글자+선택 버전으로 다시 쓰던 것을, 선택 버전을 이미 허용하면 그대로 두게 고쳤다.
- `bun update --exact`가 `peerDependencies` 범위를 핀하고, `bun update --latest`가 이미 latest를 허용하는 피어 범위를 좁히던 것.
- `bun outdated a b`가 두 패턴을 **모두** 만족하는 패키지만 보여 주던 것을, 하나라도 만족하면 보여주고 `!pattern`은 제외하게 고쳤다.
- `latest`보다 앞선 의존성을 `bun outdated`가 숨기던 것을, `bun update`가 바꿀 것이면 보여 주게 고쳤다.
- 첫 글로벌 설치 전에 `bun pm bin -g`와 `bun pm ls -g`가 `No package.json was found`이던 것.
- `bun pm ls`가 락파일 패키지를 `node_modules` 라벨 아래 보여 주던 것을, `node_modules`가 있으면 실제 설치된 것을 보여 주게 고쳤다.
- `bun why name@version`이 정확한 버전, 스코프 이름, 워크스페이스에서 아무것도 못 찾던 것.
- `bun why`가 등장할 때마다 의존 패키지를 다시 찍어 큰 트리에서 지수적으로 늘던 것을, 반복은 `*deduped`로 표시하게 고쳤다.
- `.git`이 파일인 worktree·서브모듈에서 `bun pm version`이 커밋과 태그를 안 만들던 것.
- `bun pm version`이 `npm version`과 같은 버전을 계산한다. `1.0.0-rc.1`의 `major`는 `2.0.0`이 아니라 `1.0.0`이고, `v2.0.0`은 `2.0.0`으로 적힌다.
- 없는 dist-tag의 `bun pm view pkg@tag`가 조용히 `latest`를 쓰던 것을, 사용 가능한 태그를 나열하는 오류로 고쳤다.
- `bun pm cache rm`이 캐시 디렉터리 자체를 지워, 심볼릭 링크면 끊기고 부모가 읽기 전용이면 `EACCES`이던 것.
- `~/.bunfig.toml`이 캐시 디렉터리를 정했을 때 `bun pm cache rm`이 아무것도 안 지우고 `Cleared 'bun install' cache`를 찍던 것.
- `workspace:`·`catalog:` 버전이 `bun.lock`에서 나와 낡을 수 있고, 락파일 없으면 pack이 실패하던 것을 `package.json`에서 읽게 고쳤다.
- 카탈로그 엔트리가 `workspace:^` 등인 `catalog:` 의존성을 출판 시 그대로 두던 것을, 워크스페이스 버전으로 바꾸게 고쳤다.
- isolated와 워크스페이스에서 `bun pm pack`·`bun publish`가 `bundledDependencies`를 빼던 것.
- `.npmignore`의 `!pattern`이 제외된 디렉터리 아래 파일을 다시 포함하지 못하던 것.
- 상대 `--destination`, `--filename`, `bun publish ./x.tgz`를 패키지 루트에서 resolve하던 것을 cwd 기준으로 고쳤다.
- `bun publish --provenance`, `publishConfig.provenance`, `NPM_CONFIG_PROVENANCE`를 무시하고 provenance 없이 출판하던 것을, Bun이 provenance 생성을 지원할 때까지 **오류**로 고쳤다.
- 여러 `bin` 이름에 올라 있는 파일을 pack할 때 여러 번 넣던 것.
- 새 디렉터리에 파일을 추가하는 패치가 비루트에서 `EACCES`이던 것.
- 헝크를 줄 번호만으로 적용해 파일이 바뀐 뒤 엉뚱한 곳에 들어가던 것을, `git apply`처럼 문맥으로 맞추게 고쳤다.
- 파일 끝에 개행이 없는 상태에서 줄을 덧붙이는 패치가 마지막 줄을 잃던 것.
- 이미 패치된 패키지의 `bun patch --commit`이 `.bun-tag`와 캐시 경로를 패치에 넣던 것.
- `bun patch`가 번들·중첩 의존성을 빼고 `--commit`이 그것들을 삭제로 기록하던 것.
- 중간에 실패한 `bun patch`가 `node_modules`에 부분 패키지를 남기거나 아무것도 안 남기던 것.
- 패치가 적용되지 않거나 설치가 거부된 `bun patch --commit`이 패키지 폴더, `package.json`, `bun.lock`을 바꿔 둘 수 있던 것을, 모든 검사가 통과하기 전에는 아무것도 수정하지 않게 고쳤다.
- isolated에서 `bun patch`가 `node_modules/<pkg>`를 의존성을 로드할 수 없는 디렉터리로 바꾸던 것.
- 패키지는 설치돼 있지만 캐시에 없을 때(`bun pm cache rm` 이후) `bun patch`와 `--commit`이 `ENOENT`이던 것.
- 패치된 파일이나 캐시 폴더 이름이 비ASCII면 `--commit`이 실패하던 것.
- `Binary files ... differ` 구간이나 버전 없는 `patchedDependencies` 키처럼 적용할 수 없는 패치 부분을 조용히 건너뛰던 것을, 각각 경고를 내게 고쳤다.
- `bunx pkg@latest`가 매번 전부 다시 링크하고, 하루가 넘은 사본을 매번 갱신하던 것.
- 동시에 시작한 `bunx` 여러 개가 공유 설치를 손상하던 것.
- 하루가 넘은 캐시로 `bunx`할 때 레지스트리가 5xx·429·408을 주거나 새 버전 tarball을 받지 못하면 실패하던 것.
- 프로젝트에 그 명령이 없는 다른 버전의 `pkg`가 설치돼 있으면 `bunx pkg@3`가 `could not determine executable to run`이던 것.
- `bunx @scope/pkg`가 그 패키지 명령 대신 같은 이름의 다른 패키지 `.bin`을 실행할 수 있던 것.
- `bun create`가 기존 디렉터리를 지우던 것을, 병합하고 충돌을 나열하며 `--force`일 때만 덮어쓰게 고쳤다.
- `git init`과 첫 커밋이 템플릿 작업·`bun install`과 경합하던 것을, 첫 커밋이 템플릿 그대로이게 고쳤다.
- `bun-create` 작업이 셸 없이 돌고, 의존성 없는 템플릿에서는 아예 안 돌며, 실패가 무시되던 것.
- 템플릿 `package.json`의 들여쓰기가 사라지던 것.
- 자동 설치가 패키지를 받는 동안 `require()`, `import()`, `Bun.resolveSync()` 안에서 타이머와 I/O 콜백이 돌 수 있던 것.
- `pkg@1` 다음 `pkg@2`를 import할 때 메타데이터가 디스크 캐시에 있으면 `Unexpected`이던 것.
- 자동 설치 다운로드 한 번 실패가 프로세스 남은 시간 동안 `fetch()` 동시 요청을 4개로 제한하던 것.
- 자동 설치된 패키지의 피어가 "Cannot find module"이던 것.
- 읽기 전용 컨테이너처럼 캐시나 임시 디렉터리를 쓸 수 없으면 import가 "Cannot find package"를 던진다.
- Windows: `env -S` shebang 명령이 안 돌던 것, 패키지가 다른 드라이브면 `.bunx` 심이 깨지던 것, `bun remove`가 `.bunx`·`.exe` 심을 남기던 것, 드라이브 루트에서 `bun install`이 실패하던 것, exFAT·FAT32의 `EINVAL: Failed to replace old lockfile`, 바이러스 검사가 새 파일을 잡고 있으면 rename이 실패하던 것을 최대 5초 재시도, cwd·템플릿·대상에 비ASCII가 있으면 `bun create`가 "ENOENT: failed to copy file", git 저장소에서 `bun pm version`의 `preversion`·`version`·`postversion`이 빈 환경으로 돌던 것.

### 2.13 SQL 수정 전체와 TypeScript 타입

"various stability" 묶음: `Bun.SQL`, `bun:sqlite`, `node:sqlite`.

**풀**

- `idleTimeout`과 `maxLifetime`이 쿼리 실행 중, reserve 중, `sql.begin()`이 열린 연결을 닫던 것을, 일을 끝낸 뒤에 닫게 고쳤다.
- 연결 일부를 잃은 풀이 하나라도 쓸 수 있으면 새 연결을 안 열어 `max`까지 회복하지 못하던 것.
- 수동 `BEGIN` 뒤 reservation처럼, 트랜잭션이 열린 채 풀에 반환된 연결을 다음 호출자에게 주던 것을, 그 연결을 닫게 고쳤다.
- `sql.close({ timeout: 0 })`가 즉시 닫지 않고 실행 중 쿼리를 기다리던 것.
- `sql.close({ timeout: 2 ** 31 })`가 타이머가 넘쳐 1 ms 뒤에 실행 중 쿼리를 죽이던 것.
- `sql.begin()`과 `sql.reserve()`가 연결을 기다리는 더 오래된 쿼리보다 앞질러 가던 것을 FIFO로 고쳤다.
- `sql.listen()` 연결에서 `onconnect`·`onclose`가 안 불리던 것.
- PostgreSQL·MySQL 소켓에 TCP keepalive 60초. 서버가 사라지면 쿼리가 영원히 기다리지 않고 실패한다.

**트랜잭션**

- `sql.begin(tx => Promise.all(tasks))`에서 한 태스크가 실패한 뒤, 다른 태스크가 `ROLLBACK` 이후에 보낸 문이 autocommit으로 실행돼 행이 남던 것을 reject하게 고쳤다.
- `reserved`나 `tx`에서 만든 쿼리를 `release()`·`COMMIT`·`ROLLBACK` 뒤에 처음 await하면 다른 호출자의 연결에서 돌 수 있던 것을 reject하게 고쳤다.
- 실행 중인 `reserved.begin()` 도중 `reserved.release()`가 연결을 일찍 반환해, 그 트랜잭션의 `COMMIT`이 다음 호출자의 작업을 커밋할 수 있던 것.
- `tx.close({ timeout })`가 쿼리가 시간 안에 끝나면 커밋하던 것을 롤백으로 고쳤다.
- 차가운 풀에서 `sql.begin()` 콜백에 `AsyncLocalStorage` 스토어가 없고, 바쁜 풀에서는 다른 요청의 스토어가 보이던 것을 호출자의 스토어로 고쳤다.
- `sql.begin()`·`tx.savepoint()` 콜백이 반환한 결과가 `count`·`command` 없는 평범한 배열이던 것.
- PostgreSQL·MySQL에서 서버가 커밋하거나 prepare한 트랜잭션의 응답과 종료 오류가 같은 읽기에 도착하면 `sql.begin()`·`sql.beginDistributed()`가 그 트랜잭션을 reject하던 것.

**쿼리와 결과, 연결 옵션**

- Babel·swc의 템플릿 리터럴 loose 모드가 컴파일한 `sql`...`` 호출은 `TypeError`다. 템플릿 리터럴 loose 모드를 끈다.
- PostgreSQL·SQLite에서 `affectedRows`가 항상 `null`이던 것을, 쓴 행 수이고 `SELECT`는 `0`으로 고쳤다. MySQL에서는 쓰기 뒤 `count`가 `0`이었다.
- `WHERE id IN ${sql([])}`가 PostgreSQL·MySQL에서 구문 오류이던 것을, 어떤 행도 안 맞게 고쳤다.
- MySQL·MariaDB에서 `sql("db.table")`이 전체를 식별자 하나로 인용하던 것을, 문서대로 `` `db`.`table` ``로 고쳤다.
- MySQL에서 `ON DUPLICATE KEY UPDATE ${sql({ age: 31 })}`가 절이 소문자이거나 여러 줄이면 구문 오류이던 것.
- `sql instanceof Bun.SQL`이 `TypeError`이던 것.
- TypeScript에서 await한 쿼리 결과에 `count`, `command`, `affectedRows`, `columns`와 나머지 결과 프로퍼티가 있다.
- `new SQL({ filename: "./dev.db" })`에 `adapter`가 없으면 PostgreSQL로 접속을 시도하고, `SQLITE_URL=x.db`가 `postgres://x.db`라는 파일을 열려 하던 것.
- 문서의 `socket` 옵션과 `?socket=`이 효과가 없고, `mysql://user:pass@/db?socket=/path`가 `Invalid URL`이던 것.
- 없는 `path`를 무시하고 TCP로 접속하던 것을 `ERR_POSTGRES_CONNECTION_REFUSED` 또는 `ERR_MYSQL_CONNECTION_REFUSED`로 고쳤다.
- 문서에 PostgreSQL 사용자로 적힌 `PGUSERNAME`과 `USERNAME`이 무시되던 것.
- 데이터베이스 없는 `mariadb://` URL이 `mariadb`라는 데이터베이스를 고르려다 errno 1049이던 것을, 데이터베이스를 고르지 않게 고쳤다.
- SQLite 어댑터에서 `?mode=rw`가 파일을 만들고, `?mode=RO`나 `{ readwrite: false }`가 읽기-쓰기로 열던 것.

**PostgreSQL**

- `NULL` 파라미터 조합마다 서버 문을 새로 prepare하고 닫지 않아 백엔드가 수 GB까지 커지던 것을, 연결마다 최근 문 1,024개만 유지하게 고쳤다.
- `ALTER TABLE`, `DEALLOCATE ALL`, `DISCARD ALL` 뒤 캐시된 문이 `cached plan must not change result type` 같은 오류를 계속 내던 것을, 다시 prepare하게 고쳤다.
- 타입 없는 `sql.array(["a", "b"])`가 `JSON[]`로 캐스팅돼 `text[]`에 JSON 인용 원소가 들어가던 것을, 캐스팅을 넣지 않게 고쳤다.
- `sql.array(values, "TEXT")`·`"INT"`의 `null`이 문자열 `"null"`이나 오류이던 것을 SQL `NULL`로 고쳤다.
- `NULL`이 있거나 차원이 둘 이상인 `int4[]`·`float4[]`를 반환하는 prepared 쿼리가 `ERR_POSTGRES_NULLS_IN_ARRAY_NOT_SUPPORTED_YET` 또는 `ERR_POSTGRES_MULTIDIMENSIONAL_ARRAY_NOT_SUPPORTED_YET`으로 reject되던 것.
- `text`에 묶인 `Date`가 `toString()`, 평범한 객체가 `[object Object]`로 저장되던 것을 ISO 8601과 JSON으로 고쳤다.
- `date`·`time`에 묶인 `Date`가 실패하던 것.
- `prepare: false`에서 `Date`가 `toString()`, `jsonb`에 묶인 객체가 `[object Object]`이던 것.
- `bool`·`int4`·`float8`·`timestamp`에 묶인 배열·객체를 클라이언트에서 강제 변환해 `[]`가 `true`가 되던 것을, 텍스트로 보내고 서버가 검증하게 고쳤다.
- Invalid Date가 PostgreSQL·MySQL에서 1970-01-01로 저장되던 것을, 쿼리를 reject하게 고쳤다.
- 2^51 이상 2^53−1 이하의 정수를 `float8`로 보내 `numeric`이 2^52+1을 `4503599627370500`으로 저장하던 것을 `int8`로 보낸다. Bun은 이것을 문자열로 반환한다.
- 서버가 위치를 안 보내면 `PostgresError.column`과 `.line`이 Bun 소스 위치를 가리키던 것.

**MySQL·MariaDB**

- 같은 연결의 쿼리를 파이프라인하지 않고 하나씩 보내던 v1.2.22 이후 회귀. 지연 30 ms에서 prepared 쿼리 네 개가 124 ms → 31 ms.
- TLS 없이 `caching_sha2_password` 로그인이 비밀번호 20바이트 이상에서 errno 1045. fast auth도 성공하지 않아 평문 TCP는 매번 `allowPublicKeyRetrieval: true`가 필요했다.
- 문서에 있는 `sha256_password`가 모든 로그인에서 errno 1045이던 것.
- nullable 열 K개의 `INSERT` 하나가 서버에 최대 2^K개의 문을 prepare하고 닫지 않던 것을, 연결마다 최근 문 256개만 유지하게 고쳤다.
- 실패한 prepare를 캐시해서 `CREATE TABLE`로 유효해진 뒤에도 쿼리가 실패하던 것.
- 유휴였던 연결의 쿼리가 프로세스를 살려 두지 않아, 쿼리가 나는 중에 exit 0으로 끝날 수 있던 것.
- 파라미터 `toJSON()`이 쿼리를 시작하면 한 연결의 쿼리 둘이 서로의 행으로 resolve될 수 있던 것.
- MariaDB가 모든 객체·배열 파라미터를 errno 1210으로 거부하던 것.
- 1970년 이전 `Date`가 거부되고, prepared 쿼리가 `TIME(n)`의 소수 초를 잃던 것.
- 2^53−1을 넘는 `lastInsertRowid`가 반올림되던 것을 문자열, 또는 `bigint: true`면 `BigInt`로 고쳤다.
- 서버가 `max_connections` 등으로 새 연결을 거부하면 `ERR_MYSQL_UNSUPPORTED_PROTOCOL_VERSION`이던 것을, 서버 오류(errno 1040, "Too many connections")로 고쳤다.

**`Bun.SQL`의 SQLite**

- `select*from t`, `/*c*/select`, `values (...)`처럼 쓴 유효한 쿼리가 `[]`로 resolve되던 것.
- `INSERT ... SELECT`와 `WITH ... INSERT`의 `count`가 0이던 것.
- 첫 문이 행을 반환하는 여러 문 문자열(맨 앞이 `PRAGMA`인 마이그레이션)이 그 문만 실행하던 것.
- 다른 `sql.begin()`이 도는 동안 두 번째 `sql.begin()`이 `cannot start a transaction within a transaction`이던 것을, 기다리게 고쳤다.
- 실패한 `COMMIT`이 트랜잭션을 열어 두어 이후 `sql.begin()`이 전부 실패하던 것.

**`bun:sqlite`**

- `INSERT ... RETURNING`처럼 쓰는 문의 `iterate()`를 끝까지 읽지 않고 프로세스가 끝나면 쓰기가 유실되던 것을 커밋하게 고쳤다. 명시적 `BEGIN`은 여전히 롤백된다.
- `new Database(path, { create: false })`가 있는 파일에서 `SQLITE_MISUSE`, `{}`·`{ readonly: false }`·`{ readwrite: false }`도 같던 것.
- `{ readonly: true, create: true }`가 읽기-쓰기로 열리던 것을 `TypeError`로 고쳤다.
- `db.run("a; b; c")`와 `db.exec()`가 마지막 문을 제외한 런타임 오류를 삼키던 것을, 실패 문에서 throw하고 나머지를 건너뛰게 고쳤다.
- `ALTER TABLE` 뒤 기존 `Statement`가 옛 열 이름이나 틀린 키로 행을 반환하던 것.
- 기본 모드에서 `{ name: 1 }`이 `$name`에 `NULL`을 묶고, `strict: true`에서 `{ $name: 1 }`이 throw하던 것을, 두 형식 모두 두 모드에서 되게 고쳤다.
- `db.prepare(sql, "x")`가 배열이 아닌 바인딩을 무시하던 것.
- `SELECT 1`의 `row["1"]`이 `undefined`이던 것.
- `changes`가 트리거, 외래 키 연쇄, FTS5 섀도 테이블이 쓴 행까지 세던 것을, `node:sqlite`처럼 그 문의 행만 세게 고쳤다.
- `stmt.iterate()`에서 `break`하면 커서가 열려 `DROP TABLE`이 `database table is locked`이던 것.
- `db.transaction(fn)`이, `fn`이 이미 reject된 프로미스를 반환하면(첫 `await` 전에 throw하는 `async` 함수) 커밋하던 것을 롤백으로 고쳤다.
- `stmt.run(new Date())`, 또는 유일한 인자로 `Map`·`Promise`를 주면 `NULL`을 묶던 것을 `TypeError`로 고쳤다.
- 트랜잭션 밖에서 `RETURNING`이 있는 쓰기 도중 워커를 끝내면 FTS 인덱스 없는 행이 커밋될 수 있던 것. `MATCH`가 그 행을 놓친다. `INSERT INTO ft(ft) VALUES('rebuild')`로 인덱스를 고친다.
- `db.query()`가 아무 크기의 SQL 텍스트를 캐시해서, 텍스트가 바뀌는 수 MB 쿼리 루프가 953 MB까지 커지던 것을 피크 92 MB로 고쳤다.
- 문이 네이티브 메모리를 GC에 보고한다. 버린 200파라미터 문 20,000개가 465 MB → 27 MB.
- `stmt.get()`이 전체 결과 대신 첫 행에서 멈춘다. `INSERT`·`UPDATE`·`DELETE … RETURNING`은 변경을 모두 적용하고 커밋한다.
- 열 63개 이상인 행이 셀당 1,665명령 → 310명령.
- 문 80,000개 문자열의 `db.run()` CPU 시간이 5.34 s → 0.11 s.
- 워커가 SQLite malloc 뮤텍스 하나를 공유하지 않는다. 그 결과 `PRAGMA hard_heap_limit`와 `soft_heap_limit`는 받지만 `node:sqlite`처럼 더 이상 강제되지 않는다.

**`node:sqlite`**

- `db.close()`가 모든 `StatementSync`가 GC될 때까지 파일과 `-wal`·`-shm`을 열어 두어 Windows에서 `EBUSY`이던 것.
- `Proxy`(Vue `reactive()`, MobX)나 모듈 네임스페이스를 이름 있는 파라미터로 주면 모든 파라미터에 `NULL`이 묶이던 것.
- `INSERT ... RETURNING`의 `stmt.get()`이, 지연된 외래 키 때문에 커밋이 실패했는데도 행을 반환하던 것을 throw로 고쳤다.
- 5열 행의 `stmt.get()`이 13,458명령 → 4,077명령.

**TypeScript 타입**

- `toHaveBeenCalledOnce()`가 `bun-types`에 없던 것. `bun test`에서는 이미 동작했다.
- `@types/bun`이 `Bun.hash()`를 `number | bigint`로 적었던 것. 항상 `bigint`다.
- `@types/bun`이 `Bun.mmap()` 경로로 `Buffer`·`URL`을 받았던 것. 런타임에서는 둘 다 throw한다.
- `@types/bun`에 `Bun.MD5`, `Bun.SHA256` 등 해시 클래스 인스턴스의 `byteLength`가 없던 것.
- 서브프로세스 `resourceUsage()`의 `cpuTime` 필드를 `number`로 적었던 것. 실제는 `bigint`. `FileSystemRouter`의 `origin`을 `string`으로 적었던 것. `null`일 수 있다.

## 3. 전체 예제 코드 모음

예제 1–4는 `/tmp`가 아니라 아래 내용을 이 머신의 Bun 1.4.4로 실행했다. PostgreSQL이 필요한 예제는 공식 블로그의 형태만 옮기고, 이 문서에서 실행하지 않았다고 표시한다.

### 예제 1. `bun fmt`와 `--check`

```bash
printf 'const x=1\n' > src/messy.ts
bun fmt --check src/messy.ts   # exit 1, "1 file needs formatting"
bun fmt src/messy.ts           # const x = 1;
bun fmt --check src/messy.ts   # exit 0, "1 file is formatted."
```

CI에서는 `bun fmt --check`를 게이트로 두고, pre-commit에서는 `bun fmt --staged`를 둔다. `package.json`에 `fmt` 스크립트가 있으면 내장 포맷터는 `bun fmt --no-script`다.

### 예제 2. Glob extglob과 중괄호 범위

```ts
const tests = new Bun.Glob("**/!(*.test).ts");
tests.match("src/cart.ts"); // true
tests.match("src/cart.test.ts"); // false

new Bun.Glob("src/@(app|lib)/**/*.ts").match("src/app/a/b.ts"); // true
new Bun.Glob("shard-{1..3}.json").match("shard-2.json"); // true
new Bun.Glob("shard-{1..3}.json").match("shard-9.json"); // false
new Bun.Glob("app/(marketing)/**").match("app/(marketing)/page.ts"); // true, '('는 리터럴
```

`*(1).txt`를 파일 이름 안의 괄호에 맞추려고 쓰던 패턴은 `*[(]1).txt`로 바꿔야 한다.

### 예제 3. `bun:sqlite` 함수, 집계, 삽입 훅

```ts
import { Database } from "bun:sqlite";

const db = new Database(":memory:");
db.run("CREATE TABLE cats (name TEXT)");
db.run("CREATE TABLE expenses (dollars INTEGER)");

db.function("add2", (a: number, b: number) => a + b);
db.query("SELECT add2(12, 4) AS sum").get();

db.aggregate("add_all", {
  start: 0,
  step: (total: number, value: number) => total + value,
});
db.run("INSERT INTO expenses (dollars) VALUES (3), (4)");
db.query("SELECT add_all(dollars) AS total FROM expenses").get();

const inserted: string[] = [];
db.onInsert = (_database, tableName: string, rowid: number) => {
  inserted.push(`${tableName}:${rowid}`);
};
db.run("INSERT INTO cats (name) VALUES ('Salem'), ('Keanu')");

const stmt = db.query("SELECT 1 AS n");
stmt.reader; // true
stmt.readonly; // true
db[Symbol.for("sqlite-type")]; // "bun:sqlite"
```

### 예제 4. 의미 변화와 거부

```ts
let unary = false;
try {
  eval("+1n * 2n");
} catch (error) {
  unary = error instanceof TypeError;
}

let hashRejected = false;
try {
  Bun.hash(null as unknown as string);
} catch (error) {
  hashRejected = error instanceof TypeError;
}

let json5Rejected = false;
try {
  Bun.JSON5.parse("1\0 2");
} catch (error) {
  json5Rejected = error instanceof SyntaxError;
}
```

세 값 모두 1.4.4에서 true다. `+1n * 2n`은 1.4.3에서 `2n`이었으므로, 단항 플러스와 BigInt 곱을 섞어 쓰던 코드는 업그레이드 후 `TypeError`다.

### 예제 5. 공식 예제, 이 문서에서 실행하지 않음

Yarn Berry 이전, `bun pm fetch`, `cache pack`, `packageExtensions`, `link:`, `minimumReleaseAge`, `bun publish --recursive`는 2.3의 코드 블록이 공식 형태다.

PostgreSQL `cancel()`, `COPY` 스트림, `SQL.camel`, `sql.json()`, `channelBinding`은 2.4의 코드 블록이 공식 형태다. 로컬에 그 서버를 띄우지 않았다.

`ws`의 `createWebSocketStream`, `Bun.serve`의 `pause`/`resume`, `proxy.tls`는 2.5의 코드 블록이 공식 형태다.

## 4. 실무에서 바로 쓰는 조합

포맷, 타입, 설치를 한 파이프라인으로 묶는 형태다. `bun fmt`는 1.4.4에서 새로 쓸 수 있고, `bun check`는 1.4.3부터 있다.

```bash
# 커밋 전
bun fmt --staged

# CI
bun fmt --check
bun check --no-script
bun install --frozen-lockfile
```

레지스트리가 잠깐 죽는 CI라면 기본 백오프(최대 약 1.5초)로 부족할 수 있다. 그때만 `BUN_CONFIG_HTTP_RETRY_BACKOFF`를 올린다.

```bash
BUN_CONFIG_HTTP_RETRY_BACKOFF=250 bun install --frozen-lockfile
```

Docker에서 다운로드 레이어를 락파일에 묶으려면:

```dockerfile
COPY package.json bun.lock ./
RUN bun pm fetch
COPY . .
RUN bun install --offline --frozen-lockfile
```

컴파일된 실행 파일에 문자열 코드 생성을 남기지 않으려면 `--disallow-code-generation-from-strings=strict`를 빌드에 넣는다. 1.4.4부터는 디스크에 있는 플러그인 JS도 실행 파일 안의 코드로 치지 않는다.

## 6. 설치, 업그레이드 및 마이그레이션 권고사항

### 1) 업그레이드

```bash
bun upgrade
```

신규 설치:

```bash
curl -fsSL https://bun.sh/install | bash
powershell -c "irm bun.sh/install.ps1|iex"
scoop install bun
brew install bun
docker run --rm --init --ulimit memlock=-1:-1 oven/bun
npm install -g bun
```

블로그의 curl URL은 `https://bun.sh/install`이다. 특정 바이너리만 받으려면 GitHub 릴리스 `bun-v1.4.4`의 `bun-darwin-aarch64.zip`을 쓴다. 이 문서의 `bun --revision`은 `1.4.4+38afee6c8`이다.

### 2) 업그레이드 전에 손볼 코드

- **`*(1).txt`, `!(g)/a.ts`, `{1..3}` glob.** 1.4.4에서 의미가 extglob·범위로 바뀐다. 리터럴 괄호는 `*[(]1).txt`처럼 이스케이프한다. `app/(marketing)`의 맨 `(`는 그대로다. Bun Shell 인용 문자열은 영향이 없다.
- **`+1n * 2n`.** `TypeError`다. 1.4.3에서는 `2n`이었다.
- **`ws` 클라이언트.** `'error'` 리스너가 없으면 uncaught다. `'close'`의 reason은 `Buffer`다. 코드 없는 `close()`는 1005다. 프로세스가 `close()` 뒤 한 라운드트립을 더 기다린다. 30초는 `BUN_CONFIG_WS_CLOSE_TIMEOUT`, 즉시 끊으려면 `terminate()`.
- **`ws` 서버.** 블로그는 `ws` 서버가 `Bun.serve`의 기본값(idle 120초, 104초 ping, 16 MiB 제한)을 더 이상 물려받지 않는다고 적는다. `Bun.serve` 자신의 WebSocket이 그 기본값을 유지하는지는 이 릴리스 노트에 별도 문장이 없다. 기본 `maxPayload`는 100 MiB다.
- **`Bun.hash(null)` / `undefined` / 파일 핸들.** `TypeError`다. 빈 문자열 해시에 의존하던 코드가 드러난다.
- **`=strict`로 컴파일한 실행 파일.** 디스크의 JS·TS, `contents` 플러그인, 매크로, `BUN_OPTIONS`의 `--preload`가 막힌다. JSON `data:` URL은 막히지 않는다.
- **mTLS.** `ca`만으로는 클라이언트 인증서를 요청하지 않는다. `requestCert: true`가 필요하다.
- **`PASSWORD` 환경 변수.** `Bun.SQL`이 더 이상 읽지 않는다. `PGPASSWORD` 또는 `MYSQL_PASSWORD`를 쓴다.
- **프리릴리스 `bun publish`.** `--tag` 또는 `publishConfig.tag` 없이 `latest`로 올라가지 않는다. `--provenance`는 아직 생성하지 못하고 오류다.
- **알 수 없는 install 플래그.** 오타가 오류다. `--network-timeout 100000`처럼 대응이 없는 플래그는 값까지 무시된다. `--save-dev`는 이제 정말로 devDependencies다.
- **`bun test --coverage`.** 건너뛴 줄과 `await` 이후 미재개 구간을 더 이상 커버된 것으로 세지 않는다. `% Lines`가 내려갈 수 있다. `% Funcs`도 암시적 생성자를 함수로 세지 않는다.
- **피어와 락파일.** 이미 핀된 버전은 자동으로 다시 고르지 않는다. Express 5가 Remix에 붙어 있는 락파일은 패키지를 지웠다 다시 추가해야 1.4.4 규칙이 적용된다.
- **Brotli를 푸는 서비스.** 1.4.3 이하는 CVE-2026-111497 범위다. 1.4.4 이상으로 올린다. 응답을 Brotli로 압축만 하는 경로는 디코더 버그의 입구가 아니다.

### 3) 올려도 되는 것

- Prettier 스크립트를 `bun fmt`로 바꿀 때 `bun fmt --check`로 트리가 깨끗한지 먼저 본다. 지원하지 않는 플러그인이 있으면 exit 2다. `bun fmt --doctor`가 지울 수 있는 패키지를 알려 준다.
- `tsc`와 나란히 쓰던 `bun check`는 1.4.4에서 대형 프로젝트와 `bun check -b`가 빨라진다. Bun 자신의 `src/js`처럼 작아진 케이스도 공식 표에 있다.
- Yarn Berry에서 넘어올 때 `exec:` 의존성이나 `.yarnrc.yml`에만 있는 레지스트리가 있으면 이전이 폴백된다. 로그의 이유를 먼저 본다.
- Alpine 이미지는 `libc` 필드를 보므로 musl 빌드만 받는다. 둘 다 필요하면 `--libc '*'`.
- SQLite에 SQL 함수가 필요하면 `db.function` / `db.aggregate`를 쓰고, 행 단위 감사가 필요하면 `onInsert`를 쓴다.

## 7. 사실 검토 및 출처

- **공식과 실측.** `bun check`, `Bun.SQL` 명령 수, `ws` 테스트, JSC, Headers, 바디 스트림의 배율은 블로그 수치이고 기준은 v1.4.3이다. `bun fmt`의 배율은 v1.4.3이 아니라 Prettier 3.9.9·3.9.10과 oxfmt 0.72·0.74.0 대비다. 기계는 블로그가 항목마다 적은 대로 Xeon, Linux x64, 또는 M4 Max다. 2.1의 `const x = 1` 포맷 로그, 2.4·2.6에서 “이 문서에서 확인”이라고 적은 결과, 5장 전체만 이 머신의 macOS arm64 Bun 1.4.4 실행이다. 그 절대 시간을 공식 배율과 섞지 않는다.
- **릴리즈 일자와 리비전.** 블로그는 2026년 10월 22일, 작성자는 Jarred Sumner다. 이 머신의 `bun --revision`은 `1.4.4+38afee6c8`이고, 런타임이 보고한 전체 리비전은 `38afee6c84fcf48c0edb2466aa4b27d287a59c30`이다.
- **이슈 133개와 PR 597개.** 블로그 소제목은 install 이슈 133개를 닫았다고 하고, 본문은 열린 패키지 매니저 PR 597개 중 464개 전부·40개 부분 반영이라고 한다. 두 숫자는 다른 단위라 이 문서도 합치지 않는다.
- **Handlebars 표의 빈 칸.** 블로그 HTML을 텍스트로 받는 과정에서 두 행의 입력 코드가 비었다. Prettier가 공백을 지우거나 주석이 다음 줄을 삼키고 `bun fmt`는 유지한다는 문장만 남겼다.
- **Brotli CVE.** 1.4.4 블로그 Security 절은 Brotli를 영향 표면에 넣지만 CVE-2026-111497이라는 문자열은 없다. 수정 버전이라는 연결은 Bun 이슈 `#46352`, 메인테이너의 당일 릴리스 답변, 그리고 이 저장소의 Brotli 보고서에 있다.
- **재현하지 않은 항목.** `bun fmt`의 Prettier·oxfmt 대형 비교, `bun check` 대형 프로젝트, install 퍼즈와 1,000패키지 링크, PostgreSQL·MySQL CPU 명령 수, `COPY` 255 MiB/s, `ws` 테스트 271개, JSC 마이크로벤치의 공식 배율, Windows·Alpine 전용 수정.
