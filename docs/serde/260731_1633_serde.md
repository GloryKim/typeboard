## 1. Serde란

### 개념

Serde = **Ser**ialize + **De**serialize.

역할 분리:

| 층 | 역할 | 예 |
|---|---|---|
| **데이터 모델** | Rust 타입 + `Serialize`/`Deserialize` | `struct User { ... }` |
| **데이터 포맷** | 바이트/텍스트로 읽고 쓰기 | `serde_json`, `toml`, `bincode` |
| **앱** | HTTP·파일·DB·설정 | Axum `Json`, reqwest `.json()` |

Serde 자체는 JSON을 “모른다”.  
`serde`는 트레이트와 derive를 주고, `serde_json`이 JSON 문법을 구현한다.

```text
Rust 값  ──Serialize──▶  포맷 바이트 (JSON 등)
Rust 값  ◀─Deserialize─  포맷 바이트
```

한 줄:

> Serde = “Rust 타입 ↔ 임의의 직렬화 포맷”을 잇는 공통 계약

### 체크포인트

- [ ] `serde`와 `serde_json` 역할을 한 문장씩 구분
- [ ] Axum `Json<T>`가 결국 Deserialize/Serialize를 쓴다는 점 연결

## 2. 프로젝트 준비

### Cargo.toml

```toml
[package]
name = "serde-lab"
version = "0.1.0"
edition = "2021"

[dependencies]
serde = { version = "1", features = ["derive"] }
serde_json = "1"

# 자주 같이 쓰는 것들 (선택)
# chrono = { version = "0.4", features = ["serde"] }
# uuid = { version = "1", features = ["serde", "v4"] }
# serde_with = "3"
```

| crate / feature | 용도 |
|---|---|
| `serde` | 트레이트 |
| `features = ["derive"]` | `#[derive(Serialize, Deserialize)]` |
| `serde` 기본 `std`/`alloc` | 대부분 환경 기본 ON. `no_std`는 feature 조합 필요 |
| `serde` `rc` | `Rc`/`Arc` 직렬화 (참조 공유는 복원되지 않음 — 값 복제) |
| `serde_json` | JSON |
| `chrono`/`uuid` + `serde` feature | 시간·UUID를 바로 직렬화 |

수동으로 `impl Serialize`만 할 거면 `derive` feature 없이도 가능하지만, 실무는 거의 derive를 켠다.

## 3. Serialize / Deserialize 첫걸음

### 개념

```rust
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize, Deserialize, PartialEq)]
struct User {
    id: u64,
    name: String,
    active: bool,
}
```

| 트레이트 | 방향 |
|---|---|
| `Serialize` | Rust → 포맷 |
| `Deserialize` | 포맷 → Rust |

수신만: `Deserialize`  
응답·저장만: `Serialize`  
왕복: 둘 다

### 설명

derive가 생성하는 코드는 대략:

- 구조체 필드 이름(또는 rename된 이름)을 키로
- 필드 타입의 `Serialize`/`Deserialize`를 재귀 호출

필드 타입이 Serde를 구현하지 않으면 컴파일 에러가 난다.

### 체크포인트

- [ ] `User`에 Serialize+Deserialize derive
- [ ] `HashMap` 같은 표준 타입이 이미 구현돼 있음을 확인

## 4. serde_json 입출력

### to_string / from_str

```rust
use serde::{Deserialize, Serialize};
use serde_json::{self, Result};

#[derive(Debug, Serialize, Deserialize, PartialEq)]
struct User {
    id: u64,
    name: String,
}

fn roundtrip() -> Result<()> {
    let u = User {
        id: 1,
        name: "kim".into(),
    };

    let json = serde_json::to_string(&u)?;
    // {"id":1,"name":"kim"}

    let back: User = serde_json::from_str(&json)?;
    assert_eq!(u, back);
    Ok(())
}
```

### 자주 쓰는 API

| 함수 | 역할 |
|---|---|
| `to_string` / `to_vec` / `to_writer` | 직렬화 |
| `to_string_pretty` | 들여쓰기 JSON |
| `from_str` / `from_slice` / `from_reader` | 역직렬화 |
| `json!` 매크로 | 리터럴로 `Value` 만들기 |

```rust
use serde_json::{json, Value};

fn value_demo() {
    let v: Value = json!({
        "id": 1,
        "tags": ["a", "b"],
        "meta": { "ok": true }
    });
    assert_eq!(v["id"], 1);
    assert_eq!(v["tags"][0], "a");
}
```

### 숫자·null

```rust
#[derive(Serialize, Deserialize, Debug)]
struct Sample {
    n: i64,
    maybe: Option<String>,
}

fn null_and_number() {
    let s: Sample = serde_json::from_str(r#"{"n":10,"maybe":null}"#).unwrap();
    assert!(s.maybe.is_none());

    // 필드 자체가 없으면? Option 이면 None (default 없이도)
    let s2: Sample = serde_json::from_str(r#"{"n":10}"#).unwrap();
    assert!(s2.maybe.is_none());
}
```

- [ ] roundtrip 성공
- [ ] `Option` + 없는 키 / `null` 둘 다 None인지 확인

## 5. 컨테이너 attribute

구조체·enum **선언**에 붙는다.

### 자주 쓰는 것

```rust
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug)]
#[serde(rename = "user_account")]           // 타입 이름(일부 포맷)
#[serde(rename_all = "camelCase")]          // 필드/배리언트 이름 규칙
#[serde(deny_unknown_fields)]               // 모르는 키면 에러
struct Account {
    user_id: u64,
    display_name: String,
}
```

| attribute | 효과 |
|---|---|
| `rename = "..."` | 컨테이너 이름 (JSON 구조체에는 보통 안 보임. enum·일부 바이너리 포맷에서 쓰임) |
| `rename_all = "..."` | **구조체 필드** 또는 **enum 배리언트** 일괄 케이스 |
| `rename_all_fields = "..."` | enum의 **구조체 배리언트 안 필드**만 일괄 케이스 |
| `deny_unknown_fields` | 여분 키 거부 (JSON 같은 self-describing 포맷) |
| `default` / `default = "path"` | 없는 필드를 `Default` 또는 함수 결과로 |
| `bound = "..."` | 생성 impl의 where 절 **교체**(추론 bound를 덮어씀) |
| `remote = "..."` | 외부 타입용 원격 derive |
| `tag` / `content` / `untagged` | enum 표현 방식 (10절). `tag`는 **named struct**에도 가능 |
| `from` / `into` / `try_from` | 중간 타입으로 변환해 (역)직렬화 (16절) |
| `transparent` | 단일 필드 newtype/구조체를 그 필드처럼 |
| `expecting = "..."` | 역직렬화 에러 메시지용 기대 문구 |
| `crate = "..."` | re-export된 serde 경로 |

`rename_all` 가능한 값:

`"lowercase"`, `"UPPERCASE"`, `"PascalCase"`, `"camelCase"`, `"snake_case"`, `"SCREAMING_SNAKE_CASE"`, `"kebab-case"`, `"SCREAMING-KEBAB-CASE"`

직렬화/역직렬화 따로:

```rust
#[serde(rename_all(serialize = "camelCase", deserialize = "snake_case"))]
```

### deny_unknown_fields 예

```rust
#[derive(Deserialize, Debug)]
#[serde(deny_unknown_fields)]
struct Strict {
    name: String,
}

fn strict_demo() {
    let ok = serde_json::from_str::<Strict>(r#"{"name":"a"}"#);
    assert!(ok.is_ok());

    let bad = serde_json::from_str::<Strict>(r#"{"name":"a","x":1}"#);
    assert!(bad.is_err());
}
```

기본(속성 없음) JSON 객체는 **모르는 필드를 무시**한다.

### 체크포인트

- [ ] `camelCase` rename_all로 JSON 키 확인
- [ ] deny_unknown_fields로 여분 키 실패 확인

## 7. 필드명 규칙 — rename / rename_all / alias

### 문제

Rust는 `snake_case`, 많은 JSON API는 `camelCase`.

```json
{ "userId": 1, "displayName": "kim" }
```

```rust
// 이대로면 JSON 키 `userId` ≠ Rust 필드명 `user_id`
// → 필수 필드면 역직렬화 실패. (default/Option이 있을 때만 채워지거나 None)
struct User {
    user_id: u64,
    display_name: String,
}
```

### rename_all (권장)

```rust
#[derive(Serialize, Deserialize, Debug, PartialEq)]
#[serde(rename_all = "camelCase")]
struct User {
    user_id: u64,
    display_name: String,
}

fn camel_roundtrip() {
    let u = User {
        user_id: 1,
        display_name: "kim".into(),
    };
    let s = serde_json::to_string(&u).unwrap();
    assert!(s.contains("userId"));
    assert!(s.contains("displayName"));

    let back: User = serde_json::from_str(&s).unwrap();
    assert_eq!(u, back);
}
```

### 필드별 rename

```rust
#[derive(Serialize, Deserialize)]
struct Legacy {
    #[serde(rename = "UserID")]
    user_id: u64,
}
```

### serialize / deserialize 이름 분리

```rust
#[derive(Serialize, Deserialize, Debug)]
struct Migrating {
    #[serde(rename(serialize = "newName", deserialize = "oldName"))]
    name: String,
}
```

읽기는 `oldName`, 쓰기는 `newName`. 왕복 호환이 깨질 수 있으니 주의.

### alias — 옛 키도 받기

```rust
#[derive(Serialize, Deserialize, Debug)]
struct Flexible {
    #[serde(alias = "old", alias = "legacy_name")]
    name: String,
}

fn alias_demo() {
    let a: Flexible = serde_json::from_str(r#"{"old":"x"}"#).unwrap();
    assert_eq!(a.name, "x");

    // 직렬화 키는 필드명(또는 rename) — alias 가 아님
    let s = serde_json::to_string(&a).unwrap();
    assert!(s.contains("name"));
}
```

### 체크포인트

- [ ] rename_all로 프론트 camelCase 맞추기
- [ ] alias로 구버전 JSON 수신

## 8. default · Option · skip

### Option

| JSON (`serde_json`) | `Option<T>` |
|---|---|
| 키 없음 | `None` (`#[serde(default)]` 없이도) |
| `null` | `None` |
| 값 있음 | `Some(T)` |

필수 필드(`String` 등)는 키 없으면 에러.

주의:

- **키 없음**과 **`null`을 `Option`만으로는 구분할 수 없다.** PATCH에서 “생략=유지 / null=삭제”가 필요하면 3상태 타입(`Option<Option<T>>` + `deserialize_with`, 또는 `serde_with` 등)을 쓴다.
- 이 “없는 키 → None” 특별 취급은 **포맷/Deserializer에 따라 다를 수 있다.** (예: 일부 바이너리 포맷은 `#[serde(default)]`가 필요할 수 있음) JSON에서는 위 표가 맞다.

### default

```rust
fn default_page() -> u32 {
    1
}

#[derive(Deserialize, Debug)]
struct PageQuery {
    #[serde(default = "default_page")]
    page: u32,

    #[serde(default)] // Default::default() → 0
    offset: u32,
}

fn default_demo() {
    let q: PageQuery = serde_json::from_str("{}").unwrap();
    assert_eq!(q.page, 1);
    assert_eq!(q.offset, 0);
}
```

컨테이너에 `#[serde(default)]`를 주면 **모든 필드**가 없을 때 Default를 쓴다(필드 타입에 Default 필요).

### skip / skip_serializing / skip_deserializing

```rust
#[derive(Serialize, Deserialize, Debug, Default)]
struct Session {
    token: String,

    #[serde(skip)]
    // 직렬화·역직렬화 모두 제외. Deserialize 시 Default::default()
    internal_counter: u64,

    #[serde(skip_serializing)]
    password_hash: String,

    #[serde(skip_deserializing)]
    #[serde(default)]
    server_only_flag: bool,
}
```

### skip_serializing_if

```rust
#[derive(Serialize, Debug)]
struct Patch {
    #[serde(skip_serializing_if = "Option::is_none")]
    name: Option<String>,

    #[serde(skip_serializing_if = "Vec::is_empty")]
    tags: Vec<String>,
}

fn skip_if_demo() {
    let p = Patch {
        name: None,
        tags: vec![],
    };
    let s = serde_json::to_string(&p).unwrap();
    assert_eq!(s, "{}");
}
```

함수 시그니처: `fn(&FieldType) -> bool`.

- [ ] Option 없는 키 / null
- [ ] default 함수
- [ ] skip_serializing_if로 빈 객체 `{}` 만들기

## 9. flatten

### 개념

한 단계 구조를 펼쳐 부모 JSON에 인라인한다.

```rust
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug, PartialEq)]
struct Pagination {
    limit: u64,
    offset: u64,
    total: u64,
}

#[derive(Serialize, Deserialize, Debug, PartialEq)]
struct UsersResponse {
    users: Vec<String>,

    #[serde(flatten)]
    pagination: Pagination,
}

fn flatten_demo() {
    let r = UsersResponse {
        users: vec!["a".into()],
        pagination: Pagination {
            limit: 10,
            offset: 0,
            total: 1,
        },
    };
    let s = serde_json::to_string(&r).unwrap();
    // {"users":["a"],"limit":10,"offset":0,"total":1}
    assert!(s.contains("\"limit\":10"));
    assert!(!s.contains("pagination"));
}
```

### 나머지 필드 수집

```rust
use std::collections::HashMap;
use serde_json::Value;

#[derive(Serialize, Deserialize, Debug)]
struct FlexibleUser {
    id: String,
    username: String,

    #[serde(flatten)]
    extra: HashMap<String, Value>,
}

fn extra_fields() {
    let u: FlexibleUser = serde_json::from_str(
        r#"{"id":"1","username":"kim","mascot":"Ferris","age":3}"#,
    )
    .unwrap();
    assert_eq!(u.extra["mascot"], "Ferris");
}
```

### 제약

- **named fields** 구조체에서만
- flatten 대상은 구조체 또는 map
- **`deny_unknown_fields`와 함께 쓸 수 없음** (바깥·안쪽 모두)

### 체크포인트

- [ ] Pagination flatten 왕복
- [ ] HashMap flatten으로 여분 키 수집

## 10. enum 직렬화

### 기본 (외부태그, externally tagged)

```rust
#[derive(Serialize, Deserialize, Debug, PartialEq)]
enum Message {
    Request { id: String, method: String },
    Response { id: String, result: String },
}

fn external_tag() {
    let m = Message::Request {
        id: "1".into(),
        method: "ping".into(),
    };
    let s = serde_json::to_string(&m).unwrap();
    // {"Request":{"id":"1","method":"ping"}}
    assert!(s.starts_with("{\"Request\":"));
}
```

### internally tagged — `tag`

```rust
#[derive(Serialize, Deserialize, Debug, PartialEq)]
#[serde(tag = "type")]
enum Event {
    Click { x: i32, y: i32 },
    Key { code: String },
}

fn internal_tag() {
    let e = Event::Click { x: 1, y: 2 };
    let s = serde_json::to_string(&e).unwrap();
    // {"type":"Click","x":1,"y":2}
    assert!(s.contains("\"type\":\"Click\""));
}
```

제약 (공식 문서):

- **구조체 배리언트**, **구조체/맵을 담은 newtype**, **unit** 가능
- **튜플 배리언트**가 있으면 `#[serde(tag = "...")]`는 **컴파일 에러**
- 역직렬화에 `alloc` feature 필요 (serde 기본 ON)

`rename_all`을 enum에 붙이면 **배리언트 태그 문자열**도 바뀐다.  
`Order` + `rename_all = "camelCase"` → JSON `"type":"order"`.  
필드만 바꾸고 태그는 Rust 이름 그대로 두려면 enum에는 `rename_all`을 쓰지 말고, 구조체 배리언트/`rename_all_fields`/내부 타입에만 적용한다.
### adjacently tagged — `tag` + `content`

```rust
#[derive(Serialize, Deserialize, Debug, PartialEq)]
#[serde(tag = "t", content = "c")]
enum Envelope {
    Text(String),
    Code { lang: String, body: String },
}

fn adjacent_tag() {
    let e = Envelope::Text("hi".into());
    let s = serde_json::to_string(&e).unwrap();
    // {"t":"Text","c":"hi"}
    assert!(s.contains("\"t\":\"Text\""));
}
```

### untagged

```rust
#[derive(Serialize, Deserialize, Debug, PartialEq)]
#[serde(untagged)]
enum StringOrNumber {
    Str(String),
    Num(i64),
}

fn untagged_demo() {
    let a: StringOrNumber = serde_json::from_str("\"hi\"").unwrap();
    let b: StringOrNumber = serde_json::from_str("42").unwrap();
    assert!(matches!(a, StringOrNumber::Str(_)));
    assert!(matches!(b, StringOrNumber::Num(42)));
}
```

배리언트 순서가 중요하다. 앞 배리언트가 먼저 시도된다.  
어느 배리언트도 맞지 않으면 에러 메시지가 빈약한 편이다 → 컨테이너 `#[serde(expecting = "...")]`로 보완 가능.  
성능이 민감하면 수동 `Deserialize` 또는 `serde-untagged` 크레이트를 검토한다.

### unit / newtype / tuple

```rust
#[derive(Serialize, Deserialize, Debug)]
enum Simple {
    Unit,                 // 외부태그 JSON: "Unit"
    Newtype(u64),         // {"Newtype":1}
    Tuple(u64, u64),      // {"Tuple":[1,2]}
    Struct { a: u64 },    // {"Struct":{"a":1}}
}
```

구조체 형태도 구분:

| 형태 | 예 | JSON (대략) |
|---|---|---|
| named struct | `struct S { a: u64 }` | `{"a":1}` |
| tuple struct | `struct T(u64, u64)` | `[1,2]` |
| newtype | `struct N(u64)` | `1` (또는 transparent) |
| unit struct | `struct U;` | `null` |

- [ ] external / internal / adjacent / untagged JSON 모양을 구분
- [ ] API 설계 시 `tag = "type"` 패턴 한 번 써 보기

## 11. 배리언트 attribute

```rust
#[derive(Serialize, Deserialize, Debug)]
#[serde(rename_all = "snake_case")]
enum Status {
    #[serde(rename = "ok")]
    Success,

    #[serde(alias = "fail", alias = "error")]
    Failed,

    #[serde(skip_serializing)]
    InternalOnly,
}

// internally / adjacently tagged 에서만 other 사용 가능
#[derive(Serialize, Deserialize, Debug, PartialEq)]
#[serde(tag = "kind")]
enum WireStatus {
    Ok,
    Err,
    #[serde(other)]
    Unknown,
}

fn other_demo() {
    let u: WireStatus = serde_json::from_str(r#"{"kind":"whatever"}"#).unwrap();
    assert_eq!(u, WireStatus::Unknown);
}
```

| attribute | 효과 |
|---|---|
| `rename` | 배리언트 이름 |
| `alias` | 역직렬화 시 다른 이름 허용 |
| `rename_all` | **이 구조체 배리언트의 필드**만 케이스 변환 |
| `skip` / `skip_serializing` / `skip_deserializing` | 제외 (`skip_serializing` 시 그 배리언트 직렬화는 에러) |
| `other` | 알 수 없는 **태그** catch-all. **unit 배리언트만**, **internally 또는 adjacently tagged enum만** |
| `untagged` | 이 배리언트만 태그 없이 (역)직렬화. **enum 정의에서 마지막**에 둬야 함 |
| `serialize_with` / `deserialize_with` | 배리언트 단위 커스텀 함수 |

## 13. Value · Map · 동적 JSON

### Value

타입이 고정되지 않은 JSON 조각.

```rust
use serde_json::{Map, Value};

fn manipulate_value() {
    let mut map = Map::new();
    map.insert("a".into(), Value::from(1));
    map.insert("b".into(), Value::String("x".into()));
    let v = Value::Object(map);

    let n = v["a"].as_i64().unwrap();
    assert_eq!(n, 1);
}
```

`Value::Object`의 맵 백엔드:

| feature | 키 순서 |
|---|---|
| 기본 (`preserve_order` OFF) | `BTreeMap` → **키 정렬** |
| `preserve_order` ON | `IndexMap` → **삽입 순서** 유지 |

Cargo feature는 **의존성 그래프에서 합집합**이다. 다른 크레이트가 `preserve_order`를 켜면 내 크레이트도 IndexMap이 된다.  
정렬이 필수면 직렬화 직전에 `value.sort_all_objects()`를 호출하는 방법이 권장된다.

구조체로 못 받을 때 `Value`로 받은 뒤 부분 파싱:

```rust
#[derive(Deserialize)]
struct Partial {
    id: u64,
}

fn partial_from_value() {
    let v: Value = serde_json::from_str(r#"{"id":1,"noise":true}"#).unwrap();
    let p: Partial = serde_json::from_value(v).unwrap();
    assert_eq!(p.id, 1);
}
```

### DeserializeOwned

`'static`에 가깝게 소유하는 역직렬화. Axum `Json<T>` 등에서 `T: DeserializeOwned`를 요구한다.

정확히: `DeserializeOwned` = `for<'de> Deserialize<'de>`.  
즉 **입력 버퍼를 빌리는** 타입(`&str`, `&[u8]`, `Cow<'de, str>` 등)은 보통 만족하지 못하고, `String`/`Vec` 같은 소유 타입이 필요하다.

```rust
use serde::de::DeserializeOwned;

fn parse<T: DeserializeOwned>(s: &str) -> serde_json::Result<T> {
    serde_json::from_str(s)
}
```

- [ ] Value ↔ 구조체 `from_value` / `to_value`

## 15. 커스텀 Serialize / Deserialize

derive로 안 되는 형식(날짜 문자열, 비트플래그 등).

### Serialize 수동

```rust
use serde::ser::{Serialize, Serializer};

struct AsHex(u32);

impl Serialize for AsHex {
    fn serialize<S: Serializer>(&self, serializer: S) -> Result<S::Ok, S::Error> {
        serializer.serialize_str(&format!("{:08x}", self.0))
    }
}
```

### Deserialize 수동 (간단 — string에서)

```rust
use serde::de::{self, Deserialize, Deserializer, Visitor};
use std::fmt;

struct AsHex(u32);

impl<'de> Deserialize<'de> for AsHex {
    fn deserialize<D: Deserializer<'de>>(deserializer: D) -> Result<Self, D::Error> {
        struct HexVisitor;
        impl Visitor<'_> for HexVisitor {
            type Value = AsHex;
            fn expecting(&self, f: &mut fmt::Formatter) -> fmt::Result {
                f.write_str("hex string")
            }
            fn visit_str<E: de::Error>(self, v: &str) -> Result<AsHex, E> {
                u32::from_str_radix(v, 16)
                    .map(AsHex)
                    .map_err(E::custom)
            }
        }
        deserializer.deserialize_str(HexVisitor)
    }
}

fn hex_roundtrip() {
    let h = AsHex(0xdead);
    let s = serde_json::to_string(&h).unwrap();
    assert_eq!(s, "\"0000dead\"");
    let back: AsHex = serde_json::from_str(&s).unwrap();
    assert_eq!(back.0, 0xdead);
}
```

실무에서는 `serde_with`, `#[serde(with = "module")]`로 빼는 경우가 많다.

## 16. with · from · into · try_from

### with = "module"

```rust
mod as_string {
    use serde::{self, Deserialize, Deserializer, Serializer};

    pub fn serialize<S: Serializer>(v: &u64, s: S) -> Result<S::Ok, S::Error> {
        s.serialize_str(&v.to_string())
    }

    pub fn deserialize<'de, D: Deserializer<'de>>(d: D) -> Result<u64, D::Error> {
        let s = String::deserialize(d)?;
        s.parse().map_err(serde::de::Error::custom)
    }
}

#[derive(Serialize, Deserialize, Debug)]
struct Row {
    #[serde(with = "as_string")]
    id: u64,
}
```

모듈에 `serialize` / `deserialize` 함수가 있으면 된다.

### serialize_with / deserialize_with

`with`를 한쪽만 쓰고 싶을 때:

```rust
#[derive(Serialize, Deserialize, Debug)]
struct Row2 {
    #[serde(serialize_with = "as_string::serialize")]
    #[serde(deserialize_with = "as_string::deserialize")]
    id: u64,
}
```

필드에 `serialize_with`만 있으면 그 필드는 `Serialize`를 구현하지 않아도 되고, `deserialize_with`만 있으면 `Deserialize`를 구현하지 않아도 된다.

### from / into / try_from (컨테이너)

중간 타입으로 변환한 뒤 (역)직렬화한다.

| attribute | 방향 | 필요 구현 |
|---|---|---|
| `from = "FromType"` | 역직렬화 | `Self: From<FromType>`, `FromType: Deserialize` |
| `try_from = "FromType"` | 역직렬화 | `Self: TryFrom<FromType>` (`Err: Display`), `FromType: Deserialize` |
| `into = "IntoType"` | 직렬화 | `Self: Clone + Into<IntoType>`, `IntoType: Serialize` |

```rust
#[derive(Serialize, Deserialize, Debug, PartialEq, Clone)]
#[serde(from = "u64", into = "u64")]
struct UserId(u64);

impl From<u64> for UserId {
    fn from(v: u64) -> Self {
        UserId(v)
    }
}
impl From<UserId> for u64 {
    fn from(v: UserId) -> Self {
        v.0
    }
}

fn from_into_demo() {
    let u: UserId = serde_json::from_str("42").unwrap();
    assert_eq!(u.0, 42);
    // into 는 Clone 후 변환하므로 Clone 필요
    assert_eq!(serde_json::to_string(&u).unwrap(), "42");
}
```

### transparent

`#[serde(transparent)]` — newtype(또는 필드 하나인 braced struct)을 **그 안쪽 필드만** 있는 것처럼 직렬화.

```rust
#[derive(Serialize, Deserialize, Debug, PartialEq)]
#[serde(transparent)]
struct Meter(f64);

fn transparent_demo() {
    let m = Meter(1.5);
    assert_eq!(serde_json::to_string(&m).unwrap(), "1.5");
}
```

`from`/`into`와 달리 변환 로직 없이 “래퍼를 벗겨” 위임한다.

### 체크포인트

- [ ] `with` 모듈로 숫자↔문자열
- [ ] `from`/`into`에 `Clone`(into) 요구사항 확인
- [ ] transparent newtype

## 20. 성능 · 함정 · 자주 하는 실수

### 성능 감각

- 입력이 이미 `&[u8]`이면 `from_slice`가 자연스럽다. `&str`이면 `from_str`(내부적으로 UTF-8 슬라이스 파싱). **둘의 할당 차이는 크지 않다** — 병목은 보통 할당·필드 매칭
- 큰 JSON은 `from_reader` / 버퍼 재사용, 또는 부분만 파싱(`RawValue`, 23절) 검토
- `Value`로 전부 파싱하면 할당이 많다 → 가능하면 구조체
- `to_string` 대신 `to_writer`로 IO에 직접
- `untagged` enum은 배리언트를 순서대로 시도하므로 상대적으로 비쌀 수 있다

### 함정

1. **필수 필드인데 rename_all 불일치** → 400/에러  
2. **`flatten` + `deny_unknown_fields`** → 지원 안 함 (바깥·안쪽 모두)  
3. **untagged enum 배리언트 순서** → 잘못된 배리언트로 파싱  
4. **enum에 `rename_all = "camelCase"`** → 배리언트 태그도 `Order`→`order`로 바뀜  
5. **`f64`와 JSON 정수** — 대체로 OK, JS 안전정수·초큰 정수는 `u64`/`i64`/`String` 검토  
6. **`std::collections::HashMap` 키 순서는 비결정적** — 문자열 전체 비교 테스트 주의. (`serde_json::Map`은 기본 정렬 / `preserve_order`면 삽입순)  
7. **`#[serde(default)]` 없는 non-Option** — 키 없으면 실패  
8. **skip 필드 Deserialize** — `Default` 또는 `default = "..."` 필요  
9. **공유 DTO 없이 Sender/Receiver rename 따로** → 운영 사고  
10. **`Option`으로 absent vs null 구분 불가** → PATCH 시맨틱 깨짐  
11. **internally tagged + tuple 배리언트** → 컴파일 에러  

### 체크포인트

- [ ] 위 함정 중 3개를 코드로 재현해 보기

## 21. 실전: API DTO 한 방에

```rust
use serde::{Deserialize, Serialize};
use serde_json::json;

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "camelCase")]
pub struct OrderEvent {
    pub order_id: String,
    pub product_name: String,
    pub quantity: u32,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub note: Option<String>,
}

// 주의: enum에 rename_all을 붙이면 태그("Order")까지 camelCase("order")가 된다.
// 태그는 PascalCase/Rust 이름 유지, 필드만 camelCase → 아래처럼 분리.
#[derive(Debug, Serialize, Deserialize, PartialEq)]
#[serde(tag = "type")]
pub enum WireMessage {
    Order(OrderEvent),
    #[serde(rename_all = "camelCase")]
    Ack {
        request_id: String,
        ok: bool,
    },
}

fn demo() {
    let msg = WireMessage::Order(OrderEvent {
        order_id: "ORD-1".into(),
        product_name: "deskmat".into(),
        quantity: 2,
        note: None,
    });

    let s = serde_json::to_string(&msg).unwrap();
    // {"type":"Order","orderId":"...","productName":"...","quantity":2}
    assert!(s.contains("\"type\":\"Order\""));
    assert!(!s.contains("note")); // skip_serializing_if

    let back: WireMessage = serde_json::from_str(&s).unwrap();
    assert_eq!(back, msg);

    // 동적 검사
    let v = serde_json::to_value(&msg).unwrap();
    assert_eq!(v["type"], json!("Order"));
}
```

## 23. 보너스: borrow · RawValue

### borrow (제로카피)

입력 버퍼 수명 `'de`에 빌리는 필드:

```rust
use serde::Deserialize;
use std::borrow::Cow;

#[derive(Deserialize, Debug)]
struct Line<'a> {
    #[serde(borrow)]
    msg: &'a str,

    #[serde(borrow)]
    note: Cow<'a, str>,
}

fn borrow_demo() {
    let data = r#"{"msg":"hi","note":"x"}"#;
    let line: Line = serde_json::from_str(data).unwrap();
    assert_eq!(line.msg, "hi");
}
```

Axum `Json<T>`는 `T: DeserializeOwned`라 **수명 있는 타입은 보통 못 넣는다.**  
파일/버퍼를 직접 `from_str`/`from_slice`할 때 의미가 있다.

### RawValue (지연 파싱)

`serde_json` feature `raw_value`가 필요하다.

```toml
serde_json = { version = "1", features = ["raw_value"] }
```

```rust
use serde::Deserialize;
use serde_json::value::RawValue;

#[derive(Deserialize)]
struct Envelope<'a> {
    #[serde(borrow)]
    payload: &'a RawValue, // 아직 구조체로 안 펼침
}
```

큰 JSON에서 일부만 먼저 보고, 나중에 `serde_json::from_str(payload.get())`로 세부 타입을 파싱할 때 유용하다.

### 체크포인트

- [ ] borrow는 DeserializeOwned와 충돌한다는 점 이해
- [ ] RawValue feature를 Cargo.toml에 켠 뒤 한 번 실험
