# OpenClaw × LM Studio × Qwen3.8 — Local Agent Stack Report

---

## 1. Executive Summary

This report documents a working **fully local** personal AI agent stack:


| Layer           | Component                                           | Role                                    |
| --------------- | --------------------------------------------------- | --------------------------------------- |
| Agent runtime   | **OpenClaw 2026.9.2** (`3928bad`)                   | Gateway, tools, sessions, CLI / TUI     |
| Local inference | **LM Studio** (`127.0.0.1:1234`)                    | OpenAI-compatible local server          |
| Primary model   | **Qwen3.8 27B** (`qwen/qwen3.8-27b`, MLX 4-bit)     | Chat + tool use + vision-capable LLM    |
| Node runtime    | **Node.js 24.19.0** (user-space under this project) | Runs OpenClaw CLI + LaunchAgent Gateway |


What makes the result striking is not merely “a chatbot answering in Korean.” The agent:

1. Runs **entirely on-device** (no cloud LLM required for the primary model).
2. Speaks through OpenClaw’s **Gateway** (persistent daemon), not a one-off script.
3. Uses a **coding tools profile**, so it can inspect the host environment (e.g., correctly reporting Bun `1.4.1` at `/Users/home/.bun/bin/bun`).
4. Maintains **session continuity** across `agent`, TUI, and prior turns.

In short: OpenClaw turns a local LM Studio model into something closer to a **resident assistant with tools**, rather than a passive completion endpoint.

## 2. Why This Feels Remarkable



### 2.1 From “local LLM” to “local agent”

Most local setups stop at:

> load model → chat in GUI → get text back

This stack goes further:

```
User (TUI / CLI)
    → OpenClaw Gateway (port 18789, loopback)
        → Tool / session / workspace layer
            → LM Studio OpenAI-compatible API (/v1)
                → Qwen3.8 27B (loaded in MLX, 4-bit)
```

The model is no longer the whole product. **OpenClaw is the control plane**; Qwen is the brain; LM Studio is the inference engine.

A real session on this machine produced roughly:


| Turn  | User                              | Assistant behavior                                             |

### 2.3 Tool use is the inflection point

- `trained_for_tool_use: true`

OpenClaw’s onboard wizard selected this model as default and enabled the `coding` **tools profile**. The Bun answer is evidence that the agent can **act on the machine**, not only invent plausible text.

## 4. Installation History (What Was Done)



### 4.1 Problem with system Node

The machine’s Homebrew Node (`22.8.0`) was broken at install time:

```text
dyld: Library not loaded: /opt/homebrew/opt/icu4c/lib/libicui18n.74.dylib
```

Therefore a **user-space OpenClaw install** was preferred over a global npm install that would depend on the broken Node.

### 4.2 Prefix install into this research folder

Command used:

```bash
curl -fsSL --proto '=https' --tlsv1.2 https://openclaw.ai/install-cli.sh \
  | bash -s -- --prefix /Users/.../.../..../260905_...aw2 --no-onboard
```

Result:

- OpenClaw **2026.9.2** installed under the project prefix
- Bundled **Node 24.19.0** at `tools/node-v24.19.0/`
- Wrapper binary at `bin/openclaw`



### 4.3 Non-interactive LM Studio onboarding

```bash
openclaw onboard \
  --non-interactive \
  --accept-risk \
  --auth-choice lmstudio \
  --custom-base-url http://127.0.0.1:1234/v1 \
  --custom-model-id qwen/qwen3.8-27b \
  --skip-channels \
  --skip-skills \
  --skip-search \
  --skip-hooks \
  --skip-ui \
  --install-daemon \
  --workspace /Users/.../.../.../260905_.../workspace
```

Outcomes:

- Config written to `~/.openclaw/openclaw.json`
- Default model set to `lmstudio/qwen/qwen3.8-27b`
- LM Studio catalog models registered under `models.providers.lmstudio`
- LaunchAgent installed: `~/Library/LaunchAgents/ai.openclaw.gateway.plist`
- Daemon deliberately uses the **project’s Node 24.19.0**, not broken Homebrew Node
- Gateway listening on **127.0.0.1:18789**



### 4.4 Verification

## 7. How to Operate Day-to-Day



### 7.1 Prerequisites

1. **LM Studio** running with Local Server on port **1234**.
2. **Qwen3.8 27B** loaded (or JIT enabled so first request can load it).
3. **OpenClaw Gateway** LaunchAgent loaded (installed during onboard).

Check Gateway:

```bash
export PATH="/Users/.../.../.../260905_.../bin:$PATH"
openclaw gateway status
openclaw health
openclaw models list
```



### 7.2 Talk to the agent

One-shot:

```bash
openclaw agent --message "Your question here"
```

Interactive terminal UI (correct command when Gateway is already running):

```bash
openclaw tui
```

Browser Control UI:

```bash
openclaw dashboard
```



### 7.3 Switch models later

```bash
openclaw models set lmstudio/qwen/qwen3.6-27b
# or any other catalog id listed by: openclaw models list
```



### 7.4 Critical gotcha: `chat` vs `tui`


| Command         | Meaning                 | When Gateway is running                     |
| --------------- | ----------------------- | ------------------------------------------- |
| `openclaw chat` | Alias for `tui --local` | **Fails** — conflicts with existing Gateway |
| `openclaw tui`  | Connects to Gateway     | **Works**                                   |


Error seen in practice:

```text
A Gateway is running for this state directory (pid ..., port 18789).
Run without --local to use it, or stop the Gateway first.
```

**Use** `openclaw tui`**, not** `openclaw chat`**, while the daemon is up.**

## 8. Capability Analysis



### 8.1 What already works

- Local Korean / English conversation through OpenClaw surfaces
- Persistent Gateway + session continuity
- Primary model routing to LM Studio Qwen3.8
- Tool-capable agent answering real host facts (Bun version / path)
- Multi-model catalog registered from LM Studio discovery
- LaunchAgent auto-managed Gateway lifecycle



### 8.2 What was intentionally skipped during onboard

For a fast local wiring, the following were skipped:

- Chat channel setup (Telegram / Discord / Slack / etc.)
- Skills setup
- Search provider setup
- Hooks setup
- Interactive Control UI handoff prompts

These can be added later with `openclaw configure` or a follow-up `openclaw onboard` section.

### 8.3 Limits and caveats

1. **LM Studio must stay up.** If the local server stops, OpenClaw Gateway remains up but model calls fail.
2. **Latency.** Local 27B MLX inference is slower than cloud frontier models; first replies can take tens of seconds depending on load and context.
3. **Context lean policy.** OpenClaw may use 64k effective context even though the model supports 262k.
4. **Security / autonomy.** With `tools.profile: coding`, the agent can inspect and potentially modify the environment according to OpenClaw’s approval / policy settings. Treat it as a privileged local assistant.
5. **Broken system Node.** Homebrew Node still needs repair for other tools; OpenClaw itself is insulated via the prefix Node.
6. **Do not publish** `~/.openclaw/openclaw.json` (contains gateway token).

## 9. Research Implications

This setup is a useful research baseline for several questions:

1. **Local agent quality:** How well does Qwen3.8 27B handle tool calling, multi-step tasks, and Korean UX under OpenClaw’s coding profile?
2. **Control-plane vs model:** Separating Gateway/tools from inference makes it easy to A/B swap models (`qwen3.8` vs `qwen3.6` vs Gemma / MiniMax) without changing the agent product surface.
3. **Privacy:** Prompts and tool I/O can stay on-machine if channels and cloud fallbacks are not enabled.
4. **Ops model:** LaunchAgent + loopback Gateway is a lightweight “always-on assistant” pattern for a workstation, without Docker.
5. **Failure modes:** Clear separation of CLI PATH issues, Gateway conflicts (`--local`), and LM Studio availability makes debugging measurable.

```typescript
// bun.serve 기본 예제
// 실행: bun run bun-serve-example.ts

const server = Bun.serve({
  port: 3000,
  async fetch(req: Request) {
    const url = new URL(req.url);

    // GET / -> JSON 응답
    if (url.pathname === "/") {
      return Response.json({
        message: "Bun 서버에서 온 인사!",
        path: url.pathname,
        time: new Date().toISOString(),
      });
    }

    // GET /hello?name=... -> 텍스트 응답
    if (url.pathname === "/hello") {
      const name = url.searchParams.get("name") ?? "world";
      return new Response(`Hello, ${name}!`);
    }

    // POST /echo -> 요청 body를 그대로 JSON으로 반환
    if (url.pathname === "/echo" && req.method === "POST") {
      const body = await req.json().catch(() => null);
      return Response.json({ received: body });
    }

    return new Response("Not Found", { status: 404 });
  },
});

console.log(`Server running at http://localhost:${server.port}`);
```
