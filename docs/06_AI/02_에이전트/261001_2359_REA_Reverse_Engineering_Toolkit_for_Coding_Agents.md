# REA 사례로 본 코딩 에이전트 시대의 역공학 도구와 증거 기반 분석

## 요약

REA(Reverse Engineer Anything)는 Claude Code, Codex, Cursor 같은 코딩 에이전트가 소스 코드 없이 앱을 역공학할 수 있게 해 주는 MCP 서버 겸 CLI다. 슬로건은 "마음에 드는 기능을 보면, 바이너리 수준까지 어떻게 동작하는지 이해하라"이다. 다른 앱의 기능을 에이전트에게 조사시키고, 근거와 함께 설명받고, 내 프로젝트용으로 다시 만들게 하는 흐름을 목표로 한다. TypeScript로 작성됐고 MIT 라이선스이며, 2026년 4월 14일 저장소가 만들어진 뒤 10월 11일 기준 약 9만 스타, 1만 9,800 포크를 기록했다. GitHub Trending 1위에 올랐고 Hacker News에서 740점과 316개 댓글을 받았다.

REA는 새로운 디컴파일 알고리즘을 만든 프로젝트가 아니다. Hopper, Ghidra, IDA 같은 기존 분석 엔진과 JavaScript·.NET·웹·Android 분석 도구를 에이전트가 실제로 다룰 수 있는 하나의 인터페이스로 묶었고, 모든 결과에 근거와 한계를 붙이도록 강제했다. 이 두 가지가 기여의 전부이자 핵심이다. 커뮤니티는 "완전 자동화된 고급 표절"이라는 비판과 "단종된 옛 소프트웨어 보존에 유용하다"는 반론으로 갈렸다. 결론적으로 REA는 역공학의 진입 장벽을 크게 낮췄지만, 그만큼 법적·윤리적 판단의 책임이 사용자에게 더 무겁게 놓인다.

## 1. REA 개요와 확인된 사실

전통적인 역공학은 사람이 도구를 고르고, 도구마다 다른 UI와 API를 배우고, 어셈블리를 읽으며 함수 호출과 상수의 의미를 추적하고, 결과를 다른 도구로 옮기며 정리하는 일이었다. REA는 README에서 이 과정을 이렇게 정리한다. "도구를 고르고, API를 배우고, 증거를 옮기고, 다음에 무엇을 볼지 정하는 일을 에이전트에게 넘긴다."

```text
나:   "Notes 앱 검색 기능이 어떻게 동작하는지 근거와 함께 보여 주고, 내 프로젝트에 비슷하게 만들어 줘"
에이전트 ──MCP──▶ REA ──▶ Hopper / Ghidra / IDA / JS 분석기 / 브라우저 / adb ...
에이전트 ◀────── 코드 조각 + 참조 + 호출 관계 + 해석하지 못한 부분(unknowns)
에이전트: 설명 → 후속 질문 → 구현 → 테스트
```

같은 기능은 `rea` CLI로 터미널에서도 쓸 수 있다. 설치는 한 줄이다.

```bash
npx rea-agents setup
```

setup은 감지된 에이전트 목록과 바꿀 설정을 계획으로 보여 주고, 승인받은 뒤 기존 설정을 백업하고 MCP 서버와 조사 워크플로 지침(skill)을 함께 등록한다. 요구 사항은 Node.js 22.19 이상(또는 24.11 이상, 26 이상)과 npm이다. 공식 MCP Registry에는 `io.github.morluto/rea`로 등록되어 있다.

> 출처: [GitHub morluto/rea](https://github.com/morluto/rea), [rea.tools](https://rea.tools/), [docs/installation.md](https://github.com/morluto/rea/blob/main/docs/installation.md)

## 2. 대표 사례

### 2.1 Windows 계산기: 왜 200 + 10%는 220인가

공식 사이트의 첫 데모다. 사람이 직접 분석하면 계산기 DLL의 어셈블리를 읽어야 한다.

```text
0x180124945: MOV EAX, dword ptr [R13 + 0x18]
0x180124949: CMP EAX, 0x5c        ; 0x5c = 곱하기(IDC_MUL 92)
0x18012494c: JZ 0x180124aba
0x180124952: CMP EAX, 0x5b        ; 0x5b = 나누기(IDC_DIV 91)
0x180124955: JZ 0x180124aba
0x18012495b: MOV EDX, 0x64        ; 0x64 = 100
```

REA를 쓰면 "Windows 계산기를 조사해서 왜 200 + 10%가 220인지 % 버튼 뒤의 코드를 보여 줘"라는 프롬프트 하나로 끝난다. REA가 `%` 처리 함수의 원본 명령어와 디컴파일 결과를 돌려주면 에이전트가 규칙을 요약한다.

```c
if (operation == multiply || operation == divide) {
  percent = current / 100;              // 200 × 10% → 200 × 0.1
} else {
  percent = current * previous / 100;   // 200 + 10% → 200 + 20
}
```

이 분석은 REA 4.1.0으로 Windows Calculator 11.2508.4.0(x64)을 검사한 결과이며, Microsoft가 공개한 소스의 상수 정의와 대조해 검증했다.

### 2.2 크롬 공룡 게임의 가속 규칙

REA는 실행 중인 페이지의 `index.js`를 가져와 속도 규칙(시작 6, 업데이트마다 0.001씩 증가, 최대 13)을 찾았다. 에이전트는 이 규칙으로 속도 슬라이더가 달린 작은 게임을 새로 만들었고, 원본 update 함수를 통제된 브라우저에서 실행해 4,000번 뒤 10.0, 10,000번 뒤 13.0이 나오는 것까지 확인했다.

## 3. 분석 대상과 엔진

REA가 다루는 대상은 넓다. 네이티브 바이너리는 의사코드, 어셈블리, 문자열, 심볼, 호출과 참조를 돌려주며 Hopper, Ghidra, IDA 중 하나가 필요하다. JavaScript와 Electron 앱은 모듈, import, 소스맵, 라우트, IPC, 네이티브 애드온 관계를 Node.js만으로 분석한다. 웹사이트는 Chrome 계열 브라우저로 페이지 구조와 네트워크를 관찰한다. .NET 어셈블리는 추가 도구 없이 메타데이터와 CIL을 정적으로 읽는다. 이 밖에 Android APK와 기기(JADX, adb), WASM과 EVM 바이트코드, 펌웨어(Binwalk, Unblob), 네트워크 캡처(HAR, mitmproxy), 리눅스 크래시 기록, 네이티브 PTY 기반 프로세스 동작 캡처까지 지원한다.

정적 분석은 파일만 읽고 앱을 실행하지 않는다. 런타임 캡처는 사용자 권한으로 대상을 실제로 실행하거나 조작한다. 이 구분은 문서 곳곳에서 강조된다.

| 엔진 | 특징 |
| --- | --- |
| Hopper | 기본 제안 엔진. macOS에서는 공식 DMG를 내려받아 `~/Applications`에 설치하며 관리자 권한이 필요 없다. 무료 데모 모드로도 분석 가능 |
| Ghidra | Ghidra 12.1.2와 JDK 21을 사용자가 직접 설치. 읽기 전용이며 함수 목록, 의사코드, 어셈블리, xref, CFG 등 19개 연산 제공 |
| IDA | 기존 ida-pro-mcp 서버를 감싸서 사용. REA는 IDA를 설치하거나 라이선스를 다루지 않음 |

## 4. 설계의 핵심: 근거와 한계를 강제한다

REA를 다른 MCP 래퍼와 가르는 지점은 결과의 형식이다. LLM은 그럴듯한 설명을 지어내는 데 능하다. 역공학처럼 정답 확인이 어려운 분야에서 이 성향은 치명적이다. REA는 에이전트가 받는 재료 자체를 증거 단위로 쪼개 이 문제를 줄인다.

- **Evidence v2 레코드**: 결론마다 근거를 재현 가능한 형태로 기록하고, 내보내기·가져오기·비교(`rea compare`)할 수 있다.
- **unknowns 명시**: 해석되지 않은 호출 대상은 "모름"으로 남긴다. 타임아웃이나 크기 제한에 걸리면 부분 결과를 완전한 것처럼 돌려주지 않고 명시적으로 실패한다.
- **정적 추론과 런타임 관찰의 분리**: JavaScript 앱 레이어를 연결하는 도메인 그래프에서 "코드를 보고 추측한 것"과 "실행해서 본 것"을 섞지 않는다.
- **입력 무결성 검증**: Ghidra 브리지는 대상 파일을 임시 공간에 복사하고 SHA-256을 확인한 뒤에야 연산을 수행한다.

```text
일반 MCP 래퍼 : 도구 출력 → 에이전트 → 그럴듯한 설명
REA          : 도구 출력 → 증거 레코드 + unknowns → 에이전트 → 근거가 붙은 설명
```

안전장치도 같은 철학을 따른다. 분석은 로컬에서 돌고 REA가 앱을 외부 서버에 올리지 않는다. 다만 결과는 에이전트의 모델 제공자로 넘어가므로 그쪽 데이터 정책을 따른다. Linux에서 Hopper를 설치할 때는 `sudo` 대신 `pkexec`로 권한을 요청하고, 체크섬이 맞지 않으면 중단한다. `rea doctor --json`은 읽기 전용으로 환경을 진단하고, `rea investigate-versions`는 두 버전의 앱을 실행하지 않고 구조 차이만 비교한다.

## 5. 반응과 논쟁

### 5.1 인기와 거품

10월 4일 데모 트윗이 31만 4천 회 조회됐고 6일 뒤 GitHub Trending 1위에 올랐다. 10월 11일에는 약 10시간 만에 72,487개에서 84,912개로 1만 2천 스타 이상 늘었고 하루 약 280개씩 포크됐다. 같은 분야 오픈소스 보안 에이전트 도구 중 스타 수 1위로, 2위 PentAGI(2만 5,400), IDA Pro MCP(1만 2,600)와 차이가 크다. 작성자 스스로 "오픈소스 프로젝트는 좋아서 스타를 받는가, 스타가 있어서 좋은가"라고 물을 만큼 유행을 타고 몰린 스타도 섞여 있다는 평가가 있다. README에는 REA 이름을 쓴 암호화폐는 프로젝트와 무관한 사기라는 경고까지 들어갔다.

### 5.2 표절인가 보존인가

Hacker News 논쟁의 축은 두 가지였다. 한쪽은 "완전 자동화된 고급 표절(fully automated luxury plagiarism)"이라고 비판하며, AI가 만든 디컴파일 결과가 저작권법상 변형적 공정 이용으로 인정될 수 있는지 의문을 제기했다. 다른 쪽은 더 이상 어디서도 팔지 않는 옛 게임이 많고 이를 복원·보존하는 데 큰 도움이 된다고 반론했다.

또 하나의 시각은 "도구가 핵심은 아니다"였다. REA 없이도 Claude가 증상만 보고 Windows 원격 데스크톱 바이너리의 오래된 버그 두 개를 패치하거나, Insta360 앱을 역공학해 AMD GPU 가속을 추가한 사례가 공유됐다. REA는 증폭기이지 필수품은 아니라는 뜻이다.

## 6. 법적·윤리적 경계

README의 면책 조항은 REA가 합법적인 역공학 연구, 분석, 재구성을 위한 도구이며 필요한 권한을 얻고 관련 법을 지키는 것은 사용자 책임이라고 명시한다. 실무에서 지켜야 할 선은 다음과 같다.

```text
허용되는 방향 : 동작 원리를 이해하고 내 방식으로 다시 구현, 호환성·보안 연구, 단종 소프트웨어 보존
피해야 할 방향 : 라이선스가 역공학을 금지한 소프트웨어 분석, 코드를 그대로 베껴 재판매
추가 주의      : 분석 결과가 모델 제공자로 전송되므로 기밀 바이너리는 다루지 않음
```

오픈소스 대상은 역공학보다 소스를 직접 읽는 편이 빠르고 깔끔하다. 역공학 도구는 소스가 없을 때의 수단이다.

| 영역 | 점검 항목 |
| --- | --- |
| 라이선스 | 대상 소프트웨어의 EULA가 역공학을 허용하는지 확인했는가? |
| 목적 | 이해와 재구현이 목적인가, 복제와 재판매가 목적인가? |
| 데이터 경계 | 분석 결과가 외부 모델 제공자로 전송되어도 괜찮은 대상인가? |
| 정적·동적 구분 | 앱을 실행하는 런타임 캡처가 필요한지, 정적 분석으로 충분한지 구분했는가? |
| 근거 확인 | 에이전트의 설명이 증거 레코드와 연결되어 있고 unknowns를 확인했는가? |
| 교차 검증 | 공개 소스, 문서, 테스트 케이스와 대조해 복원 결과를 검증했는가? |
| 재구현 검증 | 복원한 규칙을 원본과 같은 입력으로 비교하는 테스트를 만들었는가? |
| 설정 변경 | setup이 바꾸는 에이전트 설정을 검토하고 백업을 확인했는가? |

## 결론

REA는 역공학이라는 전문 영역을 "프롬프트 한 줄"로 끌어내렸다. 새로운 분석 기술은 없지만, 흩어진 엔진을 에이전트가 다룰 수 있는 인터페이스로 묶고 모든 결론에 근거와 한계를 붙이도록 강제한 설계가 폭발적인 반응을 이끌었다. 계산기의 % 규칙, 게임의 가속 공식, Electron 앱의 IPC 경로를 몇 분 만에 밝혀내는 사례는 인상적이다. 그러나 진입 장벽이 낮아질수록 판단의 책임은 더 무거워진다. 무엇을 분석해도 되는지, 결과를 어디까지 써도 되는지는 도구가 대신 정해 주지 않는다. 에이전트 시대의 역공학에서 필요한 역량은 어셈블리를 읽는 능력보다 라이선스를 확인하고, 증거를 검증하고, 이해한 것을 내 방식으로 다시 만드는 능력이다.
