# 1. 1.4.4에서 달라진 점

Bun 1.4.4는 2026년 10월 22일에 나온 패치입니다. 1.4.3 위에 포매터, 더 빠른 타입 검사, 패키지 관리자 개편, SQL·WebSocket 동작 변경, 그리고 보안 수정이 한꺼번에 올라갔습니다. 이 글은 [공식 릴리스 노트](https://bun.com/blog/bun-v1.4.4)를 기준으로, 따라 할 명령과 업그레이드 뒤에 결과가 달라질 수 있는 곳만 골라 정리한 것입니다. 표에 있는 시간과 배율은 Bun 팀이 재는 환경의 수치이고, 이 Mac에서 다시 재지 않았습니다.

이 컴퓨터는 `bun upgrade`로 1.4.3에서 1.4.4로 올렸습니다.

## 왜 바로 올리는가

1.4.4의 보안 수정은 TLS, HTTP, WebSocket, Brotli, `fetch`, `Bun.serve`, SQL 클라이언트, `bun install`과 `bunx`까지 넓습니다. 그 안에 [Brotli 디코더의 범위 밖 쓰기(CVE-2026-111497)](./06_%EB%B3%B4%EC%95%88%EA%B3%BC_%EB%8F%99%EC%9E%91%EC%9D%B4_%EB%B0%94%EB%80%8C%EB%8A%94_%EC%88%98%EC%A0%95.md)가 들어 있습니다. `fetch`가 `Content-Encoding: br` 응답을 풀 때, `node:zlib`, `DecompressionStream("brotli")`가 이 디코더를 탑니다. 1.4.3 이하는 이 수정이 없습니다.

보안과 별개로, 아래는 코드를 고치지 않아도 실행 결과가 달라질 수 있습니다.

| 바뀌는 곳 | 1.4.3 | 1.4.4 |
|---|---|---|
| `Bun.Glob`의 `*( )`, `!( )`, `{1..3}` | 글자 그대로 매칭 | extglob·범위. `*(1).txt`는 더 이상 `copy(1).txt`가 아님 |
| 브라우저 `WebSocket`의 `close` | `close()` 직후, 내가 보낸 코드, 종종 `wasClean: true` | 상대의 Close를 기다림. 코드 없는 Close는 1005, 실패는 1006 |
| `ws` 패키지의 `error` | `ErrorEvent`인 경우가 있음 | `Error`. 리스너가 없으면 미처리 예외 |
| `bun test --coverage` | 실행되지 않은 분기·`await` 뒤를 덮인 줄로 세는 경우가 있음 | 그 줄을 빼서 커버리지 숫자가 내려갈 수 있음 |
| 피어 의존성 | 다른 패키지가 깔아 둔 버전을 그대로 씀 | 범위를 만족하는 버전을 고름. **이미 있는 `bun.lock`은 그대로** |
| `bun install --없는플래그` | 무시하고 설치 | 오류로 종료. npm에만 있는 플래그는 값까지 통째로 무시 |
| mTLS의 `ca` | 클라이언트 인증서를 요청 | `requestCert: true`가 있어야 요청. `ca`만으로는 요청하지 않음 |
| DB 비밀번호 환경 변수 `PASSWORD` | `Bun.SQL`이 읽음 | 읽지 않음. `PGPASSWORD`, `MYSQL_PASSWORD`, URL, `password` 옵션 |
| PostgreSQL 정수 2^51 이상 2^53 미만 | `float8`로 보내 `numeric`이 어긋남 | `int8`로 보내고, Bun은 그 결과를 문자열로 돌려줌 |
| `sql.array(["a","b"])`에 타입 없음 | `JSON[]`로 캐스트 | 캐스트 없음. `text[]`는 `sql.array(values, "TEXT")` |

`bun.lock`에 이미 고정된 버전은 피어 의존성 규칙이 바뀌어도 자동으로 다시 풀리지 않습니다. 다시 풀려면 그 패키지를 지웠다가 넣거나 잠금 파일을 새로 만들어야 합니다.

## 업그레이드

```bash
bun upgrade
bun --version
```

특정 버전만 받을 때는 설치 스크립트에 태그를 넘깁니다.

```bash
curl -fsSL https://bun.com/install | bash -s "bun-v1.4.4"
```

`bun upgrade`가 `fork failed: resource temporarily unavailable`로 끝나면 Bun 문제가 아닙니다. 그 계정이 만들 수 있는 프로세스 수에 닿은 상태라, 새 프로세스를 띄우는 명령이 모두 거절됩니다. 프로세스를 줄인 뒤에 같은 명령을 다시 실행하면 됩니다.
