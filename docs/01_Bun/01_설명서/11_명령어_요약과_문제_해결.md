# 11. 명령어 요약과 문제 해결

## 명령어 한눈에 보기

### 기본

| 명령 | 설명 |
|---|---|
| `bun --version` | 버전 확인 |
| `bun upgrade` | 최신 버전으로 업그레이드 |
| `bun upgrade --stable` | canary에서 안정 버전으로 돌아오기 |
| `bun --revision` | 버전과 빌드 번호 확인 |
| `bun --help` | 전체 도움말 |
| `bun <명령> --help` | 명령별 도움말 |

### 프로젝트와 실행

| 명령 | 설명 |
|---|---|
| `bun init -y` | 새 프로젝트 만들기 |
| `bun create <템플릿> <폴더>` | 템플릿으로 프로젝트 만들기 (예: `bun create vite my-web`) |
| `bun index.ts` | 파일 실행 |
| `bun -e '코드'` / `bun -p '식'` | 파일 없이 코드 실행 / 결과 출력 |
| `bun --env-file=파일 index.ts` | 지정한 환경 변수 파일로 실행 |
| `bun --watch index.ts` | 저장할 때마다 다시 시작 |
| `bun --hot server.ts` | 프로그램을 유지한 채 코드만 교체 |
| `bun --check index.ts` | 타입 검사를 통과할 때만 실행 (1.4.3 신규) |
| `bun --console-depth=5 index.ts` | `console.log`로 객체를 더 깊이 펼쳐 보기 |
| `bun run <스크립트>` | `package.json`의 스크립트 실행 |
| `bun run` | 스크립트 목록 보기 |
| `bunx <도구>` | 패키지를 설치하지 않고 바로 실행 |
| `bunx --bun <도구>` | Node.js가 아니라 Bun으로 도구 실행 |
| `bun repl` | 코드를 한 줄씩 입력해 보는 대화형 모드 |

### 패키지

| 명령 | 설명 |
|---|---|
| `bun install` (`bun i`) | `package.json`의 패키지 모두 설치 |
| `bun install --frozen-lockfile` | `bun.lock` 그대로만 설치 (CI, 배포용) |
| `bun install --production` | `devDependencies` 빼고 설치 |
| `bun add <패키지>` | 패키지 추가 |
| `bun add -d <패키지>` | 개발용 패키지 추가 |
| `bun remove <패키지>` | 패키지 삭제 |
| `bun outdated` | 새 버전이 있는 패키지 보기 |
| `bun update` | 패키지 업데이트 (`package.json`의 범위 안에서) |
| `bun update --latest` | 범위를 무시하고 최신 버전으로 업데이트 |
| `bun pm ls` | 설치된 패키지 목록 |
| `bun why <패키지>` | 그 패키지가 왜 설치되었는지 |
| `bun pm untrusted` / `bun pm trust <패키지>` | 설치 스크립트가 막힌 패키지 보기 / 허용 |
| `bun pm cache rm` | 다운로드 캐시 비우기 |

### 품질 확인과 배포

| 명령 | 설명 |
|---|---|
| `bun test` | 테스트 실행 |
| `bun check` | 타입 검사 (1.4.3 신규) |
| `bunx tsc --noEmit` | 타입 검사 (1.4.2 이하, `typescript` 설치 필요) |
| `bun build ./index.ts --outdir dist` | 하나의 파일로 빌드 (브라우저용) |
| `bun build ./index.ts --target=bun --outdir dist` | 서버 코드 빌드 |
| `bun build ./index.ts --compile --outfile app` | 실행 파일 만들기 |
| `bun build ./index.ts --compile --target=bun-windows-x64 --outfile app` | 다른 운영체제용 실행 파일 만들기 |

## 문제 해결

### `command not found: bun`

터미널을 새로 열거나 `source ~/.zshrc`를 실행하세요. 계속되면 `~/.bun/bin`이 `PATH`에 있는지 확인합니다.

```bash
echo $PATH | tr ':' '\n' | grep bun
```

### `error: Script not found "check"`

Bun이 1.4.2 이하입니다. `bun --version`으로 확인하고 `bun upgrade`로 올리세요.

### `bun check`에서 `Cannot find name 'console'` 오류가 나요

Bun의 타입 정의가 설치되지 않은 폴더입니다. `bun init`으로 만든 프로젝트에는 들어 있지만, 빈 폴더에 파일만 만들었다면 직접 설치하세요.

```bash
bun add -d @types/bun
```

### `--watch`를 붙였는데 자동으로 다시 실행되지 않아요

옵션 위치를 확인하세요. 옵션은 파일 이름 **앞**에 와야 합니다.

```bash
bun --watch index.ts   # 올바름
bun index.ts --watch   # 틀림: --watch가 프로그램 인자로 전달됨
```

### `bun test`를 했더니 내 스크립트가 아니라 테스트 실행기가 돌아요

`bun test`는 Bun의 테스트 실행기입니다. `package.json`에 직접 만든 `test` 스크립트를 실행하려면 `bun run test`를 쓰세요.

### 포트가 이미 사용 중이에요 (`EADDRINUSE`)

같은 포트로 띄운 서버가 이미 실행 중입니다. 사용 중인 프로그램을 찾아 종료하거나 다른 포트를 쓰세요.

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN   # 3000번을 쓰는 프로그램 확인
kill <PID>                          # 해당 프로그램 종료
```

### .env 값이 `undefined`로 나와요

- `.env` 파일이 **실행하는 위치(현재 폴더)**에 있는지 확인하세요.
- 변수 이름의 대소문자가 같은지 확인하세요.
- 값은 항상 문자열입니다. 숫자가 필요하면 `Number(Bun.env.PORT)`로 바꾸세요.

### 타입이 틀렸는데 실행은 돼요

정상입니다. Bun은 실행할 때 타입을 검사하지 않습니다. `bun check`로 따로 검사하세요([9장](./09_%ED%83%80%EC%9E%85_%EA%B2%80%EC%82%AC.md)).

### 실행은 되는데 `bun check`에서 `possibly 'undefined'`나 `TS1484` 오류가 나요

`bun init`이 만든 `tsconfig.json`의 엄격한 설정 때문입니다. 고치는 법은 [9장](./09_%ED%83%80%EC%9E%85_%EA%B2%80%EC%82%AC.md#처음에-자주-만나는-타입-오류)에 있습니다.

### `Cannot find module` / `Cannot find package` 오류가 나요

| 원인 | 해결 |
|---|---|
| 패키지를 설치하지 않음 (다른 사람의 프로젝트를 받은 직후 등) | `bun install` |
| 내 파일을 불러올 때 `./`를 빠뜨림 | `import { add } from "math"` → `import { add } from "./math"` |
| 파일 이름이나 대소문자가 다름 | macOS는 대소문자를 구분하지 않아도 Linux 서버는 구분합니다. 이름을 정확히 맞추세요 |

### 패키지를 설치했는데 동작하지 않아요

설치할 때 실행되어야 하는 스크립트(`postinstall`)가 막혔을 수 있습니다. Bun은 보안을 위해 널리 쓰이는 패키지 외에는 설치 스크립트를 실행하지 않습니다([5장](./05_%ED%8C%A8%ED%82%A4%EC%A7%80_%EA%B4%80%EB%A6%AC.md#설치-스크립트는-기본으로-실행되지-않습니다)).

```bash
bun pm untrusted          # 스크립트가 막힌 패키지 확인
bun pm trust 패키지이름    # 확인한 패키지만 허용
```

### 다른 폴더에서 실행하면 파일을 못 찾아요 (`ENOENT`)

`Bun.file("data.json")`처럼 쓴 경로는 **명령을 실행한 폴더**를 기준으로 찾습니다. 코드 파일 옆의 파일을 찾으려면 `import.meta.dir`를 붙이세요([4장](./04_%EC%BD%94%EB%93%9C_%EC%8B%A4%ED%96%89%EA%B3%BC_%EC%9E%90%EB%8F%99_%EC%9E%AC%EC%8B%A4%ED%96%89.md#%EC%A7%80%EA%B8%88-%EC%8B%A4%ED%96%89-%EC%A4%91%EC%9D%B8-%ED%8C%8C%EC%9D%BC-%EC%A0%95%EB%B3%B4-importmeta)).

```ts
const data = await Bun.file(`${import.meta.dir}/data.json`).json();
```

### `bun.lockb` 파일이 있어요

Bun 1.2 이전에 쓰던 예전 잠금 파일입니다. `bun install --save-text-lockfile`로 `bun.lock`을 만든 뒤 `bun.lockb`를 지우세요.

### 빌드한 서버 코드를 실행하면 `... is not a function` 오류가 나요

`bun build`의 기본 대상이 브라우저라서 `node:fs` 같은 서버 기능이 빠진 것입니다. `--target=bun`을 붙여 다시 빌드하세요([10장](./10_%EB%B9%8C%EB%93%9C%EC%99%80_%EC%8B%A4%ED%96%89_%ED%8C%8C%EC%9D%BC.md#자주-쓰는-옵션)).

### `console.log`에 `[Object ...]`라고 나와요

`console.log`는 객체를 **세 단계까지만** 펼쳐 보여 주고, 더 깊은 곳은 `[Object ...]`로 줄입니다. 값이 없어진 것은 아닙니다.

```ts
console.log({ a: { b: { c: { d: 1 } } } });
```

```text
{
  a: {
    b: {
      c: [Object ...],
    },
  },
}
```

전부 보려면 `bun --console-depth=5 index.ts`처럼 깊이를 늘리거나, `console.log(JSON.stringify(값, null, 2))`로 JSON 문자열로 바꿔 출력하세요.

### 같은 와이파이의 휴대폰에서 내 서버에 접속하고 싶어요

주소창에 `localhost` 대신 내 컴퓨터의 IP 주소를 씁니다. macOS에서는 `ipconfig getifaddr en0`으로 확인합니다(예: `http://192.168.0.10:3000`). 접속되지 않으면 macOS 방화벽 설정을 확인하세요.

## Bun 설정 파일: bunfig.toml

명령마다 옵션을 붙이기 번거로우면 프로젝트 폴더에 `bunfig.toml`을 만들어 기본값을 정해 둘 수 있습니다. 초급 단계에서는 없어도 됩니다.

```toml
[test]
coverage = true      # bun test 할 때 항상 커버리지 표시 (--coverage와 같음)

[install]
exact = true         # bun add 할 때 항상 정확한 버전으로 고정 (-E와 같음)
```

> 테스트 제한 시간은 `bunfig.toml`로 바꿀 수 없습니다. `bun test --timeout 10000`처럼 명령에 붙이세요.
