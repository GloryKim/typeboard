# 8. 테스트하기

Bun에는 테스트 실행기가 들어 있습니다. Jest와 거의 같은 문법이라 따로 설치할 것이 없습니다.

## 테스트할 코드

`math.ts`:

```ts
export function add(a: number, b: number): number {
  return a + b;
}
```

## 테스트 파일 만들기

파일 이름이 `.test.ts`(또는 `_test.ts`, `.spec.ts`)로 끝나면 Bun이 테스트 파일로 인식합니다.

`math.test.ts`:

```ts
import { describe, expect, test } from "bun:test";
import { add } from "./math";

describe("add", () => {
  test("두 수를 더한다", () => {
    expect(add(1, 2)).toBe(3);
  });

  test("음수도 더한다", () => {
    expect(add(-1, -2)).toBe(-3);
  });
});
```

| 이름 | 뜻 |
|---|---|
| `describe("이름", ...)` | 관련된 테스트를 묶는 그룹 |
| `test("이름", ...)` | 테스트 하나 |
| `expect(실제값).toBe(기대값)` | "실제값이 기대값과 같아야 한다" |

## 실행하기

```bash
bun test
```

## 실패하면 이렇게 보입니다

기대값을 일부러 틀리게 `toBe(3)`으로 바꾸고 실행하면, 어느 줄에서 무엇이 달랐는지 보여 줍니다.

```text

                             ^

```

`Expected`는 기대한 값, `Received`는 실제로 나온 값입니다.

## 자주 쓰는 비교 함수

| 함수 | 확인하는 것 |
|---|---|
| `toBe(값)` | 값이 정확히 같다 (숫자, 문자열 등) |
| `toEqual(객체)` | 객체나 배열의 **내용**이 같다 |
| `toBeTruthy()` / `toBeFalsy()` | 참/거짓으로 취급되는 값이다 |
| `toContain(항목)` | 배열이나 문자열에 항목이 들어 있다 |
| `toThrow()` | 함수가 오류를 던진다 |
| `toBeNull()` / `toBeUndefined()` | 값이 `null` / `undefined`이다 |
| `toHaveLength(n)` | 배열이나 문자열의 길이가 n이다 |
| `toBeGreaterThan(n)` | n보다 크다 (`toBeLessThan`도 있음) |
| `not.toBe(값)` | 앞에 `not`을 붙이면 반대를 확인 |

```ts
expect({ name: "철수" }).toEqual({ name: "철수" }); // 통과
expect([1, 2, 3]).toContain(2);                      // 통과
expect(() => JSON.parse("{")).toThrow();             // 통과
expect("안녕").toHaveLength(2);                      // 통과
expect(1 + 1).not.toBe(3);                           // 통과
```

### toBe와 toEqual의 차이

`toBe`는 **같은 것인지**, `toEqual`은 **내용이 같은지**를 봅니다. 객체와 배열은 내용이 같아도 따로 만들면 다른 것이라서 `toBe`가 실패합니다.

```ts
expect({ a: 1 }).toEqual({ a: 1 }); // 통과: 내용이 같음
expect({ a: 1 }).toBe({ a: 1 });    // 실패: 서로 다른 객체
```

숫자, 문자열, `true`/`false`는 `toBe`, 객체와 배열은 `toEqual`을 쓴다고 기억하면 됩니다.

## 비동기 코드 테스트

`fetch`, 파일 읽기처럼 `await`가 필요한 코드는 테스트 함수에 `async`를 붙이고 `await`로 기다립니다.

```ts
test("비동기 결과를 기다린다", async () => {
  const value = await Promise.resolve(3);
  expect(value).toBe(3);
});
```

- 테스트 하나는 **기본 5초** 안에 끝나야 합니다. 넘으면 `this test timed out after 5000ms.`로 실패합니다.
- 오래 걸리는 테스트는 세 번째 인자로 시간을 늘립니다: `test("이름", async () => { ... }, 10_000)`
- 전체 기본값을 바꾸려면 `bun test --timeout 10000`을 씁니다.

## 잠시 건너뛰기, 이것만 실행하기

| 쓰는 법 | 동작 | 출력 |
|---|---|---|
| `test.skip("이름", ...)` | 실행하지 않고 건너뜀 | `(skip) 이름` |
| `test.todo("이름")` | 나중에 쓸 테스트라고 표시만 함 | `(todo) 이름` |
| `test.only("이름", ...)` | 같은 파일에서 이 테스트만 실행 | 나머지는 실행 안 됨 |

> `test.only`를 지우지 않고 올리면 다른 테스트가 계속 실행되지 않습니다. 확인이 끝나면 꼭 `only`를 지우세요.

## 테스트 전후 준비: beforeEach / afterEach

| 함수 | 언제 실행 |
|---|---|
| `beforeEach(fn)` | 각 테스트 **직전마다** |
| `afterEach(fn)` | 각 테스트 **직후마다** |
| `beforeAll(fn)` / `afterAll(fn)` | 파일(또는 `describe`)의 테스트 전체 시작 전 / 끝난 뒤 한 번 |

테스트마다 새 데이터를 준비해서 테스트끼리 영향을 주지 않게 할 때 씁니다. 실제 사용 예는 [14장 예제 17](./14_%EC%98%88%EC%A0%9C_%EB%8D%B0%EC%9D%B4%ED%84%B0%EB%B2%A0%EC%9D%B4%EC%8A%A4_%ED%85%8C%EC%8A%A4%ED%8A%B8_%EB%B9%8C%EB%93%9C.md#예제-17-장바구니-테스트)에 있습니다.

## 가짜 함수로 바꿔 끼우기: mock, spyOn

"이 함수가 몇 번, 어떤 값으로 불렸는지" 확인하거나, `Math.random()`처럼 실행할 때마다 결과가 달라지는 함수를 고정하고 싶을 때 씁니다.

```ts
import { expect, mock, spyOn, test } from "bun:test";

test("mock: 불린 횟수와 값 확인", () => {
  const double = mock((x: number) => x * 2);
  double(1);
  double(5);

  expect(double).toHaveBeenCalledTimes(2);   // 두 번 불렸다
  expect(double).toHaveBeenCalledWith(5);    // 5로 불린 적이 있다
  expect(double.mock.results[1]?.value).toBe(10); // 두 번째 결과는 10
});

test("spyOn: 기존 함수를 잠시 바꾸기", () => {
  const spy = spyOn(Math, "random").mockReturnValue(0.5);
  expect(Math.random()).toBe(0.5); // 항상 0.5

  spy.mockRestore();               // 원래대로 되돌리기
  expect(Math.random()).not.toBe(0.5);
});
```

| 이름 | 하는 일 |
|---|---|
| `mock(함수)` | 원래 동작은 그대로 하면서 호출 기록을 남기는 함수를 만듦 |
| `spyOn(객체, "메서드")` | 이미 있는 메서드에 기록 기능을 붙임. `.mockReturnValue(값)`으로 결과를 고정 |
| `.mockRestore()` | `spyOn`으로 바꾼 메서드를 원래대로 되돌림. 다른 테스트에 영향을 주지 않도록 꼭 호출 |

인터넷에서 환율을 가져오는 함수를 가짜로 바꿔 테스트하는 예는 [14장 예제 17](./14_%EC%98%88%EC%A0%9C_%EB%8D%B0%EC%9D%B4%ED%84%B0%EB%B2%A0%EC%9D%B4%EC%8A%A4_%ED%85%8C%EC%8A%A4%ED%8A%B8_%EB%B9%8C%EB%93%9C.md#예제-17-장바구니-테스트)에 있습니다.

## 유용한 옵션

| 명령 | 설명 |
|---|---|
| `bun test --watch` | 파일을 저장할 때마다 테스트를 다시 실행 |
| `bun test math` | 파일 경로에 `math`가 들어간 테스트만 실행 |
| `bun test -t "음수"` | 이름에 `음수`가 들어간 테스트만 실행 |
| `bun test --coverage` | 코드의 몇 %가 테스트되었는지 표시 |
| `bun test --bail` | 첫 실패에서 멈춤 |
| `bun test --timeout 10000` | 테스트 하나의 제한 시간을 10초로 (기본 5초) |

> `bun test`를 실행하면 환경 변수 `NODE_ENV`가 `test`가 되고, `.env.test` 파일을 읽습니다([4장](./04_%EC%BD%94%EB%93%9C_%EC%8B%A4%ED%96%89%EA%B3%BC_%EC%9E%90%EB%8F%99_%EC%9E%AC%EC%8B%A4%ED%96%89.md#여러-개의-env-파일과-우선순위)).
