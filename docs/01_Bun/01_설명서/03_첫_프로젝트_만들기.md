# 3. 첫 프로젝트 만들기

## 프로젝트 생성

빈 폴더를 만들고 `bun init`을 실행합니다. `-y`는 모든 질문에 기본값으로 답하라는 뜻입니다.

```bash
mkdir my-app
cd my-app
bun init -y
```

출력 예시(일부):

```text
 + .gitignore
 + index.ts
 + tsconfig.json (for bun check and editor autocomplete)
 + README.md

To get started, run:

    bun run index.ts

To type check, run:

    bun check

bun install v1.4.3 (c6da4a4d3)
...
+ @types/bun@1.4.3
+ typescript@7.0.2

7 packages installed [1.58s]
```

- 파일을 만든 뒤 **패키지 설치(`bun install`)까지 자동으로** 합니다. 그래서 `bun.lock`과 `node_modules/`도 함께 생깁니다.
- Cursor 편집기의 터미널에서 실행하면 `.cursor/rules/use-bun-instead-of-node-vite-npm-pnpm.mdc` 파일도 생깁니다. Cursor의 AI에게 "이 프로젝트에서는 Node.js, npm 대신 Bun을 쓰라"고 알려 주는 규칙 파일입니다. 필요 없으면 지워도 됩니다.

## 생성된 파일 살펴보기

| 파일 | 역할 |
|---|---|
| `package.json` | 프로젝트 이름, 스크립트, 의존 패키지 목록 |
| `index.ts` | 시작 코드 (`console.log("Hello via Bun!");`) |
| `tsconfig.json` | TypeScript 설정. 편집기 자동완성과 `bun check`가 사용 |
| `bun.lock` | 설치된 패키지의 정확한 버전 기록. **직접 고치지 말고 Git에 함께 올리세요.** |
| `node_modules/` | 설치된 패키지 폴더. Git에 올리지 않습니다(`.gitignore`에 포함). |
| `.gitignore` | Git에 올리지 않을 파일 목록 |
| `README.md` | 프로젝트 설명 |

1.4.3에서 만든 `package.json`은 다음과 같습니다.

```json
{
  "name": "my-app",
  "module": "index.ts",
  "type": "module",
  "private": true,
  "scripts": {
    "typecheck": "bun check"
  },
  "devDependencies": {
    "@types/bun": "latest"
  },
  "peerDependencies": {
    "typescript": "^7"
  }
}
```

- `"module": "index.ts"`: 이 프로젝트의 시작 파일을 알려 주는 표시입니다. `bun run`이 이 값을 보고 실행하지는 않으므로, 실행할 때는 파일 이름을 직접 적습니다.
- `"type": "module"`: 이 프로젝트의 `.js` 파일을 ES 모듈(`import`/`export` 문법)로 다룬다는 뜻입니다. 주로 Node.js와 다른 도구를 위한 설정입니다. **Bun은 이 설정이 없어도** `.js`, `.ts` 어디서나 `import`/`export`와 예전 방식인 `require`를 모두 쓸 수 있습니다.
- `"typecheck": "bun check"`: **1.4.3부터** 자동으로 들어가는 스크립트입니다. `bun run typecheck`로 타입 검사를 합니다([9장](./09_%ED%83%80%EC%9E%85_%EA%B2%80%EC%82%AC.md)).
- `devDependencies`의 `@types/bun`: 편집기와 타입 검사가 `Bun.serve`, `Bun.file` 같은 Bun 전용 기능을 알아보게 해 주는 타입 정보입니다. 실행에는 필요 없습니다.
- `peerDependencies`의 `typescript`: 이 프로젝트가 TypeScript와 함께 쓰인다는 표시입니다. Bun은 TypeScript 패키지 없이도 `.ts`를 실행합니다.

### tsconfig.json에서 알아 둘 설정

`tsconfig.json`은 **타입 검사와 편집기**가 읽는 설정입니다. Bun이 코드를 실행할 때는 대부분 쓰이지 않습니다. 초급 단계에서는 고칠 필요가 없지만, 다음 설정은 타입 검사 결과에 영향을 주니 알아 두세요.

| 설정 | 뜻 |
|---|---|
| `"strict": true` | 엄격한 타입 검사. `null`일 수 있는 값을 그냥 쓰면 오류로 알려 줌 |
| `"noUncheckedIndexedAccess": true` | 배열에서 `list[0]`처럼 꺼낸 값을 "없을 수도 있음(`undefined`)"으로 봄 |
| `"verbatimModuleSyntax": true` | 타입만 불러올 때는 `import type { User } from "./types"`처럼 `type`을 붙여야 함 |
| `"noEmit": true` | 타입 검사만 하고 JavaScript 파일은 만들지 않음 |
| `"types": ["bun"]` | `@types/bun`의 타입 정보(`Bun.serve` 등)를 사용 |

뒤의 두 설정 때문에 처음에 자주 만나는 오류와 해결법은 [9장](./09_%ED%83%80%EC%9E%85_%EA%B2%80%EC%82%AC.md#처음에-자주-만나는-타입-오류)에 있습니다.

## 실행하기

```bash
bun run index.ts
```

```text
Hello via Bun!
```

`run`은 생략할 수 있습니다.

```bash
bun index.ts
```

## 코드 고쳐 보기

`index.ts`를 다음처럼 바꿔 보세요. TypeScript 타입 표기(`: string`)가 있어도 그대로 실행됩니다.

```ts
function greet(name: string): string {
  return `안녕하세요, ${name}님!`;
}

console.log(greet("Bun"));
```

```bash
bun index.ts
```

```text
안녕하세요, Bun님!
```

## 파일 나누기: export와 import

코드가 길어지면 여러 파일로 나눕니다. 다른 파일에서 쓰게 할 것에는 `export`를 붙이고, 쓰는 쪽에서 `import`로 불러옵니다.

`math.ts`:

```ts
export const PI = 3.14;

export function add(a: number, b: number): number {
  return a + b;
}

export default function circleArea(r: number): number {
  return PI * r * r;
}
```

`index.ts`:

```ts
import circleArea, { add, PI } from "./math";
import * as math from "./math";

console.log(add(1, 2));
console.log(PI, circleArea(2));
console.log(math.add(10, 20));
```

```bash
bun index.ts
```

```text
3
3.14 12.56
30
```

| 쓰는 법 | 뜻 |
|---|---|
| `export function add` | 이름을 붙여 내보내기. 한 파일에 여러 개 가능 |
| `export default function ...` | 기본으로 내보내기. 파일당 하나 |
| `import { add, PI } from "./math"` | 이름으로 내보낸 것은 **같은 이름으로 중괄호 안에** 적기 |
| `import circleArea from "./math"` | 기본 내보내기는 중괄호 없이, 이름은 마음대로 |
| `import * as math from "./math"` | 전부를 `math.add`처럼 묶어서 가져오기 |

- `"./math"`의 `./`는 "**지금 파일과 같은 폴더**"라는 뜻입니다. `./`가 없으면(`"zod"`처럼) 설치한 패키지를 찾습니다.
- Bun에서는 확장자(`.ts`)를 생략해도 됩니다. `"./math.ts"`라고 써도 됩니다.
- 오래된 Node.js 코드에서 보는 `const { add } = require("./math")`도 Bun에서는 그대로 동작합니다. 새로 작성할 때는 `import`를 쓰세요.

## 다른 사람이 만든 템플릿으로 시작하기: bun create

`bun create`는 npm이나 GitHub에 올라온 템플릿으로 프로젝트를 만듭니다.

```bash
bun create vite my-web     # Vite 프로젝트 (create-vite 템플릿 실행)
bun create hono my-api     # Hono 웹 서버 프로젝트
```

`bun create 이름`은 `create-이름` 패키지를 찾아 실행합니다. `npm create`, `npx create-...`와 같은 역할입니다.

## bun init의 다른 템플릿

| 명령 | 만들어지는 프로젝트 |
|---|---|
| `bun init -y` | 기본 TypeScript 프로젝트 (이 장에서 만든 것) |
| `bun init --react` | React 프로젝트 |
| `bun init --react=tailwind` | React + Tailwind CSS 프로젝트 |
| `bun init --minimal` | 타입 정의만 설정 |

초급 단계에서는 기본 프로젝트로 충분합니다.
