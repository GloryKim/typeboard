## 1. rusqlite란 · SQLite와의 관계

### 개념

| 이름 | 무엇인지 |
|---|---|
| **SQLite** | 임베디드 RDBMS 엔진 + SQL 방언 + 파일 포맷 (`.db`) |
| **sqlite3 CLI** | 터미널에서 SQL을 치는 공식 셸 (`sqlite3 app.db`) |
| **libsqlite3** | C API (`sqlite3_open`, `sqlite3_prepare_v2`, …) |
| **rusqlite** | 그 C API를 **안전한 Rust 래퍼**로 감싼 크레이트 |

한 줄:

> **SQL·DB 파일·엔진은 SQLite 그대로.**  
> rusqlite는 “Rust에서 그걸 어떻게 열고, 바인딩하고, 행을 읽고, 트랜잭션을 닫느냐”의 API다.

```text
Rust 앱
  └─ rusqlite (Connection / Statement / Transaction)
       └─ libsqlite3 (bundled 또는 시스템)
            └─ app.db 파일 (또는 :memory:)
```

### 설명

- `CREATE TABLE` / `SELECT` / 인덱스 / 트리거 / CTE 문법은 **SQLite 문서가 진실**.
- rusqlite를 배운다고 SQL이 바뀌는 게 아니다.  
  바뀌는 것은 **문자열 연결로 값을 넣지 않기**, **타입 변환**, **RAII 트랜잭션**, **스레드 모델**이다.

### 체크포인트

- [ ] “rusqlite = 새 DB”가 아니라 “SQLite Rust 바인딩”임을 설명
- [ ] CLI로 만든 `.db`를 rusqlite로 그대로 열 수 있음

## 2. SQLite vs rusqlite — 차이 한눈에

### 같은 것

| 항목 | 내용 |
|---|---|
| SQL 문법 | SQLite SQL (거의) 그대로 |
| 파일 포맷 | 동일 `.db` / WAL 파일 |
| 타입 시스템 | 동적 타입 + type affinity (INTEGER/TEXT/BLOB/REAL/NUMERIC) |
| 동시성 모델 | 같은 DB 파일에 대한 **쓰기 잠금**; WAL이면 **읽기 동시성↑** |
| PRAGMA | `PRAGMA journal_mode=WAL;` 등 동일 (연결/파일 종류에 따라 실제 모드 값은 다를 수 있음) |

### 다른 것 (실무에서 중요)

| 주제 | SQLite CLI / C | rusqlite |
|---|---|---|
| 값 넣기 | `'...'` 리터럴 또는 `?` 바인딩 | **바인딩** (`params!` / 튜플 / named / 배열 등). 값에 `format!` 금지 |
| 결과 읽기 | 표로 출력 / `sqlite3_column_*` | `row.get::<T>(i)?` → Rust 타입 |
| NULL | SQL `NULL` | Rust `Option<T>` (`None` ↔ NULL) |
| 트랜잭션 끝 | `COMMIT`/`ROLLBACK` 직접 | `Transaction` drop 시 **기본 ROLLBACK**, `commit()` 명시 |
| 중첩 트랜잭션 | `SAVEPOINT` / 실수하기 쉬움 | `transaction()`은 `&mut self`로 중첩 컴파일 차단 + `savepoint()` |
| 에러 | 정수 코드 + 메시지 | `rusqlite::Error` / `Result<T>` |
| 스레드 | 문서 읽고 알아서 | `Connection: Send + !Sync` → 동시 공유 금지, `Mutex`/`r2d2` |
| async | 없음 (블로킹 I/O) | rusqlite도 **동기**. Tokio에선 `spawn_blocking` 또는 sqlx 검토 |
| 확장 로딩 | `.load` / C API | feature `load_extension` + 가드 |
| SQLite 바이너리 | 시스템에 설치 | 보통 **`bundled`**로 소스 빌드해 내장 |

### CLI 한 줄 ↔ Rust 한 블록

```sql
-- sqlite3 app.db
INSERT INTO person (name, age) VALUES ('kim', 30);
SELECT id, name FROM person WHERE age > 20;
```

```rust
use rusqlite::{params, Connection, Result};

fn demo(conn: &Connection) -> Result<()> {
    conn.execute(
        "INSERT INTO person (name, age) VALUES (?1, ?2)",
        params!["kim", 30],
    )?;

    let mut stmt = conn.prepare("SELECT id, name FROM person WHERE age > ?1")?;
    let rows = stmt.query_map(params![20], |row| {
        Ok((row.get::<_, i64>(0)?, row.get::<_, String>(1)?))
    })?;

    for r in rows {
        println!("{:?}", r?);
    }
    Ok(())
}
```

- [ ] “SQL은 같고 API만 다르다”를 표로 설명
- [ ] drop = rollback 기본 동작을 기억

## 3. 프로젝트 준비

### Cargo.toml (권장)

```toml
[package]
name = "rusqlite-lab"
version = "0.1.0"
edition = "2021"

[dependencies]
rusqlite = { version = "0.40", features = ["bundled"] }

# 선택
# rusqlite = { version = "0.40", features = ["bundled", "chrono", "serde_json", "backup", "functions"] }
# r2d2 = "0.8"
# r2d2_sqlite = "0.35"  # crates.io에서 rusqlite 0.40과 맞는 버전 확인
# thiserror = "2"
```

| feature | 용도 |
|---|---|
| `bundled` | SQLite 소스를 같이 빌드 (배포·CI에서 시스템 lib 의존 ↓) **실무 기본 추천** |
| `chrono` | `DateTime` ↔ SQLite 변환 |
| `serde_json` | `serde_json::Value` 저장 |
| `fallible_uint` | `u64`/`usize` ToSql·FromSql (범위 검사) |
| `backup` | Online backup API |
| `functions` | 커스텀 SQL 함수 |
| `load_extension` | 확장 로드 |
| `column_decltype` 등 | 메타데이터 보강 |

시스템 SQLite만 쓰려면 `bundled` 없이 `libsqlite3-sys`가 링크한다.  
버전·헤더 불일치가 잦아 **앱/학습용은 bundled가 안전**하다.

참고: `bundled`의 `libsqlite3-sys`는 컴파일 옵션으로 **`SQLITE_DEFAULT_FOREIGN_KEYS=1`** 을 켠다.  
즉 bundled면 FK가 기본 ON인 경우가 많다. 시스템/CLI SQLite는 기본 OFF인 경우가 많아 **이식성을 위해 앱에서 `PRAGMA foreign_keys=ON`을 명시**하는 편이 안전하다.

### 최소 main

```rust
use rusqlite::{Connection, Result};

fn main() -> Result<()> {
    let conn = Connection::open_in_memory()?;
    println!("sqlite {}", rusqlite::version());

    // execute는 “결과 행이 없는” 문장용. SELECT에 쓰면 에러:
    // "Execute returned results - did you mean to call query?"
    let one: i64 = conn.query_row("SELECT 1", [], |r| r.get(0))?;
    assert_eq!(one, 1);
    Ok(())
}
```

- [ ] `features = ["bundled"]`로 `cargo run` 성공

## 4. Connection — 열기 / 메모리 / 플래그

### 파일 / 메모리

```rust
use rusqlite::{Connection, OpenFlags, Result};

fn open_examples() -> Result<()> {
    // 파일 (없으면 생성)
    let _a = Connection::open("app.db")?;

    // 프로세스 전용 메모리 DB
    let _b = Connection::open_in_memory()?;

    // 읽기 전용 + 없으면 실패
    let flags = OpenFlags::SQLITE_OPEN_READ_ONLY;
    let _c = Connection::open_with_flags("app.db", flags)?;

    // 읽기/쓰기 + 생성 + URI
    let flags = OpenFlags::SQLITE_OPEN_READ_WRITE
        | OpenFlags::SQLITE_OPEN_CREATE
        | OpenFlags::SQLITE_OPEN_URI;
    let _d = Connection::open_with_flags("file:app.db?mode=rwc", flags)?;

    Ok(())
}
```

### CLI와의 대응

| CLI | rusqlite |
|---|---|
| `sqlite3 app.db` | `Connection::open("app.db")` |
| `:memory:` | `Connection::open_in_memory()` |
| 여러 DB attach | `ATTACH DATABASE 'other.db' AS other;` — SQL 그대로 `execute` |

### 설명

- **경로 하나 = 보통 커넥션 하나(또는 풀).** 같은 파일을 여러 프로세스가 열 수는 있지만, 쓰기 충돌·busy는 SQLite 규칙대로.
- `Connection`은 **`Send`이지만 `Sync`가 아니다.** 여러 스레드가 **동시에** 같은 커넥션을 쓰면 안 된다 → `Mutex`로 직렬화하거나 스레드/요청당 커넥션(풀). → 12절.
- `Connection::open` 기본 플래그 대략:  
  `READ_WRITE | CREATE | URI | NO_MUTEX`  
  (`NO_MUTEX` = SQLite multi-thread 모드. rusqlite가 `!Sync`로 안전성을 맞춘다.)

### 공유 메모리 DB (고급)

일반 `open_in_memory()`는 **그 커넥션만** 보는 사설 메모리 DB다.  
여러 커넥션이 같은 메모리 DB를 쓰려면 URI 예:

```rust
let flags = OpenFlags::SQLITE_OPEN_READ_WRITE
    | OpenFlags::SQLITE_OPEN_CREATE
    | OpenFlags::SQLITE_OPEN_URI;
let a = Connection::open_with_flags("file:memdb1?mode=memory&cache=shared", flags)?;
let b = Connection::open_with_flags("file:memdb1?mode=memory&cache=shared", flags)?;
// a와 b가 같은 인메모리 DB를 공유 (프로세스 내)
```

## 5. 첫 CRUD

### 스키마 + INSERT + SELECT

```rust
use rusqlite::{params, Connection, Result};

#[derive(Debug)]
struct Person {
    id: i64,
    name: String,
    age: i32,
    bio: Option<String>,
}

fn crud() -> Result<()> {
    let conn = Connection::open_in_memory()?;

    conn.execute(
        "CREATE TABLE person (
            id   INTEGER PRIMARY KEY,
            name TEXT NOT NULL,
            age  INTEGER NOT NULL,
            bio  TEXT
        )",
        [], // 파라미터 없음: () 또는 []
    )?;

    conn.execute(
        "INSERT INTO person (name, age, bio) VALUES (?1, ?2, ?3)",
        params!["kim", 30, Option::<String>::None],
    )?;

    // last_insert_rowid — CLI의 last_insert_rowid()와 동일 개념
    let id = conn.last_insert_rowid();

    let person = conn.query_row(
        "SELECT id, name, age, bio FROM person WHERE id = ?1",
        params![id],
        |row| {
            Ok(Person {
                id: row.get(0)?,
                name: row.get(1)?,
                age: row.get(2)?,
                bio: row.get(3)?,
            })
        },
    )?;

    println!("{person:?}");

    let n = conn.execute(
        "UPDATE person SET age = ?1 WHERE id = ?2",
        params![31, id],
    )?;
    assert_eq!(n, 1); // 변경된 행 수 (sqlite3_changes)

    conn.execute("DELETE FROM person WHERE id = ?1", params![id])?;
    Ok(())
}
```

### 설명

| 메서드 | 역할 |
|---|---|
| `execute` | 한 문장 준비+실행. **변경 행 수** `usize` 반환. **결과 행이 하나라도 있으면 에러** (`SELECT 1` 등). 결과 0행인 SELECT는 Ok(0)일 수 있으나, SELECT는 `query*`를 쓰는 것이 맞다 |
| `last_insert_rowid` | 이 커넥션에서 마지막 INSERT의 rowid |
| `query_row` | 성공 시 **첫 행** 사용, 추가 행은 **무시**. 0행이면 에러 |
| `query_one` | **정확히 한 행** — 0행·2행+ 모두 에러 |

CLI에서 `SELECT changes();`에 해당하는 정보가 `execute` 반환값이다.

`INTEGER PRIMARY KEY` 컬럼에 NULL/생략으로 INSERT하면 rowid가 채워진다.  
`AUTOINCREMENT`는 “한 번 쓴 id를 재사용하지 않음” 등 추가 규칙이 있다 (보통 PK만으로 충분).

### 체크포인트

- [ ] CREATE → INSERT → SELECT → UPDATE → DELETE 왕복
- [ ] `bio: None`이 SQL NULL로 들어가는지 확인

## 6. 파라미터 바인딩 (SQL 인젝션 방지)

### 개념

SQLite도 `?`, `?1`, `:name`, `@name`, `$name` 바인딩을 지원한다.  
rusqlite는 이걸 Rust에서 강제하기 쉽게 만든다.

**하지 말 것:**

```rust
// 절대 금지
let sql = format!("SELECT * FROM person WHERE name = '{}'", user_input);
conn.execute(&sql, [])?;
```

**할 것:**

```rust
use rusqlite::{named_params, params, Connection, Result};

fn bind_demo(conn: &Connection, name: &str, min_age: i32) -> Result<()> {
    // 위치 파라미터 (?1, ?2, ...) — 1부터
    conn.execute(
        "INSERT INTO person (name, age) VALUES (?1, ?2)",
        params![name, min_age],
    )?;

    // 튜플도 Params
    conn.execute(
        "INSERT INTO person (name, age) VALUES (?1, ?2)",
        (name, min_age),
    )?;

    // 이름 파라미터
    let mut stmt = conn.prepare(
        "SELECT id FROM person WHERE name = :name AND age >= :min_age",
    )?;
    let _id: i64 = stmt.query_row(
        named_params! {
            ":name": name,
            ":min_age": min_age,
        },
        |row| row.get(0),
    )?;

    Ok(())
}
```

### 동적 길이 파라미터

```rust
use rusqlite::{params_from_iter, Connection, Result};

fn delete_many(conn: &Connection, ids: &[i64]) -> Result<usize> {
    if ids.is_empty() {
        return Ok(0); // `IN ()` 는 SQLite에서 문법 에러
    }
    // IN (?, ?, ?) 를 동적으로 — placeholder는 "?"만, 값은 바인딩
    let placeholders = (0..ids.len()).map(|_| "?").collect::<Vec<_>>().join(", ");
    let sql = format!("DELETE FROM person WHERE id IN ({placeholders})");
    conn.execute(&sql, params_from_iter(ids.iter()))
}
```

`format!`로 **SQL 조각(? 개수)** 만 만들고, 실제 id 값은 반드시 바인딩한다.  
빈 슬라이스는 위에서 early-return 한다 (`IN ()` 불가).

### CLI와의 차이

| CLI | rusqlite |
|---|---|
| 사람이 리터럴을 직접 입력 | 앱은 **항상 바인딩** |
| `.parameter` 등 | `params!` / `named_params!` |

### 주의 (공식 문서)

이름 파라미터를 **일부만** 바인딩하면, 예전에 바인딩된 값이 남거나 한 번도 안 묶인 것은 NULL이 될 수 있다.  
가능하면 **매 실행마다 필요한 이름을 모두** 넘긴다.

### 체크포인트

- [ ] `params!` / `named_params!` / 튜플 각각 한 번씩
- [ ] `format!`로 값 넣기 유혹을 거절

## 7. 타입 매핑 — ToSql / FromSql / NULL

### SQLite 타입 vs Rust

SQLite 저장 클래스는 대략 5종: `NULL`, `INTEGER`, `REAL`, `TEXT`, `BLOB`.

| Rust (자주) | SQLite | 비고 |
|---|---|---|
| `i32` / `i64` | INTEGER | PK·rowid는 `i64` 추천 |
| `f64` | REAL | |
| `bool` | INTEGER 0/1 | |
| `String` / `&str` | TEXT | |
| `Vec<u8>` / `&[u8]` | BLOB | |
| `Option<T>` | NULL 또는 T | SQL **NULL** ↔ `None` |
| `u32` 등 (작은 부호 없는 정수) | INTEGER | |
| `u64` / `usize` | INTEGER | 기본 `FromSql` **없음**. feature `fallible_uint` 필요 (범위 밖이면 에러) |
| `chrono::DateTime` | TEXT/INTEGER 등 | feature `chrono` |
| `serde_json::Value` | TEXT | feature `serde_json` |

### 동적 값

```rust
use rusqlite::{Connection, Result};

fn dynamic(conn: &Connection) -> Result<()> {
    conn.execute("CREATE TABLE kv (k TEXT PRIMARY KEY, v)", [])?;
    // 컬럼 타입을 비워도 SQLite는 허용 (affinity 느슨)
    conn.execute("INSERT INTO kv VALUES (?1, ?2)", ("a", 1i64))?;
    conn.execute("INSERT INTO kv VALUES (?1, ?2)", ("b", "hello"))?;

    let v: i64 = conn.query_row("SELECT v FROM kv WHERE k = 'a'", [], |r| r.get(0))?;
    let s: String = conn.query_row("SELECT v FROM kv WHERE k = 'b'", [], |r| r.get(0))?;
    assert_eq!(v, 1);
    assert_eq!(s, "hello");
    Ok(())
}
```

고급: `rusqlite::types::{Value, ValueRef, ToSql, FromSql}` 로 동적 타입·커스텀 매핑.

### NULL

```rust
fn nulls(conn: &Connection) -> Result<()> {
    // INSERT NULL
    conn.execute(
        "INSERT INTO person (name, age, bio) VALUES (?1, ?2, ?3)",
        ("x", 1, Option::<String>::None),
    )?;

    let bio: Option<String> = conn.query_row(
        "SELECT bio FROM person WHERE name = 'x'",
        [],
        |r| r.get(0),
    )?;
    assert!(bio.is_none());

    let err = conn.execute(
        "INSERT INTO person (name, age) VALUES (?1, ?2)",
        (Option::<String>::None, 1),
    );
    assert!(err.is_err());
    Ok(())
}
```

| CLI | rusqlite |
|---|---|
| 타입이 느슨해서 숫자처럼 보이는 텍스트도 섞임 | Rust로 꺼낼 때 `FromSql`이 **엄격** → 잘못된 타입이면 에러 |

## 9. 한 행 / 없을 수 있는 행

```rust
use rusqlite::{params, Connection, OptionalExtension, Result};

fn find(conn: &Connection, id: i64) -> Result<Option<String>> {
    // query_row: 0행 → Err(QueryReturnedNoRows)
    // 2행 이상 → 첫 행만 사용, 나머지는 무시 (!!)
    let name = conn
        .query_row(
            "SELECT name FROM person WHERE id = ?1",
            params![id],
            |row| row.get(0),
        )
        .optional()?; // QueryReturnedNoRows → Ok(None)

    Ok(name)
}

fn must_exist(conn: &Connection, id: i64) -> Result<String> {
    conn.query_row(
        "SELECT name FROM person WHERE id = ?1",
        params![id],
        |row| row.get(0),
    )
}

/// 정확히 1행을 강제할 때 (0행·2행+ 모두 에러)
fn exactly_one(conn: &Connection, email: &str) -> Result<i64> {
    conn.query_one(
        "SELECT id FROM person WHERE email = ?1",
        params![email],
        |row| row.get(0),
    )
}
```

| API | 0행 | 1행 | 2행+ |
|---|---|---|---|
| `query_row` | `QueryReturnedNoRows` | Ok | **첫 행 Ok, 나머지 무시** |
| `query_row` + `.optional()` | Ok(None) | Ok(Some) | Ok(Some 첫 행), 나머지 무시 |
| `query_one` | `QueryReturnedNoRows` | Ok | `QueryReturnedMoreThanOneRow` |

“유일해야 하는” 조회(이메일·슬러그 등)는 **`query_one`**.  
“있으면 첫 행만”이면 `query_row` / `.optional()`.

CLI에서 “없으면 빈 결과”인 경우가 Rust에선 **에러 vs Option**을 명시해야 한다.

### 체크포인트

- [ ] 없는 id로 `optional()` → `None`
- [ ] `query_row` vs `query_one` 차이를 표로 설명
- [ ] 2행이 나오는 SELECT에 `query_row`가 조용히 첫 행만 줌을 확인

## 10. 트랜잭션 · Savepoint · DropBehavior

### 개념 (SQLite와 동일 + RAII)

SQLite 트랜잭션: `BEGIN` → 작업 → `COMMIT` / `ROLLBACK`.

rusqlite:

```rust
use rusqlite::{Connection, Result, TransactionBehavior};

fn transfer(conn: &mut Connection, from: i64, to: i64, amount: i64) -> Result<()> {
    let tx = conn.transaction()?; // 기본 DEFERRED, drop 시 ROLLBACK

    let n = tx.execute(
        "UPDATE accounts SET balance = balance - ?1 WHERE id = ?2 AND balance >= ?1",
        (amount, from),
    )?;
    if n != 1 {
        // commit 없이 return → drop 시 rollback
        return Err(rusqlite::Error::StatementChangedRows(n));
    }

    let n = tx.execute(
        "UPDATE accounts SET balance = balance + ?1 WHERE id = ?2",
        (amount, to),
    )?;
    if n != 1 {
        return Err(rusqlite::Error::StatementChangedRows(n));
    }

    tx.commit()?; // 이걸 호출해야 커밋. 안 하면 drop = rollback
    Ok(())
}
```
### DropBehavior

```rust
use rusqlite::{Connection, DropBehavior, Result};

fn maybe_commit(conn: &mut Connection, ok: bool) -> Result<()> {
    let mut tx = conn.transaction()?;
    tx.execute("UPDATE counters SET n = n + 1", [])?;

    if ok {
        tx.commit()?;
    } else {
        // 명시 rollback 또는 그냥 drop
        tx.rollback()?;
    }
    Ok(())
}

fn commit_on_drop(conn: &mut Connection) -> Result<()> {
    let mut tx = conn.transaction()?;
    tx.set_drop_behavior(DropBehavior::Commit); // 위험할 수 있음 — 의도 명확할 때만
    tx.execute("UPDATE counters SET n = n + 1", [])?;
    // commit() 없이도 drop 시 커밋
    Ok(())
}
```

### 동작 모드

```rust
fn behaviors(conn: &mut Connection) -> Result<()> {
    let _ = conn.transaction_with_behavior(TransactionBehavior::Deferred)?;
    // Deferred: 잠금은 필요할 때
    // Immediate: BEGIN IMMEDIATE — 쓰기 잠금 예약
    // Exclusive: 더 강한 잠금
    Ok(())
}
```

### Savepoint (중첩)

```rust
fn with_savepoint(conn: &mut Connection) -> Result<()> {
    let mut tx = conn.transaction()?; // savepoint()는 &mut 필요
    {
        let sp = tx.savepoint()?;
        sp.execute("INSERT INTO person (name, age) VALUES ('temp', 0)", [])?;
        // sp drop → 기본 rollback of savepoint
        // sp.rollback()?; // 명시해도 동일
    }
    tx.execute("INSERT INTO person (name, age) VALUES ('keep', 1)", [])?;
    tx.commit()
}
```

### CLI / C와의 차이

| SQLite | rusqlite |
|---|---|
| `BEGIN;` … `COMMIT;` | `transaction()` + `commit()` |
| 깜빡하고 커밋 안 함 | **깜빡하면 rollback** (안전 쪽 기본값) |
| 중첩 BEGIN 실수 | `&mut self`로 `transaction()` 중첩을 컴파일 타임에 제한 |
| `SAVEPOINT` | `savepoint()` |

`unchecked_transaction(&self)`는 런타임에 중첩을 허용하지만 실수 여지가 있다. 가능하면 `&mut` API를 쓴다.

### 체크포인트

- [ ] commit 없이 drop → 데이터 안 남음 확인
- [ ] 이체처럼 두 UPDATE를 한 트랜잭션으로

## 11. PRAGMA · WAL · busy timeout

### 자주 쓰는 PRAGMA

```rust
use rusqlite::{Connection, Result};

fn pragmas(conn: &Connection) -> Result<()> {
    // WAL: 파일 DB에서 읽기 동시성↑. :memory: 에서는 journal_mode가 "memory"로 남는 경우가 많다.
    conn.pragma_update(None, "journal_mode", "WAL")?;

    // 정상 종료 시 fsync 수준 (성능↔안전) — WAL과 자주 같이 씀
    conn.pragma_update(None, "synchronous", "NORMAL")?;

    // 잠금 대기. rusqlite 새 커넥션 기본은 약 5000ms (변경될 수 있음 — 문서 기준).
    // 0으로 두면 busy handler 끔 → 잠금 시 즉시 SQLITE_BUSY.
    conn.busy_timeout(std::time::Duration::from_secs(5))?;

    // FK 강제 — 이식성을 위해 명시 권장
    // (bundled libsqlite3-sys는 DEFAULT_FOREIGN_KEYS=1 인 경우가 많음.
    //  시스템/CLI SQLite는 기본 OFF인 경우가 많음.)
    conn.pragma_update(None, "foreign_keys", true)?;

    let mode: String = conn.pragma_query_value(None, "journal_mode", |row| row.get(0))?;
    println!("journal_mode={mode}");
    Ok(())
}
```

### CLI와의 대응

```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;
```

```rust
conn.pragma_update(None, "journal_mode", "WAL")?;
conn.pragma_update(None, "foreign_keys", true)?;
```

값을 **읽는** PRAGMA(`PRAGMA foreign_keys;` 등)는 결과 행이 나와 `execute`로 치면  
`Execute returned results` 에러가 날 수 있다. → `pragma_query_value` / `pragma_query` 사용.  
값을 **설정**할 때는 `pragma_update`가 안전하다.
### 외래키 — 엔진/빌드별 기본값이 다름

| 환경 | `PRAGMA foreign_keys` 기본 (흔히) |
|---|---|
| sqlite3 CLI / 많은 시스템 lib | **OFF** |
| rusqlite `bundled` (`libsqlite3-sys`) | 컴파일 플래그로 **ON**인 경우가 많음 |

어느 쪽이든 **연결마다 명시적으로 ON** 하는 습관이 안전하다.  
CLI에서 ON이어도, 다른 방식으로 연 Connection에는 다시 확인한다.

### 체크포인트

- [ ] WAL + busy_timeout + foreign_keys를 앱 시작 시 설정하는 함수 만들기

## 12. 동시성 — 스레드 · 풀 · async

### SQLite 규칙 (엔진)

- 한 `sqlite3*` 핸들을 **여러 스레드가 동시에** 쓰는 것은 (모드에 따라) 위험하거나 금지에 가깝다.
- rusqlite는 `Connection: !Sync`로 **동시에 같은 Connection을 쓰는 것을 타입으로 막는다.**
- 여러 **커넥션**으로 같은 파일은 가능. 쓰기는 잠금, WAL이면 읽기는 비교적 여유.
- `SQLITE_BUSY` — 다른 연결이 잠금 중 (기본 busy_timeout ≈ 5s 대기 후 실패 가능).

### rusqlite에서

```rust
use rusqlite::Connection;
use std::sync::Mutex;

// 단순: 커넥션 하나를 Mutex로 보호
struct Db {
    conn: Mutex<Connection>,
}

impl Db {
    fn with<R>(&self, f: impl FnOnce(&Connection) -> rusqlite::Result<R>) -> rusqlite::Result<R> {
        let conn = self.conn.lock().expect("db lock");
        f(&conn)
    }
}
```

또는 **커넥션 풀** (`r2d2` + `r2d2_sqlite`): 요청마다 커넥션 checkout.

### async (Tokio / Axum)

rusqlite는 **블로킹**. 이벤트 루프에서 직접 호출하면 스레드를 멈춘다.

```rust
// 스케치
async fn handler(db: Arc<Mutex<Connection>>) -> Result<String, String> {
    let db = db.clone();
    tokio::task::spawn_blocking(move || {
        let conn = db.lock().unwrap();
        conn.query_row("SELECT name FROM person WHERE id = 1", [], |r| {
            r.get::<_, String>(0)
        })
        .map_err(|e| e.to_string())
    })
    .await
    .map_err(|e| e.to_string())?
}
```

진짜 async SQL이 필요하면 **sqlx** (`sqlite` feature)도 선택지다.  
“같은 SQLite 파일”이지만 API·매크로·런타임 모델이 다르다.

| | rusqlite | sqlx (sqlite) |
|---|---|---|
| I/O | 동기 | async |
| 매크로 | 거의 없음 | `query!` 등 |
| 무게 | 얇은 래퍼 | 런타임·마이그레이션 생태계 |
| 적합 | CLI, 임베디드, 단순 서버 | Tokio 중심 서비스 |

### 체크포인트

- [ ] `Connection`을 스레드 간에 잠금 없이 공유하지 않기
- [ ] async 경로에서 `spawn_blocking` 또는 풀 패턴 하나 고르기

## 13. 스키마 · 마이그레이션 패턴

SQLite/CLI와 동일한 SQL을 쓰되, 앱 부팅 시 적용한다.

```rust
use rusqlite::{Connection, Result};

const MIGRATIONS: &[&str] = &[
    // v1
    "CREATE TABLE IF NOT EXISTS schema_migrations (
        version INTEGER PRIMARY KEY,
        applied_at TEXT NOT NULL DEFAULT (datetime('now'))
    );",
    // v2 — 실제 스키마
    "CREATE TABLE IF NOT EXISTS notes (
        id INTEGER PRIMARY KEY,
        title TEXT NOT NULL,
        body TEXT NOT NULL DEFAULT '',
        created_at TEXT NOT NULL DEFAULT (datetime('now'))
    );",
];

fn migrate(conn: &mut Connection) -> Result<()> {
    conn.execute_batch(
        "CREATE TABLE IF NOT EXISTS schema_migrations (
            version INTEGER PRIMARY KEY,
            applied_at TEXT NOT NULL DEFAULT (datetime('now'))
        );",
    )?;

    let current: i64 = conn
        .query_row(
            "SELECT COALESCE(MAX(version), 0) FROM schema_migrations",
            [],
            |r| r.get(0),
        )?;

    // 예시: 버전 1 = notes 테이블
    if current < 1 {
        let tx = conn.transaction()?;
        tx.execute_batch(
            "CREATE TABLE IF NOT EXISTS notes (
                id INTEGER PRIMARY KEY,
                title TEXT NOT NULL,
                body TEXT NOT NULL DEFAULT '',
                created_at TEXT NOT NULL DEFAULT (datetime('now'))
            );",
        )?;
        tx.execute(
            "INSERT INTO schema_migrations (version) VALUES (1)",
            [],
        )?;
        tx.commit()?;
    }

    let _ = MIGRATIONS; // 위는 최소 패턴 예시
    Ok(())
}
```

### CLI와의 차이

| CLI | 앱(rusqlite) |
|---|---|
| 사람이 `.read schema.sql` | 부팅 시 `migrate()` 자동 |
| 수동 백업 | `backup` feature 또는 파일 복사 |

프로덕션에서는 `refinery` / `rusqlite_migration` 같은 도구도 검토.

### 체크포인트

- [ ] `schema_migrations` + 트랜잭션으로 한 버전 적용

## 14. 배치 · 캐시된 Statement

### execute_batch

여러 문장을 한 문자열에:

```rust
conn.execute_batch(
    r#"
    CREATE TABLE IF NOT EXISTS t (id INTEGER PRIMARY KEY, v TEXT);
    CREATE INDEX IF NOT EXISTS idx_t_v ON t(v);
    "#,
)?;
```

파라미터 바인딩이 없는 DDL/시드에 적합.  
**사용자 값이 섞이면** 문장마다 `execute` + `params!`.

주의: `Connection::execute` / `prepare`는 **한 문장**을 전제로 한다.  
세미콜론으로 여러 문장을 한 문자열에 넣으면 `Multiple statements provided` 등으로 실패하거나,  
DDL+DML 조합에서 예상과 다른 에러가 날 수 있다 → `execute_batch` 또는 문장 분리.

### prepare_cached

같은 SQL을 반복할 때:

```rust
fn insert_many(conn: &Connection, names: &[&str]) -> Result<()> {
    for name in names {
        let mut stmt = conn.prepare_cached(
            "INSERT INTO person (name, age) VALUES (?1, ?2)",
        )?;
        stmt.execute(params![*name, 0])?;
    }
    Ok(())
}
```

내부 캐시에서 `Statement`를 재사용한다. 핫 루프에서 `prepare` 비용↓.

### 대량 INSERT — 트랜잭션이 핵심

CLI에서도 그렇듯, INSERT 수천 개를 오토커밋으로 치면 느리다.

```rust
fn bulk(conn: &mut Connection, names: &[&str]) -> Result<()> {
    let tx = conn.transaction()?;
    {
        let mut stmt = tx.prepare("INSERT INTO person (name, age) VALUES (?1, 0)")?;
        for name in names {
            stmt.execute(params![*name])?;
        }
    } // stmt 수명 종료 후
    tx.commit()
}
```

- [ ] 대량 INSERT를 트랜잭션으로 묶었을 때 속도 차이 체감

## 16. 실전 예제: 미니 노트 앱

한 파일에 가깝게 모은 완결 예제.

```rust
use rusqlite::{params, Connection, OptionalExtension, Result};

#[derive(Debug, Clone)]
struct Note {
    id: i64,
    title: String,
    body: String,
}

struct NoteRepo<'a> {
    conn: &'a Connection,
}

impl<'a> NoteRepo<'a> {
    fn init(conn: &Connection) -> Result<()> {
        conn.execute_batch(
            r#"
            PRAGMA foreign_keys = ON;
            CREATE TABLE IF NOT EXISTS notes (
                id INTEGER PRIMARY KEY,
                title TEXT NOT NULL,
                body TEXT NOT NULL DEFAULT ''
            );
            CREATE INDEX IF NOT EXISTS idx_notes_title ON notes(title);
            "#,
        )?;
        Ok(())
    }

    fn new(conn: &'a Connection) -> Self {
        Self { conn }
    }

    fn create(&self, title: &str, body: &str) -> Result<i64> {
        self.conn.execute(
            "INSERT INTO notes (title, body) VALUES (?1, ?2)",
            params![title, body],
        )?;
        Ok(self.conn.last_insert_rowid())
    }

    fn get(&self, id: i64) -> Result<Option<Note>> {
        self.conn
            .query_row(
                "SELECT id, title, body FROM notes WHERE id = ?1",
                params![id],
                |row| {
                    Ok(Note {
                        id: row.get(0)?,
                        title: row.get(1)?,
                        body: row.get(2)?,
                    })
                },
            )
            .optional()
    }

    fn list(&self) -> Result<Vec<Note>> {
        let mut stmt = self.conn.prepare(
            "SELECT id, title, body FROM notes ORDER BY id DESC",
        )?;
        let iter = stmt.query_map([], |row| {
            Ok(Note {
                id: row.get(0)?,
                title: row.get(1)?,
                body: row.get(2)?,
            })
        })?;
        let mut out = Vec::new();
        for n in iter {
            out.push(n?);
        }
        Ok(out)
    }

    fn update_body(&self, id: i64, body: &str) -> Result<bool> {
        let n = self.conn.execute(
            "UPDATE notes SET body = ?1 WHERE id = ?2",
            params![body, id],
        )?;
        Ok(n == 1)
    }

    fn delete(&self, id: i64) -> Result<bool> {
        let n = self
            .conn
            .execute("DELETE FROM notes WHERE id = ?1", params![id])?;
        Ok(n == 1)
    }

    /// 제목 변경 + 본문 변경을 한 트랜잭션으로 (원자성)
    fn rename_and_append(
        conn: &mut Connection,
        id: i64,
        new_title: &str,
        appendix: &str,
    ) -> Result<()> {
        let tx = conn.transaction()?;
        let n = tx.execute(
            "UPDATE notes SET title = ?1 WHERE id = ?2",
            params![new_title, id],
        )?;
        if n != 1 {
            // drop → rollback
            return Err(rusqlite::Error::QueryReturnedNoRows);
        }
        tx.execute(
            "UPDATE notes SET body = body || ?1 WHERE id = ?2",
            params![append, id],
        )?;
        tx.commit()
    }
}

fn main() -> Result<()> {
    let mut conn = Connection::open("notes.db")?;
    conn.busy_timeout(std::time::Duration::from_secs(3))?;
    conn.pragma_update(None, "journal_mode", "WAL")?;
    NoteRepo::init(&conn)?;

    let repo = NoteRepo::new(&conn);
    let id = repo.create("rust", "hello")?;
    println!("created={id}");
    println!("get={:?}", repo.get(id)?);
    repo.update_body(id, "hello rusqlite")?;
    NoteRepo::rename_and_append(&mut conn, id, "rusqlite", "!")?;

    let repo = NoteRepo::new(&conn);
    for n in repo.list()? {
        println!("{n:?}");
    }
    Ok(())
}
```

## 17. Axum과 붙이기

패턴 요약:

1. `Connection` 또는 풀을 `State`에 넣는다.
2. 핸들러는 async이므로 DB 작업은 `spawn_blocking` 또는 풀+blocking.
3. DTO는 Serde, DB 모델은 별도이거나 동일 구조.

```rust
// 스케치 — 의존성: axum, tokio, rusqlite, serde
use axum::{extract::State, Json, Router};
use rusqlite::Connection;
use serde::Serialize;
use std::sync::{Arc, Mutex};

#[derive(Clone)]
struct AppState {
    db: Arc<Mutex<Connection>>,
}

#[derive(Serialize)]
struct NoteDto {
    id: i64,
    title: String,
}

async fn list(State(state): State<AppState>) -> Result<Json<Vec<NoteDto>>, String> {
    let db = state.db.clone();
    let notes = tokio::task::spawn_blocking(move || {
        let conn = db.lock().map_err(|e| e.to_string())?;
        let mut stmt = conn
            .prepare("SELECT id, title FROM notes ORDER BY id")
            .map_err(|e| e.to_string())?;
        let rows = stmt
            .query_map([], |row| {
                Ok(NoteDto {
                    id: row.get(0)?,
                    title: row.get(1)?,
                })
            })
            .map_err(|e| e.to_string())?;
        let mut out = Vec::new();
        for r in rows {
            out.push(r.map_err(|e| e.to_string())?);
        }
        Ok::<_, String>(out)
    })
    .await
    .map_err(|e| e.to_string())??;

    Ok(Json(notes))
}
```

## 18. 자주 하는 실수 · 함정

1. **값에 `format!`** → SQL 인젝션·이스케이프 버그  
2. **`transaction` 후 `commit` 잊기** → 전부 rollback (버그처럼 보임)  
3. **`foreign_keys`를 환경마다 다르게 가정** → CLI OFF / bundled ON 혼동. **명시적으로 ON**  
4. **한 `Connection`을 여러 스레드에서 동시 사용** → 컴파일 불가(`!Sync`) 또는 Mutex 없이 공유 시도 → 위험  
5. **async 핸들러에서 동기 쿼리 직호출** → 런타임 지연  
6. **`query_row`로 “유일 행”을 가정** → 2행+여도 첫 행만 나옴. 유일은 `query_one`  
7. **`query_row`로 “있을 수도” 조회** → `optional()` 누락  
8. **대량 INSERT를 트랜잭션 없이** → 디스크 fsync로 극느림  
9. **Statement 수명 동안 같은 conn에 다른 작업** → 빌림 체커 이슈  
10. **타입 affinity 믿기** → CLI에선 보이는데 `get::<i64>` 실패 (TEXT `"30"` 등)  
11. **이름 파라미터 일부만 바인딩** → 이전 값/NULL 잔존  
12. **WAL 켠 뒤 백업을 파일 복사만** → `-wal`/`-shm` 고려 또는 `backup` API  
13. **`execute`로 결과 있는 SELECT/PRAGMA** → `Execute returned results` 에러 (빈 SELECT는 Ok(0)일 수 있어 더 헷갈림)  
14. **빈 `IN ()` 동적 SQL** → 문법 에러  
15. **메모리 DB에 WAL을 기대** → `:memory:`는 `journal_mode`가 `memory`로 남는 경우가 많음  
16. **이체 등에서 `changes` 미확인** → 잔액 부족인데 상대 계좌만 증가  
17. **sqlx와 커넥션 옵션을 섞어 생각** → 같은 파일이어도 풀/런타임 규칙 다름  
18. **`u64`를 feature 없이 `get`** → 컴파일 에러 (`fallible_uint`)

## 20. 부록: CLI ↔ Rust 치트시트

| 하고 싶은 일 | sqlite3 CLI | rusqlite |
|---|---|---|
| DB 열기 | `sqlite3 app.db` | `Connection::open("app.db")?` |
| 메모리 | `sqlite3 :memory:` | `Connection::open_in_memory()?` |
| 스키마 | `CREATE TABLE ...;` | `conn.execute(..., [])?` |
| 여러 DDL | `.read schema.sql` | `execute_batch` |
| Insert | `INSERT ... VALUES ('a', 1);` | `execute(..., params!["a", 1])?` |
| Select 여러 행 | `SELECT ...;` | `prepare` + `query_map` |
| Select 한 행(첫 행) | | `query_row` / `.optional()` |
| Select 정확히 1행 | | `query_one` |
| 변경 행 수 | `changes()` | `execute` → `usize` |
| 마지막 id | `last_insert_rowid()` | `last_insert_rowid()` |
| 트랜잭션 | `BEGIN;` … `COMMIT;` | `transaction()?` … `commit()?` |
| Rollback | `ROLLBACK;` | drop 또는 `rollback()?` |
| PRAGMA | `PRAGMA journal_mode=WAL;` | `pragma_update(None, "journal_mode", "WAL")?` |
| 대기 | | `busy_timeout(Duration)` (기본 ≈5s) |
| 종료 | `.quit` | `Connection` drop (파일 핸들 해제) |

## 21. 부록: 알아두면 좋은 API

### `exists`

행이 있는지만 볼 때:

```rust
let mut stmt = conn.prepare("SELECT 1 FROM person WHERE id = ?1")?;
let ok = stmt.exists(params![id])?;
```

### `RETURNING` (SQLite 3.35+)

```rust
let id: i64 = conn.query_row(
    "INSERT INTO notes (title, body) VALUES (?1, ?2) RETURNING id",
    params!["t", "b"],
    |row| row.get(0),
)?;
```

bundled SQLite가 충분히 최신이면 사용 가능 (`rusqlite::version()`으로 확인).

### 중단 (`interrupt`)

긴 쿼리를 다른 스레드에서 끊을 때:

```rust
let handle = conn.get_interrupt_handle();
// 다른 스레드에서:
handle.interrupt();
```

### `Batch`

문자열에 여러 SQL이 있을 때 문장 단위로 순회 (`execute_batch` 대안).

### feature 모듈 (필요할 때)

| feature / 모듈 | 용도 |
|---|---|
| `backup` | 온라인 백업 |
| `blob` | 증분 BLOB I/O |
| `functions` | SQL 함수 등록 |
| `hooks` | commit/update 훅 |
| `trace` | 프로파일·로그 |
| `vtab` | virtual table |
